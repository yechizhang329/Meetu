## 1. 案例 1：排版小动物 Tiny Type

样本：Jonathan msg `a549f928` 附件的 "2000 块到底够不够" 账单图。这是公认的"我会发"的图。

### 5 个问题

| 问题 | 答 |
|---|---|
| 用户发它在表达什么 | "我月初想 2000 块够过一个月，月底发现一毛没剩，但我也搞笑地承认这件事" — 自嘲式生活账本 |
| 哪个元素让她敢发 | **没有产品 logo / 没有 banner / 没有"测试结果"标签** — 整张图像她自己手写的便签，不是某个 app 导出的 |
| 朋友怎么接话 | 最后一行 "结余 350？那我为啥一毛没剩🤡" 直接构造接话点；朋友可以回 "你那 200 社交是奶茶吧" / "话费 50 是 30 个 G？" |
| 视觉年轻在哪 | 手写字 + 横线笔记本纸 + 极小角色 + 单一 emoji 表情 — 不是设计稿，是"她随手写的一页" |
| 我们能借什么 / 不能借什么 | 借：**减法 + 手写主体 + 角色彩蛋 + 梗反转 + 极小品牌**；不借：横线纸具体样式（如果直接抄会变成模仿，要找我们自己的"纸感"） |

### 工程实现拆解

| 维度 | Tiny Type |
|---|---|
| 画布尺寸 | 移动竖屏长图（约 9:16 或更长）；单张 PNG |
| 字体 | **手写字体作为主字体（80-90% 通栏使用）**；衬线字（"Tiny Type" / "Date 2026/04/20"）作为顶部签名 |
| 文字层级 | 标题（手写大字）→ 正文条目（手写同字号）→ 装饰 emoji（🥹🤡）；**没有 4-5 级层级**，只有 2 级 |
| 品牌位 | "由排版小动物制作" 在最右下角，约 9-10px，灰度 mute；**几乎隐形** |
| 角色 | 右下角 ~10% 画面占比；端杯子的极简线描猫；**完成读完正文才会注意到，不抢戏** |
| DOM/CSS 推测 | 单一全屏容器，无嵌套卡片，无 box-shadow，无 border（仅整页轮廓）；横线纸用 `repeating-linear-gradient(transparent 0, transparent 47px, #E5DDC8 47px, #E5DDC8 48px)` 做底纹 |
| 导出 | 静态 PNG，疑似 Procreate / Notability / Goodnotes 手写后截图；非动态 H5 |
| 边界元素清单 | 顶部：`Tiny Type` + `Date` 仅 2 行装饰；底部：1 行 `由排版小动物制作` 极小品牌；中间：纯横线纸 + 手写文字 + 1 个角色彩蛋；**无 banner / 无标签条 / 无 friend-rate 框 / 无 watermark logo** |

### 减法机制

> "减法美学" = 当一个元素让用户怀疑"这是 app 出的图吗"，就删掉。

Tiny Type 的设计里**唯一让人想起来"这是某个产品的产出"的就是右下角 9px 的 "由排版小动物制作"**。其他所有视觉信号都指向"这是用户自己写的便签"。

## 2. 案例 2：网易云音乐 / Spotify 年度分享卡

样本：网易云每年的"年度听歌报告"分享卡 + Spotify Wrapped。这两个是国内外公认"用户主动分享"的工具图。

### 5 个问题

| 问题 | 答 |
|---|---|
| 用户发它在表达什么 | "我今年听了 X 首歌 / 这首是我的年度循环" — 用音乐口味替自己说话，不直接说"我是谁" |
| 哪个元素让她敢发 | 个人化数据（你的听歌时长 / 你最爱的歌手）— 这是**你的**图，不是网易云的图 |
| 朋友怎么接话 | "你居然听了 200 小时！" / "这歌好评" / "原来你最爱的是 XX" — 数据是接话点 |
| 视觉年轻在哪 | 大色块 + 大字 + 强对比配色（年度色随年变换：2018 黄、2022 紫、2024 蓝绿）；**故意不"克制"** |
| 我们能借什么 / 不能借什么 | 借：**个人化数据是核心 + 大色块强对比 + 年度色策略 + 长图竖向滚动**；不借：网易云的品牌强存在感（顶部"网易云音乐 2024"是大字，我们不能学这个） |

### 工程实现拆解

| 维度 | 网易云分享卡 |
|---|---|
| 画布尺寸 | **9:16 长图，1080×1920**；用户截图整张发朋友圈 |
| 字体 | 主字体定制 sans-serif 黑体；强对比字号（巨标题 60-80px / 正文 24-32px） |
| 文字层级 | 4-5 级：年度大字 → 数据数字 → 描述文字 → 引文 → 小注解；**层级感强是因为有数据当锚点** |
| 品牌位 | 顶部 + 底部都有 logo + 文字；网易云**故意不隐藏品牌**因为用户在炫耀 "我用网易云听歌" 的身份 |
| 角色 | 无角色（数据是主体）；**这是网易云不像"角色 IP 产品"的地方** |
| DOM/CSS | H5 多屏（用户滑动）；用 CSS animation 做页面切换 + 数据 reveal；最后一屏点击保存全图 → 用 `html2canvas` 或 server-side puppeteer 渲染为 PNG |
| 导出 | 9:16 PNG 或多张 1080×1920 拼合长图 |
| 关键技法 | "数据驱动的可分享性" — 没有数据，再好的 UI 也分享不出去 |

### 与 Tiny Type 的差异（重要）

网易云分享卡 **品牌存在感很强**（顶部大 logo 不隐藏），但用户依然愿意发。原因：

> **品牌强 ≠ 产品边界感强。** 用户发网易云是因为"我用网易云"是 identity 的一部分（音乐品味是身份）。

我们 Meetu 心情值班室不在这个 identity 维度。所以**我们不能学网易云的品牌强存在感** — 我们要学 Tiny Type 的**品牌隐形**。

## 3. 案例 3：小红书状态截图（用户自创）

样本：XHS "今天不想营业" / "人已下线" / "本人请假" 系列状态卡。这类不是某个 app 的导出图，是用户自己用 Notability / 备忘录 / Pic Collage 拼出来的状态图。

### 5 个问题

| 问题 | 答 |
|---|---|
| 用户发它在表达什么 | "我今天的状态" — 不是结果，是当下情绪 |
| 哪个元素让她敢发 | **图本身就是她做的**（用备忘录截屏 / 微信表情包二创 / 拍照加字）— 没有任何产品边界，因为根本不是产品做的 |
| 朋友怎么接话 | 用她常用的角色 / 表情包 / 句式接话 — "懂！" / "这不就是你？" / "+1" |
| 视觉年轻在哪 | 不对称、有"随手感"、半张脸或角色挡到字、边角溢出；**故意不"完美居中"** |
| 我们能借什么 / 不能借什么 | 借：**不对称 / 随手感 / 角色挡字 / 边角溢出 / 单色块占满**；不借：完全无产品（我们仍然是产品，要找平衡） |

### 工程实现拆解

| 维度 | XHS 状态截图 |
|---|---|
| 画布尺寸 | 多种：1:1（手机相册截屏 / 朋友圈方图）/ 4:5（XHS 主格式）/ 9:16（朋友圈滑屏） |
| 字体 | 用户用什么就什么 — iOS 备忘录默认字体 / 字魂手写体 / Pic Collage 装饰字；**不存在"统一字体"** |
| 品牌位 | **零品牌**。因为不是产品出的图 |
| 角色 | 当用户用角色（Loopy / Capoo / Chiikawa）时，角色占 30-60% 不等；用户**复用既有 IP**，不创造新角色 |
| DOM/CSS | 不存在 — 这些图是用户在 iPhone 备忘录 / Notability / Pic Collage 里手做的 |
| 导出 | 截屏 |
| 关键技法 | "用户做的图天然没有产品边界感" — 我们如果要让产品出的图看起来像用户做的，必须**用户级最简单工具能做的视觉**就够了 |

### 反推到我们

我们的 H5 输出要"看起来像用户在备忘录里写的图"，**不是"产品给用户的精心设计"**。这是 Tiny Type 已经走通的路。

## 4. 案例 4：Loopy / Chiikawa 表情包截图

样本：表情包用户截屏后发到朋友圈 / 微信群 / XHS 评论区。

### 5 个问题（参考来源：[梅花网 — 从loopy到chiikawa，什么样的IP容易出圈](https://www.meihua.info/article/5737447349797888)）

| 问题 | 答 |
|---|---|
| 用户发它在表达什么 | "我今天就是这只" — 把自己情绪映射到角色 |
| 哪个元素让她敢发 | 角色 ≠ 用户 ≠ 品牌 — 三者隔离让用户**安全表达**；用户不用直接说"我在崩溃"，角色替她说了 |
| 朋友怎么接话 | "笑死，你这只是 X 还是 Y？" / 互发同 IP 的不同表情接龙 |
| 视觉年轻在哪 | 简笔黑线 + 平涂 + 单色背景 / 透明背景 + 一个表情就是一个梗；**视觉极简** |
| 我们能借什么 / 不能借什么 | 借：**角色作为情绪代理人 + 透明 PNG 用户可以二次拼图 + 单一 IP 多变体多表情**；不借：直接复用 Loopy / Chiikawa 形象（IP 法律风险） |

### 工程实现拆解

| 维度 | IP 表情包 |
|---|---|
| 画布尺寸 | 微信表情包：240×240 png（动态 ≤ 1mb） |
| 字体 | 通常无字 / 用户后期加字 |
| 品牌位 | **零品牌**（在表情包面板里有作者名，但发出去后不显示） |
| 角色 | 100% 占比 — 角色就是图本身 |
| DOM/CSS | 不适用 — 表情包是 PNG/GIF/APNG |
| 导出 | 用户从微信表情包面板直接发，**不下载、不另存** |
| 关键技法 | "角色情绪 = 表情包关键帧" — 一个角色至少 8-16 个情绪变体让用户挑 |

### 反推到我们

如果心情值班室真要做"情绪代理人"，**4 个角色 × 16 个表情** 才是表达池的下限，不是 4 角色 × 1 个 master sheet。当前 v0.9 的 4 个 teststone PNG 是远远不够的。

## 5. 减法美学的工程清单（v0.9 → v1.0 应该删什么）

按"产品边界感 → 用户截屏感"重排：

| v0.9 现存元素 | 是否产品边界感 | 处理建议 |
|---|---|---|
| 顶部 6px 黄条 | ✅ 强 | 删 |
| "心情值班室 · MEETU" eyebrow | ✅ 强 | 删；改为底部右下角 9px 极小字 |
| 顶部 source-tag（"替你顶一会儿"等） | ⚠️ 中 | 删；信息可以转到底部 / 不显示 |
| 卡片 `.candidate-card` border + 圆角 | ✅ 强 | 删 border + 圆角，改为纸面横线分隔 |
| `.option-card` border + 圆角 | ✅ 强 | 删 border；改为手写勾选感（用户感像在备忘录里点） |
| `.share-friend-slot` border + 描边 | ✅ 强 | 删 border + bg；改为 absolute 文字层"今日值班评价：____" 一笔横线 |
| 底部 "MEETU · 心情值班室" watermark | ✅ 强 | 缩小到 9-10px，最右下角 |
| `.btn-primary` 黑实心圆角 12px | ⚠️ 中 | 保留（CTA 必须可点击），但去除 box-shadow + 字重 600 → 500 |
| `result-eyebrow` "今天替你值班" 大写英文式字距 | ✅ 强（SaaS 感） | 删；改为手写一句"今天它替你说" |
| `--font-handwrite "仅小注解"` 限制 | ⚠️ 关键 | **反过来**：手写字体作为主字体（标题 + 正文），PingFang 仅作为底部签名 |
| 角色立绘居中 40% | ⚠️ 中 | 改为右下角 10-15% 彩蛋；金句是主体 |
| 角色 emotionTag 标签 "焦虑/拖延/DDL" | ✅ 强（被分类感） | 删；不显示为标签 |
| 候选卡 `.role-name` 复述 | ✅ 中（信息冗余）| 删（Phoebe2 D3 同） |

**结论**：v1.0 工程改动不是 50 个 token 微调，而是**删掉 v0.9 的 70% UI chrome**，把字体 + 角色 + 内容三件事重新分配权重。

## 6. 工程师产品判断 review checklist（个人后续使用）

下次拿到 spec 时，先答这 5 题再写代码：

1. **用户日常已经在发的图里，最像我们要做的是哪一张？**（不能答"没有"——一定要找出来）
2. **那张图有几个元素？我们的 spec 有几个元素？多出来的元素是必要的吗？**
3. **如果我把品牌 logo / banner / 边框 / 标签全部删掉，spec 还成立吗？**（如果不成立，spec 错了；如果成立，那这些就是装饰，不是必需）
4. **我自己（作为这个产品的工程师）会把这张图截屏发朋友圈吗？**
5. **如果朋友看到这张图，第一反应是"这是某个 app 的截图"还是"这是 X 自己写的/做的"？**

这 5 题任何一题答案不对，要么 raise spec 问题，要么不写代码。

## 7. 给 Fiona 的工程视角输入（不形成产品方案）

按 Fiona 边界，我不形成产品方案。但工程视角对新 PRD 有 5 个**可行性参考点**：

1. **如果新 PRD 走 Tiny Type 风格**：工程量是当前 v0.9 的 30%（减法），不是 v0.9 的 130%（加法）。撤掉 70% UI chrome，主投资在手写字体加载 + 极简横线纸 background + 单 PNG 角色彩蛋。
2. **如果新 PRD 走"角色情绪代理人"路线**：4 角色每个至少 8-16 个表情变体是底线，不是 4×1 master sheet。这是表情包级表达池的工程量级，需要预算 32-64 张角色 PNG。
3. **如果新 PRD 走"用户做的图"风格**：放弃精心设计，工程上反而更简单（对齐随意 / 字体不统一 / 没有 design system）。但 PM 要接受"美感不可控"的代价。
4. **html2canvas 已通**：4:5 1080×1350 严格落地无问题。9:16 长图（网易云式）和 1:1（朋友圈方图）也都能实现，只需新画布参数。
5. **手写字体在 H5 加载**：体积约 5-15 MB（中文字库大），需要 woff2 + subset（只载入需要的字）；如果走"用户做的图"风格可以接受 Web 字体加载延迟（毕竟用户做的图也不会瞬间显示完美）。
