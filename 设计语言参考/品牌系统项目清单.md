# 觅遇社品牌系统项目清单

## 一、项目目标

建立一套可长期复用的觅遇社品牌系统，确保后续所有品牌资产、页面设计、运营物料和小程序视觉都基于统一标准产出，并保持品牌形象稳定、一致、可扩展。

当前已确认的正式命名：

- 中文名：觅遇社
- 英文名：Meetu

---

## 二、核心项目清单

### 1. 品牌基础资产统一

目标：把当前分散、存在 AI 差异的第一代品牌资产整理为正式主版本。

包括：

- 品牌 Logo 主版本统一
- 品牌 Icon / App Icon 主版本统一
- Mascot 主版本统一
- 拼图 motif、基础图形语言统一
- 现有历史资产中的旧名称 `觅途` 全部标记为历史版本

交付物建议：

- Logo master
- App icon master
- Mascot master
- 基础图形元素包

### 2. 品牌设计规范建立

目标：建立一套后续所有新增视觉资产都必须遵守的设计标准。

包括：

- 品牌主色、辅助色、状态色规范
- 字体、字号、字重、行高、字距规范
- 圆角、描边、阴影、边框、渐变规范
- 插画风格、图标风格、组件风格规范
- 图片边框、卡片、标题条、标签等基础样式规则

交付物建议：

- Brand style guide
- Color token / typography token / radius token
- 图标与插画风格说明

### 3. 品牌语言与术语标准

目标：让品牌“说话的方式”和“被称呼的方式”保持一致。

包括：

- 品牌名称统一：觅遇社 / Meetu
- 术语表统一：主理人、诚意金、搭子等核心词汇
- Mascot 命名统一
- 不同场景的文案语气规范
- 禁用词 / 敏感词 / 不建议使用表达

交付物建议：

- Brand voice & tone guide
- 品牌术语表
- 命名与禁用词清单

### 4. Mascot 设计优化与变体系统

目标：把 mascot 从“单张素材”升级为“系统化角色资产”。

包括：

- Mascot 造型统一与优化
- 表情、动作、姿态变体设计
- 系统提示场景变体
- 聊天表情包 / sticker 体系
- 在小程序、H5、Banner、海报中的应用规则

交付物建议：

- Mascot 基础设定图
- 表情与动作变体包
- System notice mascot pack
- Chat sticker pack

### 5. 品牌视觉应用优化

目标：把品牌系统真正落到对外和对内的主要触点。

包括：

- 品牌 Logo 与品牌海报
- 小红书图片与 Banner 设计
- H5 页面与子页模板
- 小程序 Icon、配色、封面图、宣传物料
- 运营活动页、专题页、招募页等

交付物建议：

- Banner / poster / XHS 模板库
- H5 / 子页视觉模板库
- 小程序宣传位模板

### 6. 小程序元素系统标准化

目标：让小程序内所有视觉元素都有统一母版，避免“每次单独生成”。

包括：

- 小程序 icon 系统
- Bubble / 对话框系统
- System notice / 状态提示系统
- 图片边框 / 卡片框架 / 信息容器样式
- 标签、徽章、按钮、状态条等组件元素

交付物建议：

- Mini-program UI element library
- 状态页与提示页模板
- 图标集与卡片组件集

### 7. 子页 / H5 模板体系标准

目标：让复杂信息展示页形成可复制的模板家族，而不是每次重做。

包括：

- 招募动员型模板
- 平台介绍型模板
- 流程说明型模板
- 活动专题型模板
- CMS inline HTML 版本与标准网页版本的双轨规范

交付物建议：

- 模板家族说明文档
- 网页版模板库
- CMS inline HTML 模板库

### 8. 品牌资产治理与版本管理

目标：保证后续新增资产不会再次失控。

包括：

- 文件夹结构规范
- 资产命名规范
- master asset / export asset 区分规则
- 版本替换与归档机制
- 新资产评审与入库流程
- 谁负责审批、谁负责维护的责任边界

交付物建议：

- Asset governance guide
- 命名规则与目录规范
- 资产审核流程

## 三、建议补充的内容

目前最需要明确补充的部分有：

### A. 品牌语言规范

如果只有视觉规范，没有语言规范，后续 Banner、H5、系统提示、运营文案仍然会失去一致性。

### B. 子页模板体系标准

子页 / H5 已经成为重要的信息承载方式，必须正式纳入品牌系统，而不是继续当临时页面处理。

### C. 资产治理机制

这是保证长期一致性的关键。没有治理机制，前面做出的标准会随着新资产继续漂移。

### D. 输出规格标准

建议后续补充一套明确规格：

- 哪些资产需要 SVG
- 哪些需要 PNG / WebP
- H5 截图尺寸
- Banner 比例
- 小红书封面比例
- 小程序素材导出尺寸

### E. 参考对象与适用场景说明

每个模板或视觉家族，建议都明确：

- 面向谁
- 解决什么场景
- 参考什么对标对象
- 核心气质是什么

---

## 四、建议的执行顺序

### 第一阶段：定基础

1. 确认正式命名与术语
2. 确定 Logo / Icon / Mascot 主版本
3. 确定配色、字体、图形基础语言

### 第二阶段：定系统

4. 完成品牌设计规范
5. 完成 mascot 变体系统
6. 完成小程序元素系统

### 第三阶段：定应用

7. 重做关键应用物料模板
8. 完成 Banner / XHS / H5 / CMS 页面模板家族

### 第四阶段：定治理

9. 建立文件、命名、版本和审核机制
10. 把后续新增资产纳入统一流程

---

## 五、结论

如果以上 8 个项目都做完，觅遇社得到的将不只是“一批设计素材”，而是一套真正可持续运转的品牌系统。

现阶段最关键的补充项有 3 个：

- 品牌语言规范
- 子页 / H5 模板体系标准
- 品牌资产治理与版本管理机制
