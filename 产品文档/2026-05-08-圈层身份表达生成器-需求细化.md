# 圈层身份表达生成器：需求细化

日期：2026-05-08  
负责人：Fiona  
状态：需求细化 v1  
背景：在 full-scale 大学生生活方式研究后，Jonathan 指出“低压小局/搭子接龙”链路太长，不像排版小动物这种用户内源需求。PM 将方向修正为“圈层身份表达生成器”。

---

## 0. 一句话定义

> 帮用户把“我是什么人、我想被怎样的人看见、我有哪些边界”生成一张不尴尬、可发布、可被同类接话的身份表达图和配套文案。

它不是交友平台，不是搭子匹配，也不是单纯图片生成器。

它是一个 **低压自我表达工具**。

---

## 1. 真实需求是什么

### 1.1 用户原本就在做什么

用户已经在小红书/朋友圈/群聊里做这些事：

- 发精神状态图：用梗图替自己说话；
- 发朋友圈文案：把普通生活包装得更像“我”；
- 发自介/扩列/搭子信息：让同类知道我是谁；
- 发测试结果卡：让朋友认领/吐槽自己；
- 发校园墙/投稿截图：用半匿名外壳表达需求；
- 在评论区说 `求模板 / 求教程 / 同款 / 怎么做 / dd / 蹲 / 私`。

这些行为背后不是“我要一个卡片”，而是：

> 我想表达自己，但我不想表达得尴尬。  
> 我想被同类看见，但我不想显得太主动。  
> 我想让别人知道我的边界，但我不想像在发招聘。  
> 我想找人，但最好先用一个轻松的东西试探。

### 1.2 根本痛点

用户有自我表达/寻找同类的需求，但现有表达方式很容易踩三个坑：

1. **太正式**：像简历、交友启事、征友广告；
2. **太暴露**：学校、性别、照片、社交需求写太满，不安全；
3. **太无效**：发一句“有没有人一起”没人接，发多了又尴尬。

所以产品要解决的不是“帮他匹配人”，而是：

> 让用户能用一种安全、轻松、有梗、不像广告的方式，把自己和需求表达出来。

---

## 2. 为什么这个方向比“低压小局”更短链路

| 维度 | 低压小局/搭子接龙 | 圈层身份表达生成器 |
|---|---|---|
| 用户动作 | 回复 → 填表 → 等组织 → 到场 | 输入 → 生成 → 保存/发布 |
| 价值闭环 | 必须有人响应/运营组织 | 用户生成后立刻有价值 |
| 运营依赖 | 高 | 低 |
| 流失点 | 多 | 少 |
| 是否内源 | 中，依赖召集 | 高，用户本来就在表达 |
| 是否可传播 | 依赖成局结果 | 生成物天然可传播 |
| 是否沉淀数据 | 可沉淀小局需求 | 可沉淀身份/圈层/边界/场景 |

这就是它更像“排版小动物”的原因：

- 用户已经想表达自己；
- 产品只是把表达包装成更好发的形式；
- 不需要等待别人参与，第一层价值已经成立。

## 3. 目标用户

### P0 目标用户

优先做这 4 类：

1. **想找同类但怕尴尬的人**
   - 想找游戏搭子、拍照搭子、自习搭子、citywalk搭子；
   - 不想直接说“来个人陪我”。

2. **圈层身份明确但表达成本高的人**
   - Kpop、二次元、乙游、livehouse、桌游、运动、摄影；
   - 想被同类识别，但不想把主页写成信息表。

3. **i人/慢热/边界感强的人**
   - 不是不想认识人，是不想高压社交；
   - 希望先说明“我可以少说话/不尬聊/不消失”。

4. **愿意发梗图/测试结果/朋友圈文案的人**
   - 已经习惯用图表达自我；
   - 愿意保存、截图、发群里。

### P0 不优先

- 强恋爱目的用户；
- 纯职业成长/简历模板用户；
- 匿名吐槽用户；
- 强交易/兼职用户；
- 需要平台担保和安全审查的线下约见用户。

## 4. 用户使用场景

### 场景 A：发小红书主页置顶

用户想让新来的人一眼知道自己是什么人。

输出：

- 一张“我的圈层身份图”；
- 一段小红书正文；
- 一条评论区接话模板。

例子：

```text
标题：我的主页先放个说明书
正文：慢热，不尬聊，游戏可组，分享欲看电量。
评论回复：同款品种可以自己报到。
```

### 场景 B：发群聊试探同类

用户想在群里找同类，但不想直接问。

输出：

- 一张低压需求卡；
- 一句群聊发法。

例子：

```text
图上写：
今日需求：找一个能安静自习的人
边界：不用聊天 / 不互相监督 / 能坐住就行

群里发：
我把话放这了，有同类自己出现。
```

### 场景 C：发朋友圈/QQ空间表达状态

用户不一定要找人，只是表达“这是我”。

输出：

- 精神状态图；
- 朋友圈配文。

例子：

```text
图上写：
当前状态：想出门，但不想组织。
社交电量：32%。
适合被一个不吵的人捡走。
```

### 场景 D：参加 Meetu 活动前破冰

用户参加小局前生成一张“低压入场卡”。

输出：

- 我能聊什么；
- 我不想聊什么；
- 我今天社交电量；
- 我的边界。

它可以降低线下第一次见面的尴尬，但这属于 P1 承接，不是 P0 入口。

## 5. 产品形态

### P0：单页 H5 工具

不登录、不注册、不匹配。

流程：

1. 选择当前目的；
2. 选择圈层/兴趣；
3. 选择边界；
4. 选择语气；
5. 生成图片 + 文案；
6. 保存/复制。

### 输入字段

控制在 6 个以内：

1. **我现在想要什么**
   - 找同类
   - 找搭子
   - 表达状态
   - 发朋友圈
   - 参加活动前破冰

2. **我的圈层/兴趣**
   - 游戏 / Kpop / 二次元 / livehouse / 运动 / citywalk / 自习 / 摄影 / 桌游 / 其他

3. **我的社交边界**
   - 慢热
   - 不尬聊
   - 可以少说话
   - 不想太晚
   - 女生优先
   - 不消失
   - AA
   - 不拍脸

4. **我想被谁看到**
   - 同校
   - 同城
   - 同兴趣
   - 同状态
   - 熟人也行
   - 只给朋友看

5. **表达语气**
   - 正常
   - 抽象
   - 嘴硬
   - 大字报
   - 朋友圈
   - 群聊

6. **可选信息**
   - 学校/城市（可不填）
   - 昵称（可不填）

### 输出内容

每次生成 3 件套：

1. **图片卡**：用于保存/发图；
2. **发布文案**：用于小红书/朋友圈；
3. **群聊发法**：用于微信群/小红书群。

## 6. 输出示例

### 示例 1：找自习搭子但不想说话

用户选择：

- 目的：找搭子
- 圈层：自习
- 边界：不尬聊 / 可以少说话 / 不互相监督
- 语气：嘴硬

生成图：

需要一个能一起坐着的人。

要求：
不尬聊
不互相卷

```text
不是找搭子。

```

```text
有同类自己出来。
不聊天也行。
```

## 7. 为什么它有 Meetu 价值

它不是单纯做图，因为它能沉淀 4 类关键数据：

1. **圈层数据**：用户属于什么兴趣/生活方式；
2. **场景数据**：用户想找自习、游戏、拍照、运动、citywalk 还是安静陪伴；
3. **边界数据**：用户对安全、社交压力、时间、预算的偏好；
4. **表达数据**：什么语气/视觉更愿意被保存和发布。

这些数据比“注册了一个账号”更接近 Meetu 后续产品：

- 哪些圈层值得组织活动；
- 哪些边界必须在产品里前置；
- 哪些视觉语言能打穿小红书；
- 哪些场景能形成真实连接。

所以 P0 是表达工具，P1 才可能是连接服务。

## 8. 和商业化的关系

短期不要直接收费。

商业化路径应该是后置的：

1. **流量入口**：用户生成内容带来传播；
2. **需求沉淀**：高频场景出现后，Meetu 可以组织真实活动；
3. **本地商家/场景合作**：运动馆、桌游店、咖啡店、展览、livehouse；
4. **主理人工具**：学生主理人生成活动身份卡/招募卡；
5. **高级模板/视觉风格**：未来可做轻付费，但不是 P0。

商业价值不是卖卡片，而是：

> 用低成本表达工具捕捉真实圈层需求，再把高频需求转化为活动、社群和交易闭环。

## 9. MVP 验证方案

### 9.1 7 天验证

做一个极简 H5，不接复杂 AI，先用模板组合。

投放路径：

- 小红书笔记：展示 3-5 张生成样例；
- 小红书群：发“低压身份卡生成器”样例；
- 朋友圈/微信群：邀请内部学生试用；
- 公众号/社交动物测试结果页：轻入口。

### 9.2 验证指标

| 指标 | 及格线 | 说明 |
|---|---:|---|
| 进入 H5 后完成生成率 | ≥60% | 输入链路是否够短 |
| 保存图片率 | ≥40% | 输出是否有用 |
| 复制文案率 | ≥25% | 文案是否可直接用 |
| 用户愿意发出去自报 | ≥20% | 是否突破尴尬阈值 |
| 评论/私信问“在哪做” | 出现即可 | 是否有传播外溢 |
| 生成内容含明确圈层/场景 | ≥50% | 是否能沉淀有价值数据 |
| 负反馈“像广告/尴尬” | <10% | 是否踩中表达风险 |

### 9.3 如果失败，说明什么

- 保存率低：输出不好看/不好用；
- 完成率低：输入太复杂；
- 发出意愿低：表达太尴尬；
- 全是搞笑状态，无圈层/场景：只能做流量工具，不能做产品入口；
- 负反馈高：像交友广告或泄露隐私。

## 10. P0 PRD 边界

### 必做

- 10-15 个高质量模板；
- 4 种语气：正常 / 抽象 / 嘴硬 / 低压；
- 6 个以内输入项；
- 图片保存；
- 文案复制；
- 简单数据记录：圈层、场景、边界、语气、保存/复制。

### 不做

- 登录；
- 匹配；
- 公开展示用户；
- 评论区；
- 私信；
- 地图；
- 付费；
- 自动拉群。

### 需要谨慎

- 学校/城市字段必须可选；
- 不要求上传真人照片；
- 不收手机号；
- 不承诺“找到人”；
- 不把输出写成“求偶/征友/招聘”。

## 11. 推荐下一步

我建议下一步不是直接开发，而是先做 2 个并行小任务：

### Task A：PRD 草案

把这个方向细化成可开发的 H5 PRD：

- 用户流程；
- 输入字段；
- 模板结构；
- 输出类型；
- 埋点；
- 风险边界。

### Task B：样例包

先做 12 张生成样例，不一定开发：

- 3 张找同类；
- 3 张找搭子；
- 3 张表达状态；
- 3 张活动破冰。

让 Jonathan/DavidC 先看：

- 会不会像广告；
- 有没有人味；
- 用户愿不愿意发；
- 是否真的比自己写更好。

如果样例都不想发，就不要开发。  
如果样例有明显分享欲，再进入 H5。
