# 圈层身份表达生成器 PRD v0.2（MVP 收缩版）

**日期**：2026-05-08  
**负责人**：Fiona  
**版本定位**：在 v0.1 深度研究基础上，按 DavidC 关于 friction / output quality / 技术 MVP 的挑战重新收敛。  
**当前结论**：P0 不做“真正 AI 生成器”，而做一个 **静态规则模板 H5**，验证用户是否愿意用低压表达卡表达自己并发出去。

---

## 0. 一句话定义

内部定义：

> 一个低压表达卡 H5：用户通过 3 个轻选择 + 可跳过加料项，生成 3 张可保存、可复制、可发出去的身份表达卡。

用户感知：

> 给自己做一张不尴尬的说明书。

它不是：

- 交友 App；
- AI 图片生成器；
- 自介卡编辑器；
- 匹配/群聊/发布平台；
- 又一个人格测试。

它是：

> Meetu 的前置表达层：帮用户把“我是什么状态、我想怎么被看见、我有哪些边界”转译成一张好发的图。

## 2. Target Audience

核心用户：

> 有社交表达需求，但不想用高压、直白、像广告的方式表达自己的大学生。

### 2.1 他们的特点

- 想被看见，但怕显得太想被看见；
- 想找同类，但不想主动喊人；
- 有边界，但不想把边界写得像规章制度；
- 喜欢梗图、测试结果、截图、评论区互动；
- 对“广告感 / 营销感 / 低质扩列感”非常敏感；
- 更愿意借第三方外壳表达自己，而不是直接自我介绍。

### 2.2 P0 最优先服务的人

不是所有大学生，而是：

1. **慢热但有连接欲的人**
   - 需要表达缓冲层；
   - 不想直接说“我想认识人”。

2. **习惯发梗图/测试结果/朋友圈文案的人**
   - 已经有“借内容表达自己”的行为习惯；
   - 更容易验证保存/分享。

3. **有具体场景但表达不自然的人**
   - 想找自习搭子、拍照同类、活动破冰、群聊说明；
   - 但不知道怎么说才不像广告/征友。

## 3. 核心问题定义

### 3.1 痛点不是“不会自我介绍”

真正痛点是：

> 自我介绍太像自我介绍。

直白写：

```text
我是谁 / 我喜欢什么 / 我想找什么人 / 我有什么要求
```

容易变成：

- 像简历；
- 像求偶；
- 像招聘；
- 像在卖自己；
- 像很用力地想交朋友。

### 3.2 产品要解决的问题

产品要解决：

> 如何让用户在不显得用力、不像广告、不像低质扩列的情况下，把自己的状态、同类需求和边界表达出来。

### 3.3 关键心理机制

1. **第三方外壳**：不是我硬写，是卡片/说明牌/朋友锐评替我说；
2. **可否认性**：用户可以嘴硬“随便生成的”；
3. **同类识别**：别人能接“我也是”；
4. **边界软化**：把“不查户口”说成“熟了会自动开机”；
5. **朋友接话**：输出物必须能让朋友评论，而不是只能点赞。

---

## 4. 与“社交动物测试”的关系

### 4.1 相似点

社交动物测试和本产品同源于同一套机制：

- 第三方外壳；
- 可否认性；
- 标签化表达；
- 朋友认领；
- 截图传播。

社交动物测试验证的是：

> 用户愿不愿意借第三方标签表达自己。

### 4.2 核心区别

| 维度 | 社交动物测试 | 圈层身份表达生成器 MVP |
|---|---|---|
| 用户动作 | 做题，被系统判定 | 轻选择，主动生成 |
| 核心心理 | 看看我是哪类人 | 我想这样被别人看见 |
| 输出 | 动物结果 + 朋友锐评 | 表达卡 + 文案 + 边界句 |
| 使用场景 | 晒结果、发群聊 | 群聊、朋友圈、主页置顶、活动破冰 |
| 使用频率 | 偏一次性 | 可随场景复用 |
| 产品角色 | 传播实验 | 前置表达工具 |

一句话：

> 社交动物测试回答“我被看起来像什么”；圈层身份表达生成器回答“我想怎样被别人轻轻看见”。

## 5. P0 核心假设

### 5.1 主假设

用户愿意通过极少量轻输入，生成一张“不尴尬、能发出去、能被朋友接话”的表达卡。

### 5.2 要验证的 5 件事

1. 用户是否愿意完成 3 个轻选择；
2. 用户是否觉得生成结果“像我”；
3. 用户是否愿意保存/复制；
4. 用户是否愿意发到外部场景；
5. 朋友/同学是否会自然接话。

### 5.3 P0 不验证的事

P0 不验证：

- 用户是否愿意注册；
- 用户是否愿意匹配；
- 用户是否愿意加入公开社群；
- 用户是否愿意长期经营个人资料页；
- AI 生成能力是否足够强。

## 6. MVP 技术边界

### 6.1 P0 技术形态

P0 做成：

```text
静态 H5 + 规则映射 + 预设模板 + html2canvas 导出
```

不是实时 AI 生成。

### 6.2 P0 不做

- 不做账号系统；
- 不做登录；
- 不做手机号；
- 不做公开发布墙；
- 不做匹配/私信/群聊；
- 不做自由文本输入；
- 不做拖拽式图片编辑器；
- 不做实时 AI 图片生成；
- 不做实时大模型文案生成；
- 不做用户作品存储。

### 6.3 为什么不接 AI

P0 暂不接 AI，原因：

1. 生成不稳定，容易油腻/营销/错语气；
2. 延迟和失败率影响完成率；
3. 成本不可控；
4. 用户自由输入带来审核风险；
5. 会混淆验证目标：我们要验证需求，不是验证模型能力。

AI 放到 P1：当规则模板验证保存/分享行为成立后，再用 AI 提升个性化。

## 7. P0 用户链路 v0.2

### 7.1 链路总览

```text
入口页
  ↓
Step 1：选当前状态（必填）
  ↓
Step 2：选使用场景（必填）
  ↓
Step 3：选表达方向（必填）
  ↓
可选加料：兴趣/边界/语气（可跳过）
  ↓
生成 3 张候选卡
  ↓
结果页：保存 / 复制 / 换语气 / 再生成
```

### 7.2 设计原则

> P0 不是减少问题，而是减少用户做困难决定的次数。

因此：

- 必填问题少，但必须高信息密度；
- 可跳过项用于个性化；
- 结果页行为用于收集真实偏好；
- 不让用户从 0 写自己，而是先给一个可认领的结果。

## 8. 输入设计

### 8.1 Step 1：当前状态（必填）

问题文案：

```text
你现在比较像哪种？
```

选项：

| ID | 文案 | 作用 |
|---|---|---|
| `lowkey_connect` | 有点想认识人，但不想主动 | 找同类/低压连接基调 |
| `soft_post` | 想发点东西，但不想太明显 | 状态表达/朋友圈基调 |
| `want_company` | 想找人一起做点事，但怕尬 | 搭子/活动基调 |
| `set_boundary` | 想说明边界，但不想写得像规章制度 | 边界表达基调 |

### 8.2 Step 2：使用场景（必填）

问题文案：

```text
这张图准备放哪？
```

选项：

| ID | 文案 | 影响 |
|---|---|---|
| `xhs_moments` | 小红书 / 朋友圈 | 更像状态图，文字短，视觉更强 |
| `group_chat` | 群聊 | 更口语，接话点更明显 |
| `profile_pin` | 主页置顶 | 信息更清楚，边界更稳定 |
| `event_icebreak` | 活动前破冰 | 更轻松，降低初见尴尬 |

### 8.3 Step 3：表达方向（必填）

问题文案：

```text
更想让它替你说什么？
```

选项：

| ID | 文案 | 输出重点 |
|---|---|---|
| `who_i_am` | 我是什么样的人 | 身份/状态 |
| `find_my_kind` | 我想找什么同类 | 同类识别 |
| `my_boundaries` | 我有哪些相处边界 | 低压边界 |
| `current_state` | 我现在是什么精神状态 | 情绪/传播 |

## 9. 可选加料项

可选区文案：

```text
想更像你，可以再选几个词；不选也能生成。
```

### 9.1 兴趣 / 圈层 chip

最多选 2 个：

- 自习；
- 拍照；
- citywalk；
- 桌游；
- 游戏；
- Kpop；
- 二次元/乙游；
- livehouse；
- 运动；
- 咖啡/探店。

### 9.2 边界 chip

最多选 3 个：

- 不尬聊；
- 不查户口；
- 不催回复；
- 可少说话；
- 不拍脸；
- AA；
- 不熬夜；
- 可临时退出；
- 熟了会自动开机；
- 不压力。

### 9.3 语气 chip

最多选 1 个：

- 正常一点；
- 损一点；
- 嘴硬一点；
- 大字报一点；
- 像朋友帮我写的；
- 别太像广告。

## 10. 生成逻辑

### 10.1 Payload

```ts
type ExpressionPayload = {
  state: 'lowkey_connect' | 'soft_post' | 'want_company' | 'set_boundary';
  context: 'xhs_moments' | 'group_chat' | 'profile_pin' | 'event_icebreak';
  intent: 'who_i_am' | 'find_my_kind' | 'my_boundaries' | 'current_state';
  interests: string[];
  boundaries: string[];
  tone: 'normal' | 'roast' | 'stubborn' | 'poster' | 'friend' | 'no_ad';
};
```

### 10.2 规则映射

```text
state × context × intent → baseTemplate
baseTemplate + defaultBoundaries + toneVariant → cardCopy
interests / boundaries → 替换局部词句
```

### 10.3 候选生成

每次生成 3 张候选：

1. **稳妥版**：更像主页/朋友圈可发；
2. **朋友锐评版**：更适合群聊接话；
3. **大字报版**：更适合小红书/朋友圈首图。

候选不是 AI 随机，而是 3 个预设模板 variant。

## 11. 输出结构

每张表达卡包含：

| 模块 | 说明 |
|---|---|
| 主标题 | 7-12 字，第一眼能懂 |
| 身份/状态句 | 一句话说明“你现在是什么状态” |
| 使用说明 | 1-3 条边界或相处方式 |
| 朋友接话点 | 让别人能回“这不就是你/我也是” |
| 轻品牌 footer | Meetu，弱露出 |

### 11.1 示例输出

#### 示例 A：低压同类招领

```text
低压同类招领

需要一个能一起坐着的人。
可以少说话，不查户口。
熟了会自动开机。

朋友锐评：
你不是社恐，你只是反对上来就营业。
```

#### 示例 B：主页说明书

```text
本人使用说明

慢热。
但不是没兴趣。

请勿上来查户口。
请勿连续催回复。
熟了以后会自己冒出来。
```

#### 示例 C：群聊破冰

```text
今日状态：可被约，但需低压

适合：自习 / 咖啡 / 随便走走
不适合：临时大型局、上来就拍照、强行热场

如果你也这样，可以假装路过一下。
```

## 12. 视觉模板

P0 只做 4 套模板。

| 模板 | 用途 | 视觉机制 |
|---|---|---|
| 说明牌 | 主页置顶/身份说明 | 身份型 + 信任型 |
| 低压招领 | 找同类/找搭子 | 组织型 + 情绪型 |
| 朋友锐评 | 群聊传播 | 传播型 + 情绪型 |
| 大字报 | 小红书/朋友圈首图 | 传播型 |

视觉原则：

- 不要像商业海报；
- 不要大 logo；
- 不要二维码；
- 不要下载/加群/报名强 CTA；
- 文字必须缩略图可读；
- 结果图必须能单独发出去成立。

## 13. 页面结构

### 13.1 入口页

核心文案：

```text
给自己做一张不尴尬的说明书。

不用写简历。
不用装外向。
不用把边界说得像规章制度。

选几个词，生成一张能发出去的图。
```

CTA：

```text
开始生成
```

### 13.2 选择页

每页只做一个问题。

要求：

- 选项不超过 4 个；
- 文案像聊天，不像问卷；
- 可选加料区可跳过；
- 全流程 1 分钟内完成。

### 13.3 结果页

模块：

1. 3 张候选卡横向/纵向展示；
2. 当前选中卡大图预览；
3. 保存图片；
4. 复制文案；
5. 换个语气；
6. 再生成；
7. 可选：复制“发群聊版本”。

不放：

- 下载 App；
- 登录；
- 加群；
- 手机号；
- 强二维码；
- 公开发布。

### 14.3 生成函数

```ts
function generateExpressionCards(payload: ExpressionPayload): ExpressionCard[] {
  const base = selectBaseTemplate(payload.state, payload.context, payload.intent);
  return [
    buildCard(base, payload, 'safe'),
    buildCard(base, payload, 'friend_roast'),
    buildCard(base, payload, 'poster'),
  ];
}
```

### 14.4 不需要后端

P0 可完全前端完成。埋点如果没有现成服务，可以先用极简日志或暂不接，人工看保存/分享反馈。

## 16. 成功指标

### 16.1 MVP 及格线

| 指标 | 目标 |
|---|---:|
| 入口页 → 开始生成 | ≥70% |
| 3 个必填问题完成率 | ≥60% |
| 生成完成率 | ≥55% |
| 保存/复制率 | ≥25% |
| 换语气/再生成点击率 | ≥20% |
| 用户反馈“像我/能发/帮我也做一个” | 出现即可强信号 |

### 16.2 强信号

- 用户主动保存表达卡；
- 用户把图发给朋友/群聊；
- 朋友自然接话；
- 有人问“这个怎么生成”；
- 某个模板被多次复用；
- 用户愿意让我们“换一个更像我”的版本。

### 16.3 失败信号

- 用户说“像广告”；
- 用户说“像扩列卡/征友表”；
- 完成率低于 40%；
- 保存/复制率低于 15%；
- 用户只觉得好看但不知道拿去干嘛；
- 生成结果太泛，不像具体的人。

## 17. 风险与规避

| 风险 | 表现 | 规避 |
|---|---|---|
| 低质扩列感 | 像征友广告 | 不放年龄/身高/硬条件，不做资料表 |
| 营销感 | 像品牌海报 | 弱品牌、无二维码、无下载 CTA |
| 输出泛化 | 像通用文案 | 3 个高信息密度必填 + golden samples |
| 输入过重 | 像问卷 | 必填 3 题，chip 可跳过 |
| 技术过重 | 像 AI 平台 | 规则模板，不接 AI |
| 无使用场景 | 生成后不知道发哪 | 第二题明确使用场景 |
| 朋友无法接话 | 只能点赞 | 每张卡必须有朋友接话点 |

## 20. 当前结论

这个方向仍然值得探索，但 P0 必须收缩。

最终 P0 定义：

> 一个静态规则模板 H5，用 3 个高信息密度轻选择 + 可跳过加料项，生成 3 张低压表达卡，验证用户是否愿意保存、复制、发出去，并让朋友接话。

P0 不追求：

```text
智能生成 / 完整编辑 / 高自由度 / 平台化
```

P0 只追求：

```text
低输入 / 稳定输出 / 愿意保存 / 愿意发 / 朋友能接话
```

如果这个成立，再进入 P1；如果这个不成立，不应继续加重工程投入。
