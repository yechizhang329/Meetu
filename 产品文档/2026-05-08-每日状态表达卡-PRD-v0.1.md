# 每日状态表达卡 PRD v0.1

**日期**：2026-05-08  
**负责人**：Fiona  
**项目阶段**：概念收敛 / MVP 前定义  
**当前版本结论**：从“圈层身份表达”进一步下沉到更高频、更低门槛的 **每日状态表达**。P0 不做大 AI 生成器，而做一个可快速验证“保存、分享、二次生成、朋友接话”的 H5 状态卡生成器。

---

## 0. 一句话定义

内部定义：

> 一个低压自我表达工具：用户用 3 次轻选择，生成一张“今天的我”状态卡，发出去等朋友接话。

用户感知：

> 给今天这个死样子的我生成一张说明牌。

它不是：

- 交友 App；
- 头像生成器；
- AI 图片生成器；
- 正经心理测试；
- 日签/鸡汤/塔罗；
- 复杂自介卡编辑器。

它是：

> 一个“低压自我表达弹药库”：帮用户把当下状态、嘴硬情绪、社交能量和朋友锐评，转译成一张好发、好笑、容易被接话的图。

## 1. 背景：为什么不是继续做“身份卡”

### 1.1 Jonathan 的关键判断

Jonathan 提醒：排版小动物本质不是头像需求，也不是单纯卡片需求，而是：

> 一种分享欲，一种表达欲。

这意味着我们不应该只停在“帮用户生成一张身份说明书”。身份表达相对低频，用户并不是每天都需要重新定义“我是谁”。

更高频的内源动作是：

> 我今天有个状态，我想发出去，但不想自己写得很尴尬。

### 1.2 从“我是谁”转向“我今天是什么状态”

之前的圈层身份表达生成器回答：

> 我是谁？我属于哪类人？我想被怎样看见？

每日状态表达卡回答：

> 我今天是什么死样子？我现在想用什么外壳表达自己？

区别：

| 维度 | 圈层身份表达卡 | 每日状态表达卡 |
|---|---|---|
| 表达对象 | 长期身份 | 即时状态 |
| 使用频率 | 低-中频 | 高频，理论可日更 |
| 用户心理 | “我要介绍自己” | “我今天就这样” |
| 分享动力 | 让别人认识我 | 让朋友接话/吐槽我 |
| 输入要求 | 需要想清楚偏好/边界 | 只需点当前状态 |
| 产品风险 | 自介感、征友感、广告感 | 更像梗图/状态分享 |

结论：

> 如果目标是高频使用和依赖，状态表达比身份表达更适合做 P0。

## 2. 根本欲望拆解

### 2.1 我想被看见，但不想正经介绍自己

直接表达很容易尴尬：

```text
我是一个有点慢热但想认识朋友的人。
```

用户更愿意这样表达：

```text
今日本人状态：在线装死中。
我不是不回，我是在等一个更像人的我上线。
```

这句话说的是自己，但不是自我介绍。它有可否认性：

> 我只是发个梗，你别太当真。

### 2.2 我想表达状态，但不想组织语言

用户不是没有表达欲，而是存在几个 friction：

1. 不知道怎么写才不尴尬；
2. 写太认真会像朋友圈小作文；
3. 写太抽象别人看不懂；
4. 写太直接又像在求关注；
5. 发出去没人回会更尴尬。

工具价值：

> 把用户脑子里那点状态，翻译成一张能发出去的图。

### 2.3 我想发出去后有人回

表达不是终点，朋友接话才是奖励。

用户真正期待的是：

- “这不就是你？”
- “给我也整一个。”
- “你今天确实这样。”
- “我也是这个状态。”
- “发我链接。”

产品要生成的不是“图片”，而是一个可被社交回应的对象。

### 2.4 我想借一个外壳替我说话

第三方外壳降低心理风险：

- 动物；
- 星座；
- MBTI；
- SBTI；
- 今日状态；
- 系统公告；
- 朋友锐评；
- 说明牌；
- 便签；
- 表情包。

本质：

> 我借一个玩意儿说我自己。

## 3. 产品定位

### 3.1 产品名称候选

偏用户语言：

- `今天我是啥`
- `今日状态牌`
- `今天的我已生成`
- `今日本人说明书`
- `今日精神状态生成器`

偏内部代号：

- `Daily State Card`
- `低压表达弹药库`
- `状态梗图生成器`

### 3.2 推荐定位

对外短句：

> 3 秒生成一张今天的你。

更有梗版本：

> 今天这个状态，别自己写了。

内部定位：

> Meetu 的高频表达入口：通过状态卡，把用户日常情绪、社交能量和朋友锐评包装成可分享、可接话、可二次生成的社交内容。

### 3.3 与 Meetu 的关系

它不是 Meetu 主社交闭环本身，而是 Meetu 的前置触点：

1. 用户先因为状态卡使用；
2. 状态卡产生分享和朋友接话；
3. 用户形成“Meetu 懂我的表达”的认知；
4. 后续再承接低压小局、搭子、活动、社群。

也就是说：

> 状态卡负责高频触达和表达习惯，小局/搭子负责线下或真实连接。

## 4. Target Audience

核心用户：

> 有表达欲，但不想用高压、直白、像广告的方式表达自己的大学生。

### 4.1 一级核心用户：表达型但怕尴尬的人

特征：

- 经常发梗图、测试结果、截图、朋友圈文案；
- 有自嘲能力；
- 喜欢“我不承认但有点像”；
- 想被朋友评价，但不想主动求评价；
- 对广告感、鸡汤感、AI 味非常敏感。

使用动机：

> 我想发点东西，但我不想显得我很想发。

### 4.2 二级用户：群聊/宿舍社交中的接话者

他们未必主动生成，但会看到朋友发的卡并参与互动：

- “这不就是你？”
- “给我也测一个。”
- “这个模板发我。”
- “我今天也是这状态。”

这些人是传播链路里的二跳用户。

### 4.3 三级用户：运营/活动场景用户

状态卡可被嵌入：

- 活动前破冰；
- 群聊活跃；
- 宿舍/社团互动；
- 考前/周末/期末节点内容；
- 小红书内容素材。

## 5. 核心使用场景

### 5.1 高频个人状态场景

| 场景 | 用户内心 | 可生成表达 |
|---|---|---|
| 早八前 | 人到了，魂没到 | `今日开机失败` |
| 熬夜后 | 白天请勿扰 | `白天加载中，晚上才上线` |
| 期末前 | 脑子不够用 | `本人大脑进入应急模式` |
| 群聊冷场 | 想救但不想负责 | `我在，但别让我当主理人` |
| 室友约饭 | 可以但别让我决定 | `能吃，但不负责选店` |
| 周末 | 想出门又懒 | `灵魂想出门，身体不同意` |
| 社交后 | 电量归零 | `已进入省电模式` |
| crush 聊天后 | 脑内很吵 | `表面已读，内心开会` |
| 合照后 | 嘴硬但管理表情 | `我没抢镜头，镜头自己来的` |
| 被安排后 | 不想营业 | `本人反对 KPI 式社交` |

### 5.2 群聊传播场景

用户生成后发群里：

```text
今天这个状态有点像我。
```

朋友可能回复：

```text
这不就是你？
给我也整一个。
我今天也这个。
你这个不准，你更严重。
```

产品要刻意制造“朋友可接话点”。

### 5.3 朋友圈/小红书场景

用户不想写长文，只发图 + 一句嘴硬文案：

```text
不认。
但他们都说像。
```

或：

```text
今天这个状态先挂出来。
```

## 6. 产品核心机制

### 6.1 三次点击生成

P0 核心要求：用户不需要思考太多。

流程：

1. 选场景；
2. 选状态；
3. 选语气；
4. 生成 3 张候选卡。

### 6.2 输入设计

#### Step 1：场景

P0 六大场景：

1. 上课/学习；
2. 宿舍/室友；
3. 群聊/社交；
4. 出门/周末；
5. 暗恋/聊天；
6. 什么都不想干。

#### Step 2：状态

P0 十二个状态：

1. 没电；
2. 嘴硬；
3. 想去但懒；
4. 想被约但不想主动；
5. 脑内很吵；
6. 不想负责；
7. 人在加载；
8. 已经开摆；
9. 想说但没说；
10. 社交后遗症；
11. 表面正常；
12. 需要朋友救一下。

#### Step 3：语气

P0 三种语气：

1. `朋友锐评`：像朋友在吐槽；
2. `本人嘴硬`：像自己在狡辩；
3. `系统公告`：像一张挂牌/通知/说明书。

### 6.3 输出结构

每张卡固定 4 个模块：

1. **今日标题**
   - `今日本人状态：在线装死中`
   - `今日社交电量：低于安全线`

2. **自我认领**
   - `我不是不回，我是在等一个更像人的我上线。`

3. **朋友锐评**
   - `你不是忙，你是在逃避一切需要回复的东西。`

4. **互动钩子**
   - `你觉得像我吗？不像我删。`
   - `发群里看看谁先认领。`

### 6.4 三张候选卡

同一组输入生成三张不同表达方向：

| 候选 | 定位 | 示例 |
|---|---|---|
| A 损友锐评版 | 最适合发群 | `你不是安静，你是在后台运行。` |
| B 本人嘴硬版 | 最适合发朋友圈 | `我没有装死，我只是暂时下线。` |
| C 公告挂牌版 | 最适合小红书/截图 | `今日展出：低电量本人。` |

用户不需要编辑，最多点击：

- `换一句更嘴硬的`
- `换个没那么狠的`
- `给室友也生成一张`

## 7. 内容系统设计

### 7.1 P0 不依赖 AI

P0 不做实时 AI 生成，原因：

- 输出质量不可控；
- 中文梗感不稳定；
- 容易油腻/像 AI；
- 开发成本高；
- 审核风险更大。

P0 用规则模板 + 高质量文案池：

- 6 个场景；
- 12 个状态；
- 3 种语气；
- 每个组合至少 2-3 条文案；
- 初始文案池约 200-300 条。

### 7.2 文案原则

必须：

- 短；
- 有口语感；
- 有嘴硬感；
- 有朋友接话点；
- 像人写的，不像产品文案；
- 能被截图单独传播。

禁止：

- 心理诊断；
- 鸡汤；
- 教育用户；
- 过度营销；
- “精准分析你的人格”；
- “治愈社恐”；
- 太像 MBTI 说明书。

### 7.3 文案样例

#### 场景：群聊/社交 + 状态：不想负责 + 语气：本人嘴硬

标题：

```text
今日群聊状态：我在，但别点我名
```

自我认领：

```text
我不是不想参与，我只是不想成为那个开始组织的人。
```

朋友锐评：

```text
你不是沉默，你是在等别人先把场子救活。
```

互动钩子：

```text
发群里看看谁先说“这不就是你”。
```

#### 场景：出门/周末 + 状态：想去但懒 + 语气：朋友锐评

```text
今日本人状态：灵魂已出门，身体不同意。

你不是没兴趣，你只是出门启动成本过高。

朋友锐评：报名时很真诚，出门前很想消失。

谁懂。
```

#### 场景：暗恋/聊天 + 状态：脑内很吵 + 语气：系统公告

```text
系统提示：本人大脑弹幕超载。

表面：嗯嗯好的。
内心：这句话要不要回？回太快会不会很明显？

朋友锐评：你不是在聊天，你是在写论文答辩。
```

## 8. 视觉系统

### 8.1 视觉定位

不是精致海报，而是：

> 可截图、可发群、像学生自己会转的状态卡。

视觉关键词：

- 桌面便签；
- 系统公告；
- 动物园挂牌；
- 聊天截图；
- 备忘录；
- 大字报；
- 表情包；
- 低精但有梗。

### 8.2 P0 模板类型

初始 6 套模板：

1. **便签贴纸版**：适合日常状态；
2. **系统弹窗版**：适合“警告/加载/故障”；
3. **朋友锐评卡**：适合发群；
4. **动物园挂牌版**：适合“今日展出”；
5. **聊天截图版**：适合嘴硬/朋友回复；
6. **大字报版**：适合小红书首图。

### 8.3 设计原则

- 字要大，缩略图可读；
- 卡片上只放 1-2 个核心金句；
- 不加大 logo；
- 不做二维码；
- 不做广告 banner；
- 卡片本身要像内容，不像产品物料。

## 9. 用户链路

### 9.1 P0 完整链路

```text
入口
  ↓
选择场景
  ↓
选择状态
  ↓
选择语气
  ↓
生成 3 张候选卡
  ↓
保存 / 换一句 / 给朋友生成
  ↓
发群/朋友圈/小红书
  ↓
朋友接话/求链接
  ↓
二次用户进入
```

### 9.2 页面结构

#### Page 1：入口页

核心文案：

```text
今天这个状态，别自己写了。
3 秒生成一张“今天的你”。
```

按钮：

```text
生成今天的我
```

#### Page 2：选场景

问题：

```text
今天主要卡在哪个场景？
```

选项：6 个大按钮。

#### Page 3：选状态

问题：

```text
你现在更像哪种状态？
```

选项：12 个 chip，可多选 1-2 个。

#### Page 4：选语气

问题：

```text
这张卡想怎么说你？
```

选项：

- 朋友锐评；
- 本人嘴硬；
- 系统公告；
- 随便来一个。

#### Page 5：结果页

展示 3 张候选卡。

按钮：

- `保存这张`
- `换一句`
- `给朋友生成`
- `再来一张`

### 9.3 二次生成链路

朋友看到卡片后进入，默认入口文案变为：

```text
你朋友已经生成了。
现在轮到你。
```

这样承接分享语境。

## 10. 习惯/依赖机制

这里不做“操控型成瘾”，而做可持续使用理由。

### 10.1 触发器

每日真实触发：

- 今天上课很困；
- 今天群聊很尬；
- 今天想出门又懒；
- 今天被室友约饭；
- 今天期末崩溃；
- 今天想发点东西但没话说。

### 10.2 行动

3 次点击生成。

行动必须足够低成本：

- 不登录；
- 不写长文本；
- 不填资料；
- 不选太多选项；
- 生成时间 < 3 秒。

### 10.3 奖励

奖励不是系统给的，而是朋友给的：

- 被认出；
- 被吐槽；
- 被转发；
- 被要链接；
- 被要求给别人生成。

### 10.4 再触发

第二天出现新状态，用户再次打开。

为了强化再触发，可以做：

- 每日 1 个新模板；
- 节点模板：周一、周五、期末、雨天、早八；
- 热门状态榜：今天大家都在“低电量”；
- “给室友生成一张”功能。

- 朋友会要链接；
- 用户会连续生成多张；
- 用户会给室友/朋友生成；
- 评论里出现“这个像我/给我也整”。

如果只出现“看了但不保存”，说明内容有趣但表达动机不足。

## 13. 商业与战略价值

### 13.1 对 Meetu 的价值

它能成为 Meetu 的高频前置触点：

- 低成本获取用户；
- 训练 Meetu 的语言风格；
- 积累用户状态偏好；
- 给小红书/公众号提供内容素材；
- 为线下小局和搭子场景做轻承接。

### 13.2 后续承接方式

不能一开始强推 Meetu 主产品。正确承接是轻的：

- 状态卡底部弱品牌；
- 结果页底部一句：`今天想出门但懒？看看有没有低压小局。`
- 不进入分享图；
- 不硬放下载/加群/报名。

### 13.3 潜在商业化

P0 不商业化。P1 后可能：

- 校园活动定制模板；
- 社团/活动破冰模板；
- 品牌联名状态卡；
- Meetu 内部活动传播工具；
- 高质量模板库。

但前提是先验证自发表达和分享。

## 14. 风险与反例

### 14.1 最大风险：变成普通模板工具

如果只是“选模板生成图”，价值不够。必须输出“像我”的内容。

解决：文案质量优先于模板数量。

### 14.2 最大风险：像 AI 生成废话

用户对 AI 味敏感。

解决：P0 用人工文案池，不实时 AI。

### 14.3 最大风险：日签化/鸡汤化

用户不需要每日正能量。

解决：表达要嘴硬、自嘲、可吐槽，不要鼓励式文案。

### 14.4 最大风险：只有传播，没有留存

用户可能玩一次就走。

解决：做“状态”而不是“身份”，通过日常场景更新提高复用。

### 14.5 最大风险：过度自嘲造成负面感

不能把用户写成“废物”或攻击用户。

解决：所有表达必须有“可爱嘴硬”的余地，不做羞辱。

## 16. P0 研发方案

### 16.1 技术形态

- 静态 H5；
- React/Vite；
- 本地文案 JSON；
- 本地模板 CSS；
- html2canvas 导出 PNG；
- localStorage 记录最近生成；
- 无后端或轻量埋点。

### 16.2 生成逻辑

输入：

```json
{
  "scene": "群聊/社交",
  "state": ["不想负责", "在线装死"],
  "tone": "本人嘴硬"
}
```

输出：

```json
{
  "title": "今日群聊状态：在线装死中",
  "selfLine": "我不是不回，我是在等一个更像人的我上线。",
  "roast": "你不是忙，你是在逃避一切需要回复的东西。",
  "hook": "发群里看看谁先认领。",
  "template": "sticky-note"
}
```

### 16.3 数据结构

```ts
type Scene = 'study' | 'dorm' | 'groupchat' | 'weekend' | 'crush' | 'nothing'
type StateTag = 'low_battery' | 'mouth_hard' | 'want_but_lazy' | 'want_invited' | 'brain_noise' | 'no_responsibility' | 'loading' | 'lying_flat'
type Tone = 'friend_roast' | 'self_defense' | 'system_notice'

type StateCard = {
  id: string
  scene: Scene
  stateTags: StateTag[]
  tone: Tone
  title: string
  selfLine: string
  roast: string
  hook: string
  template: string
  themeColor: string
}
```

## 17. 验证计划

### 17.1 第 0 阶段：人工样例包

先不开发，做 30 张图：

- 12 个状态；
- 3 种语气；
- 6 套模板混用。

发给内部和小范围用户，看：

- 哪些愿意保存；
- 哪些愿意发群；
- 哪些让朋友接话。

### 17.2 第 1 阶段：H5 MVP

开发 1 周内可完成：

- 3 步选择；
- 3 张候选；
- 保存 PNG；
- 基础埋点。

### 17.3 第 2 阶段：小红书测试

发内容不说“产品上线”，而是晒图：

- 单张状态卡；
- 极短吐槽；
- 评论区看是否有人问链接。

### 17.4 成功阈值

MVP 第一周：

- 生成完成率 > 60%；
- 保存率 > 35%；
- 二次生成率 > 15%；
- 至少 10% 用户点击“给朋友生成”；
- 外部评论/私信出现“求链接/我也要”。

## 18. 当前 PM 判断

这个方向比“身份表达卡”更接近高频使用，因为它不是要求用户定义长期身份，而是捕捉每天都发生的状态表达。

它的根本产品命题是：

> 用户不是每天都想认识新人，但每天都有一个想发出去的自己。

如果我们能把这个“自己”包装得足够低压、好笑、可接话，就有机会形成持续使用。

当前建议：

1. 暂不做大型 AI 生成器；
2. 先做 30 张人工状态卡样例；
3. 同步写 200 条文案池；
4. 用小红书/微信群验证保存和接话；
5. 再决定是否开发 H5。

## 19. 需要进一步确认的问题

1. 这个产品是否作为 Meetu 独立 H5，还是嵌入 Meetu 官网/小程序？
2. 首发状态要偏“社交状态”，还是覆盖更泛的学习/宿舍/周末/恋爱？
3. 视觉要更像“排版小动物”的抽象符号，还是更像“大字报/便签/系统通知”？
4. 分享图是否允许弱 Meetu brand，还是完全不露出？
5. 是否要保留“朋友锐评”作为统一模块？
6. 是否需要“给朋友生成一张”功能作为 P0？
7. H5 是否需要后端保存结果，还是纯前端即可？
