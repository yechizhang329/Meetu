## 0. 本版锁定结论

### 0.1 方向不变

**心情值班室是好的方向。** 继续做：

> 具象情绪代理人 / 动物员工 / 心情值班室 / 嘴替。

本轮不是换方向，不是退回泛状态卡，也不是围绕 Meetu 做社交入口。被否定的是上一轮交付状态：产品边界太重、结构缝合、视觉死气沉沉、输出不像用户会发的图。

### 0.2 核心从“像我”修正为“嘴替”

本产品第一目标不是让用户觉得：

```text
这很像我。
```

而是让用户觉得：

```text
这句话我不想自己说，但它替我说了。
```

用户分享时的心理应该是：

```text
不是我说的，是它说的。
```

朋友接话时的心理应该是：

```text
别装，这就是你。
```

### 0.3 MVP 但必须是完整系统

P0 是 MVP，但不是 4 张 demo 图。P0 必须同时成立：

1. 角色系统成立；
2. 核心使用场景覆盖完整；
3. 嘴替文案池可用；
4. 输出图质量过关；
5. H5 可生成、保存、换句、换角色；
6. 首发运营路径可执行。

成本控制只控制实现方法、资产深度、交互复杂度，**不能牺牲核心内容覆盖和最终输出质量**。

### 0.4 本版停止沿用的旧产物

以下内容保留为探索记录，不作为 v1.0 final 基线：

- 旧 `v0.8/v0.9` 的 H5 UI；
- 旧 96 条文案池；
- 旧 4 区分享卡结构；
- 顶部 banner / tag 行 / 朋友鉴定框 / 测试结果式布局；
- “米色 SaaS + 角色卡片”的设计方向。

继续保留的验证结果：

- task #17 嘴替文案味道验证通过：4 个角色的嘴替语言方向成立；
- task #30 嘴替输出图试金石通过：4 张图第一次证明“它替我说一句话”的方向成立。

## 1. 产品定义

### 1.1 一句话定义

**心情值班室是一套具象嘴替 H5：用户选择今天不想自己说出口的场景，系统派一只动物员工替她说一句话，并生成一张可以直接发出去的嘴替图。**

### 1.2 用户承诺

用户打开后，应该获得一个很具体的承诺：

```text
给我 10 秒，我帮你叫一只出来替你说。
```

不是：

```text
做一个测试，看看你是什么动物。
```

也不是：

```text
生成一张精美情绪卡片。
```

### 1.3 目标用户

核心用户：18-24 岁在校大学生，女性受众占比预计更高，但不能排斥整体大学生群体。

她们的表达状态：

- 有话想放出去，但不想太认真；
- 想拒绝、拖延、嘴硬、装正常，但不想自己显得太重；
- 喜欢借第三方表达自己，例如歌、梗图、IP 表情包、朋友圈状态；
- 抗拒“被测试/被分类/被诊断”；
- 抗拒“替品牌打广告”的分享图；
- 愿意分享一个能让朋友自然接话的东西。

### 1.4 分享成立的条件

一张图要让她愿意发，必须同时满足：

1. **这句话单独成立**：不解释产品也能被理解；
2. **角色替她承担尴尬**：话是动物说的，不是她郑重声明；
3. **产品边界极弱**：不像广告、测试结果、营销海报；
4. **朋友能接话**：朋友能评论“你别装”“这就是你”“我今天也是这只”。

## 2. P0 角色系统

P0 保留 4 个角色。每个角色不是完整 IP 设定集，而是一个“嘴替职能”。

| 角色 | 替用户说什么 | 核心状态 | 已通过基准句 |
|---|---|---|---|
| 嘴硬鹅 | 被说中但不承认 | 嘴硬 / 心虚 / 反驳 | `我没事。/ 真的。/ 我说真的。` |
| 低电量猫 | 不想营业、不想动 | 没电 / 下线 / 拒绝输入 | `人在。/ 电不在。` |
| DDL 仓鼠 | 会做但不是现在 | 拖延 / 假装不急 | `会做的。/ 不是现在。` |
| 后台羊驼 | 表面礼貌，后台崩 | 维持体面 / 内部过载 | `表面：好的。/ 后台：不要再来了。` |

### 2.1 P0 不新增角色

P0 不新增勿扰刺猬、被窝水豚、夜班猫头鹰等角色。原因：

- 当前 4 角色已经能覆盖大多数嘴替职能；
- 多角色会增加资产、文案、识别成本；
- 先把 4 角色做深，让用户形成记忆点。

P1 再考虑扩展角色。

## 3. P0 核心场景覆盖

内容覆盖不能因为成本收缩。P0 至少覆盖 8 个核心使用场景，每个场景必须有 3-5 条可发嘴替句。

| 场景 ID | 用户时刻 | 用户不想自己说的话 | 主角色 | 备选角色 | 示例嘴替方向 |
|---|---|---|---|---|---|
| S1 嘴硬否认 | 被朋友说中了 | 我没事 / 我没有 / 别说我 | 嘴硬鹅 | 后台羊驼 | `我没事。真的。我说真的。` |
| S2 低电量拒绝营业 | 不想说话、不想动 | 别叫我 / 今天不营业 | 低电量猫 | 嘴硬鹅 | `人在。电不在。` |
| S3 DDL / 拖延 | 被催任务/作业 | 会做，但不是现在 | DDL 仓鼠 | 嘴硬鹅 | `会做的。不是现在。` |
| S4 表面正常后台崩 | 表面礼貌答应 | 好的，但别再来了 | 后台羊驼 | DDL 仓鼠 | `表面：好的。后台：不要再来了。` |
| S5 想安静 / 勿扰 | 不想被追问 | 别靠太近 / 先别问 | 低电量猫 | 后台羊驼 | `今天我不在。猫替我。` |
| S6 被约出门但不想动 | 朋友突然约局 | 我想来，但身体不签字 | 低电量猫 | DDL 仓鼠 | `我人可以去，身体没同意。` |
| S7 消息不想回 | 看到了但不想开口 | 不是不理你，是嘴没上班 | 低电量猫 | 嘴硬鹅 | `消息看到了。嘴没到。` |
| S8 被安排 / 被催 | 被别人推着走 | 我会配合，但我想逃 | 后台羊驼 | DDL 仓鼠 | `我说可以，是因为说不可以要解释。` |

### 3.1 文案池 P0 要求

Lucy 需要交付：

- **40 条 A 级嘴替句**：8 场景 × 5 条；
- **16 条 B 级 backup**：每个角色 4 条，用于换一句兜底；
- 每条必须通过 5 问：
  1. 我会不会发？
  2. 它是不是替我说，而不是产品替我总结？
  3. 朋友能不能接话？
  4. 有没有产品金句/押韵段子味？
  5. 有没有测试、诊断、分类、营销感？

字段结构：

```text
sceneId / roleId / 用户原话 / 嘴替句 / 朋友接话 / 配文建议 / 风险词检查 / 视觉模式
```

### 3.2 文案风格边界

要像：

- 用户脑子里真实会冒出来的话；
- 动物替她说出口；
- 可以有流水账、停顿、自我推翻、轻荒诞；
- 不追求工整、押韵、金句感。

不要像：

- 产品精修段子；
- 心理测试结果；
- 押韵 slogan；
- 精准人格标签；
- 运营文案。

## 4. 输出图是产品核心

### 4.1 输出图不是结果卡

输出图不是：

- 测试结果；
- 角色档案；
- 营销海报；
- UI 截图；
- HTML 组件拼出来的卡片。

输出图应该是：

> 一张“它替我说了一句话”的图。

### 4.2 输出图只保留 4 个层级

1. 嘴替句：视觉主角；
2. 动物代理人：承担尴尬、制造可爱/荒诞；
3. 轻微状态动作或 0-1 个梗道具；
4. 极轻落款，弱到不影响用户发。

禁止出现在分享主图中：

- 顶部大 banner；
- 大 logo；
- `焦虑/DDL/拖延` 等标签；
- 朋友鉴定区框；
- 分数、雷达图、证书感；
- “你是/你属于/你被判定”；
- 复杂办公室背景。

### 4.3 4 张基准图结论

task #30 4 张试金石通过，作为 v1.0 输出图方向基准：

| 角色 | 判定 | final 微修 |
|---|---|---|
| 嘴硬鹅 | A- | 身体更心虚，帽子不要加重 |
| 低电量猫 | A | 保持，是当前风格上限正样本 |
| DDL 仓鼠 | A- | 更像仓鼠，避免泛小动物 |
| 后台羊驼 | B+ | 乱涂减少 25-35%，表情更“礼貌撑住” |

这些图是 reference，不是 final production asset。

## 5. Image2 / H5 生产策略

### 5.1 基本原则

实现方式不预设。最终判断标准只有一个：

> 目标用户会不会愿意把导出的图发出去。

如果纯 HTML/CSS 便宜但看起来像拼接，淘汰。  
如果 Image2 效果好但 scope 失控，收敛。  
P0 要在效果和成本之间取平衡。

### 5.2 三档生产方式

| 方式 | P0 用途 | 什么时候用 | 风险 |
|---|---|---|---|
| Image2 带文字整图 | 4 张首发爆点图 / 运营发布固定图 | 文字固定且中文字生成稳定时 | 改字成本高；逐图验收 |
| Image2 无字大背景 + H5 叠字 | P0 主路径 | 动态文案池、换一句、换角色 | 叠字必须融入画面，否则像拼接 |
| HTML/CSS 纯拼图 | 原型 / 兜底 / 内测 | 快速验证链路 | 不作为最终审美目标 |

### 5.3 P0 推荐路径

P0 采用：

```text
Image2 无字大背景 / 动物代理人图
+ H5 叠嘴替文字
+ html2canvas 导出最终图
```

同时为 4 个首发 flagship 句尝试：

```text
Image2 带文字整图
```

如果中文字稳定、整体感明显更强，就用于运营首发；如果文字不稳，则回到无字图 + H5 高质量叠字。

### 5.4 成本控制方法

成本控制不是降低产品要求，而是优化生产方式。

所有 Image2 任务必须写明：

1. 本批目标；
2. 一 call 产几张；
3. 是否使用 contact sheet / 多图合成；
4. crop 规则；
5. 复用路径；
6. 失败后是否重试；
7. 最大 call 数。

默认策略：

- 同一角色的动作/表情/构图变体优先合成一张 2×2 contact sheet，一次 call 后本地 crop；
- 同一角色不同场景只在必要时追加，不为了“看起来完整”扩资产；
- P0 不做 8 场景 × 4 角色全量专属图；
- 文案覆盖完整，视觉资产通过角色级主图 + 高质量文字叠加承载。

### 5.5 P0 资产清单

P0 必需：

| 资产 | 数量 | 生产方式 | 用途 |
|---|---:|---|---|
| 4 角色 final 嘴替主图（无字） | 4 | Image2，必要时 contact sheet + crop | H5 动态输出图基底 |
| 4 角色 flagship 带字图 | 4 | Image2 尝试；若文字不稳则 H5 叠字导出 | 首发/传播 benchmark |
| 4 角色裁切透明图或局部图 | 4 | 从 final 主图裁切 | H5 页面角色反馈 / 按钮角标 |
| 手写/拟手写文字样式 | 1 套 | 字体 / SVG / CSS 方案 | 让叠字不像 UI 字体 |
| 运营首发图 | 1-2 | 从 flagship 中选 | XHS/朋友圈首发 |

P0 不做：

- 每句文案一张图；
- 角色完整表情包；
- 复杂动效；
- 实时 AI 生图；
- 用户自定义上传图。

### 5.6 技术选型开放评估

本项目不绑定任何既有实现路径。React + html2canvas 只是已有能力，不是默认答案。Dave 需要在正式开发前给一个轻量技术选型判断，核心指标是：

> 哪种方案能以可控成本产出最像“用户愿意发出去”的最终图。

允许评估的方案包括但不限于：

| 方案 | 适用场景 | 判断重点 |
|---|---|---|
| Canvas / SVG 渲染 | 需要高质量排字、手写字体、精确导出 | 字体加载、中文换行、导出清晰度 |
| React DOM + html2canvas | 快速复用旧链路 | 是否有前端组件拼接感 |
| 预渲染 SVG/PNG 模板 | 固定结构、多文案变体 | 文字与画面是否融合 |
| Image2 带字整图 | 首发固定爆点图 | 中文稳定性、重做成本 |
| Image2 无字背景 + 前端排字 | P0 动态主路径 | 叠字是否像原生画面的一部分 |
| 服务端/脚本离线渲染 | 需要批量产图或稳定 QA | 部署复杂度、生成速度 |
| 多图 contact sheet + crop | 控制 Image2 成本 | 裁切质量、一致性 |

技术选型不是为了炫技，必须服务三个结果：

1. 最终导出图整体感强；
2. 文案覆盖足够，不牺牲场景；
3. 成本和开发周期可控。

如果某个更大胆的技术路线能显著提高输出质量，可以采用；如果只是更复杂但最终图没有更好，淘汰。

## 6. H5 链路

### 6.1 链路原则

少问，快出嘴替。

用户不是来回答问题，而是来“叫一只出来”。

### 6.2 P0 链路

#### Step 0：首页

目标：立刻让用户理解产品承诺。

示例方向（不是最终文案）：

```text
今天这句，让谁替你说？
```

页面必须出现角色存在感，但不能像产品 landing。

#### Step 1：选场景

问题方向：

```text
哪句话你今天不想自己说？
```

8 个场景以用户语言出现，不以功能分类出现。

例如：

- 被说中了，但我不准备承认；
- 人还在，电先下班了；
- 会做的，不是现在；
- 表面好的，后台别来了；
- 想安静一点，先别问；
- 朋友约我，但身体没签字；
- 消息看到了，嘴没上班；
- 被催到了，但我想把话甩出去。

#### Step 2：结果 / 嘴替工作台

结果页不是“你的结果是”。

结果页应该表达：

```text
今天让它替你说。
```

展示：

1. 推荐动物；
2. 3 条可选嘴替句；
3. 当前输出图预览；
4. 主动作：保存这张；
5. 次动作：换一句 / 换一只 / 复制配文。

语气不再作为独立问卷页。若保留，作为结果页内的轻量 chip：

- 更嘴硬；
- 更摆烂；
- 更礼貌；
- 更装没事。

#### Step 3：保存 / 分享

P0 只做：

- 生成 4:5 输出图；
- 微信内长按保存；
- 非微信下载；
- 复制一条配文；
- 换一句 / 换一只。

不做：

- 登录；
- 发到平台；
- 评论区模拟；
- 好友鉴定输入；
- 用户自定义编辑器。

### 6.3 输出图导出要求

- 默认 4:5，适配 XHS / 朋友圈；
- 导出图必须 1080×1350；
- 文案不能溢出；
- 没有 placeholder；
- 没有内部 ID；
- 没有技术 tag；
- 没有明显组件拼接边界；
- 如果导出图不好看，页面再好看也不算通过。

## 7. 首发策略

### 7.1 首发不发合集

首发只推一个最强角色 / 最强句，降低理解成本。

推荐首发候选：

1. 低电量猫：`人在。/ 电不在。` —— 最稳、最通用；
2. 嘴硬鹅：`我没事。/ 真的。/ 我说真的。` —— 互动潜力最高。

最终由 Lucy 基于首发包给 2 个版本：

- A：低电量猫稳态首发；
- B：嘴硬鹅互动首发。

### 7.2 首发文案口径

继续沿用“轻自爆，不装路人”的方向，但要更短、更像用户自己发。

原则：

- 不解释太多产品；
- 不说“测试/精准/人格”；
- 不把它讲成 Meetu 功能；
- 主帖只让用户看见“这只替我说了一句”。

## 8. 验收标准

### 8.1 PM 总验收三问

每个核心输出都必须过三问：

1. **我会不会发？**
2. **它有没有替我说不想自己说的话？**
3. **朋友能不能自然接话？**

任何一问不过，不进入下一阶段。

### 8.2 输出图验收

每张图必须满足：

- 文字是主体，不是 UI 字段；
- 角色是在替用户说话，不是展示设定；
- 画面年轻、鲜活、有个性；
- 产品边界极弱；
- 没有测试/诊断/分类感；
- 没有廉价拼接感；
- 截图发出去不尴尬。

### 8.3 文案验收

每条 A 级文案必须满足：

- 用户自己可能真会这么说；
- 动物说出来更好笑/更轻；
- 不工整到像广告；
- 不沉重到像求安慰；
- 不抽象到需要解释；
- 朋友能接一句。

### 8.4 工程验收

- 选场景 → 出图 → 保存链路跑通；
- 4:5 导出尺寸正确；
- 微信长按保存可用；
- 非微信下载可用；
- placeholder / 内部 ID 构建期阻断；
- 文案池可配置；
- 图片资产可替换；

## 11. PM 自我约束

我作为 PM 不再做以下错误：

- 不把 agent 输入机械拼成 PRD；
- 不把外部案例表层特征当方向；
- 不用“完整系统”包装缝合怪；
- 不因为工程已做就迁就错误方向；
- 不因为成本控制牺牲产品 taste；
- 不让产品变成测试、报告、卡片生成器。

我的判断标准只保留一条：

> 目标用户会不会真的用它替自己说一句，并愿意发出去。

如果不行，就是不行，回退重做。
