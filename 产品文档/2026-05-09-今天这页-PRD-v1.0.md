# 今天这页 PRD v1.0

> 状态：重新规划稿，用于替代旧「心情值班室 v0.8/v0.9」继续讨论和拆任务。旧版本只作为探索记录，不再作为开发基线。

---

## 1. 核心判断

### 1.1 旧方案为什么失败

旧方案不是“UI 还不够好”，而是产品对象错了。

我们做的是：

> 一个产品帮用户生成一张带角色、标签、品牌和操作痕迹的分享卡。

用户真正会发的是：

> 一张看起来像她自己随手写出来、刚好能表达今天状态的图。

所以旧方案的问题是：

- **产品边界太强**：顶部品牌、标签、结果卡、朋友鉴定区、按钮逻辑，都在提醒用户“这是一个产品输出”。
- **表达主体错位**：动物、岗位、角色体系抢走了用户自己的状态。
- **文案太像产品金句**：第一人称不等于用户口吻；“我没有 / 我没电”如果太工整，仍像运营写的。
- **结构过重**：先选状态、再选语气、再看角色、再生成卡，链路像回答问卷，不像拿一张图。

### 1.2 新第一原则

> **先让最终输出图值得被用户发出去，再反推 H5。**

如果一张图本身不值得分享，角色体系、H5、文案池、视觉系统都没有意义。

---

## 2. 用户是谁

### 2.1 核心用户

以 18-24 岁大学生为主，其中女性用户占比预计更高。

她们不是缺“表达能力”，而是缺一个合适的**低压力表达载体**。

### 2.2 她们的行为习惯

她们已经在用这些东西表达自己：

- 网易云 / Spotify 歌词卡：让歌替自己说。
- 微信状态 / QQ 签名：挂一个轻状态。
- 表情包 / Loopy / Capoo / Chiikawa：让小角色替自己狼狈一下。
- 备忘录 / 账单 / 手写便签：把情绪藏进生活记录里。
- 小红书状态图 / 梗图：一句话让同类秒懂。

这些东西的共同点：

- 不是正面说“我需要关注”；
- 有第三方挡一下尴尬；
- 朋友能接话；
- 看起来不像广告；
- 用户可以说“我只是随手发一下”。

### 2.3 核心心理需求

> 我想把今天的状态发出去，但不想显得我在认真求关注；最好像我随手写的，又有一个小东西帮我挡一下尴尬。

拆开是 4 个需求：

1. **表达欲**：我想让别人知道我今天什么状态。
2. **否认权**：我不想显得太认真，别人问我还能嘴硬。
3. **被接住**：朋友最好能评论、拷打、认领、接梗。
4. **低成本复用**：今天发一张，明天还能再发一张，不用重新理解产品。

## 3. 外部案例约束

### 3.1 排版小动物 / Tiny Type

它的有效点不是“黑线小动物”，而是：

- 手写内容是主体；
- 小动物只是右下角 8-12% 的情绪落款；
- 品牌小到近乎消失；
- 没有卡片容器、结果标签、功能分区；
- 生活流水账最后一行反转，笑点来自真实生活。

给我们的约束：

- 不要把动物放大成主角 IP；
- 不要做“产品结果卡”；
- 不要用标签解释用户；
- 输出必须像用户自己写的纸，不像产品替她写的金句。

### 3.2 音乐分享卡

网易云 / Spotify 的本质是“第三方代理”：

- 用户不是说“我 emo”，而是“这首歌刚好”。
- 分享的是我的状态，不是产品能力。

给我们的约束：

- 小动物是状态代理，不是测试结果；
- 品牌必须后退；
- 用户发图时要觉得“这是我今天”，不是“这是产品总结我”。

### 3.3 表情包 / IP 状态图

Loopy / Capoo / Chiikawa 的价值不是高精 IP，而是“狼狈可代入”：

- 小角色有缺点；
- 它替用户承受尴尬；
- 用户可以借它说自己。

给我们的约束：

- 角色要像同谋，不像品牌吉祥物；
- 可以可爱，但不能卖萌；
- 角色服务状态，不服务产品设定。

## 4. 产品定义

### 4.1 暂定名

推荐：**今天这页**。

备选：

- 替我写一下
- 今日状态纸条
- 别问，纸上写了
- 小动物替我记一下

不再推荐“心情值班室”作为主名。它的“房间 / 岗位 / 系统”感太强，容易把产品推向设定集。

### 4.2 一句话定义

**今天这页**是一个把当下状态变成“可发出去的一页纸”的 H5：用户点一个生活触发器，拿到几张像自己随手写出来的状态纸条；小动物只在旁边当落款、同谋和挡箭牌。

### 4.3 产品不是

- 不是人格测试；
- 不是 AI 生图工具；
- 不是角色 IP 图鉴；
- 不是文案生成器；
- 不是心理诊断 / 疗愈工具；
- 不是社交匹配产品。

### 4.4 产品是

> 一个高频、低压力、可复用的状态表达弹药库。

用户来这里不是为了完成问卷，而是为了拿走一张“今天能发”的图。

## 5. P0 不先做完整 H5，先做 3 张输出样张

P0 的第一验收对象不是页面，而是 3 张图。

三张图必须能回答：

> 如果没有 H5 入口、没有产品解释、没有团队背书，用户会愿意把它保存/发出去吗？

### 5.1 样张 A：生活流水账纸

**目的**：验证 Tiny Type 式生活真实感。

**适用状态**：钱去哪了 / 今天电量去哪了 / 一天怎么又没了。

**结构**：

- 纸张横线 / 点阵；
- 手写为主；
- 小动物右下角 8-12%；
- 品牌极小；
- 最后一行反转。

**Demo 文案 1：钱去哪了**

```text
今天只是正常活着

早饭 12
奶茶 18
打印 6
打车 21
晚饭 32
小零食 15

也没买什么

那我钱呢
```

**Demo 文案 2：电量去哪了**

```text
今日能量预算
100 点

起床 -30
上课 -20
回消息 -15
装正常 -35

剩 0？
那我怎么还倒欠 10 点
```

**动物**：低电量猫右下角趴着 / 端空杯 / 眼神放空。

---

### 5.2 样张 B：一句状态纸

**目的**：验证微信状态 / 小红书状态图式秒懂表达。

**适用状态**：没电、不在线、不想营业。

**结构**：

- 一句大字；
- 一句补充小字；
- 小动物 15-25%；
- 无标签、无解释。

**Demo 文案**

```text
本人今日电量不足

非必要别叫醒
```

备选：

```text
我人在这里

魂先下班了
```

```text
今天不太想被问

问就是还活着
```

**动物**：低电量猫 / 后台羊驼，作为状态落款，不解释角色。

---

### 5.3 样张 C：嘴硬纸条

**目的**：验证朋友互动和评论钩子。

**适用状态**：被说中但不认、朋友拷打、嘴硬。

**结构**：

- 极短；
- 故意留给朋友说“别嘴硬”；
- 小动物是嘴硬落款。

**Demo 文案**

```text
我没有。

但他们都说像。
```

备选：

```text
别说我

我不认
```

```text
不是我

是这只鹅先这样的
```

**动物**：嘴硬鹅右下角，翅膀挡嘴或背对纸边。

## 6. 输出图硬规则

### 6.1 必须保留

- 像用户自己写的；
- 一个生活细节；
- 一个状态；
- 一个反转或嘴硬点；
- 一个小动物落款；
- 极弱产品痕迹。

### 6.2 必须删除

- 顶部产品 banner；
- 大 logo / 大产品名；
- 结果标签；
- “你是/你属于/你被判定”；
- 人格、测试、心理、治愈、精准等词；
- 朋友鉴定区框；
- 表单 / 证书 / 结果卡 / 报告感；
- 多角色设定解释。

### 6.3 元素优先级

文字内容 > 纸张媒介 > 小动物 > 品牌。

小动物占比：

- 流水账纸：8-12%；
- 一句状态纸：15-25%；
- 角色状态纸：可到 30%，但不能盖过文字。

品牌占比：

- 只允许底部极小落款；
- 不允许影响用户把图当成“自己的图”。

## 7. H5 链路（样张通过后）

### 7.1 H5 目标

不是让用户“完成测试”，而是让用户最快拿到一张能发的图。

目标路径：

> 点入口 → 点一个今天发生了什么 → 直接看到 3 张图 → 保存 / 换一句 / 微改。

### 7.2 首页

主句：

```text
今天这页，替你写一下。
```

副句：

```text
选个今天的破事，拿一张能发的纸。
```

CTA：

```text
写今天这页
```

首页不要做品牌介绍，不解释“这是一个什么产品”。

### 7.3 第一步：生活触发器

用户不是回答问题，而是点一个今天发生的事。

P0 触发器：

1. 钱又不知道去哪了
2. 人在，电不在
3. DDL 在追我
4. 朋友一约我就想躲
5. 被说中了，但我不认
6. 看起来没事，其实后台炸了

### 7.4 第二步：直接给输出图

默认给 3 张，不先让用户选语气：

1. 流水账纸；
2. 一句状态纸；
3. 小动物角落纸。

用户滑动/点选即可。

### 7.5 结果页动作

只保留：

- 保存这页；
- 换一句；
- 改几个字。

不保留：

- 语气选择页；
- 角色解释；
- 标签选择；
- 朋友鉴定区；
- 多按钮功能堆叠。

## 8. 文案系统

### 8.1 旧文案池作废

旧 96 条文案不作为 base。原因：

- 太工整；
- 太像产品金句；
- 太会写；
- 第一人称但不像用户自己写的；
- 缺生活细节和自然反转。

### 8.2 新文案像什么

像：

- 便签；
- 账单；
- 草稿；
- 备忘录；
- 一条没写完的朋友圈；
- 自己脑子里碎碎念。

不像：

- slogan；
- 段子合集；
- 品牌文案；
- 测试结果；
- 角色台词设定。

### 8.3 文案公式

**公式 A：流水账 + 翻车**

```text
今天只是正常活着

早饭 12
打印 6
奶茶 18
晚饭 32

也没买什么
那我钱呢
```

**公式 B：状态句 + 嘴硬补一句**

```text
我没事

只是今天不太适合被问
```

**公式 C：生活事件 + 最后一行自曝**

```text
本来想早点睡

洗澡 20 分钟
刷手机 2 小时
想人生 15 分钟

现在开始怪床
```

**公式 D：朋友可拷打句**

```text
我没有

你们不要开始
```

## 9. 视觉系统

### 9.1 不先做 design system

P0 不做完整设计系统。先做 3 张能发的输出图。

### 9.2 视觉方向

优先方向：

1. 手写横线纸；
2. 备忘录纸；
3. 歌词卡式大字；
4. 群聊截图式纸条。

每一种都要围绕“像用户自己发的图”，而不是“像产品生成的卡”。

### 9.3 动物规则

动物是：

- 落款；
- 同谋；
- 状态旁白；
- 尴尬缓冲。

动物不是：

- 主角色；
- 测试结果；
- 分类图标；
- 品牌 mascot。

### 9.4 字体规则

P0 要重视手写/便签字体，不再把手写字体当小装饰。

但需要注意：

- 中文字体包体积；
- 字体授权；
- H5 加载速度；
- 是否可用 SVG/图片化方案绕过大字体包。

## 10. 技术实现原则

### 10.1 先样张，后 H5

Dave 不继续改旧 H5。第一阶段只需要能产出 3 张静态样张。

### 10.2 H5 最小实现

样张通过后，H5 需要：

- 2 步交互；
- 生成 3 张图；
- 支持保存；
- 支持换一句；
- 支持轻编辑。

不需要：

- 登录；
- 后端；
- 数据库；
- 实时 AI 生图；
- 复杂角色资产；
- 多页问卷。

### 10.3 技术难点

1. 手写字体/图像文字的实现方式；
2. 纸张横线/点阵背景；
3. html2canvas 导出稳定性；
4. 轻编辑后重新导出；
5. 小动物作为角落 PNG 的尺寸和位置；
6. 品牌水印极小但可追踪。

## 11. 验收标准

任何输出样张必须过 6 问：

1. 去掉产品名后，它像用户自己会发的东西吗？
2. 用户发它是在表达自己的状态，还是在给产品做广告？
3. 朋友看到能不能自然接话？
4. 这张图是否只讲一个梗？
5. 小动物是否降低尴尬，而不是增加产品感？
6. 如果我不是团队成员，我会不会保存/转发这张图？

不过即打回。

4. 小动物是否从主角降级为角落落款；

## 14. 当前结论

这不是“心情值班室改得更好看”的问题。

新方向应该是：

> 做一个让用户每天能拿走一页状态的轻工具。

判断标准不是产品完整度，而是：

> 这页她会不会发。
