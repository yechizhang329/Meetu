## 1. 产品一句话

心情值班室是一个面向在校学生的轻量 H5：用户选择一个当下状态，再选择一个"嘴替人格"替自己表达，生成一张可以保存或分享的状态图；用户可以在结果页"换个说法"，也可以在同一场景下换另一个嘴替看看。

产品要让用户感觉：

> "这很像我。"
> "这句话我不想自己说，但它替我说了。"

---

## 2. 用户与问题

### 2.1 目标用户

P0 目标用户是高社交密度的在校大学生。

典型环境：
- 宿舍；
- 班级；
- 小组作业；
- 社团/学生组织；
- 课程/早八/期末；
- 消息、群聊、朋友圈/QQ 空间/小红书等表达场景。

用户画像倾向：
- 年龄主要在 18–22 岁；
- 女性用户可能更容易早期采用，但产品和视觉不能刻板"女性化"；
- 对社交表达、梗图、情绪卡片、状态分享有较高接受度；
- 会在表达前考虑"别人怎么看""会不会被追问""会不会显得我太严重/太刻薄/太脆弱"。

### 2.2 核心问题

用户不是简单"不会说话"，而是很多时候**不想亲自承担这句话的表达成本**。

常见表达成本包括：
- 说太认真，会显得自己状态很严重；
- 说太直接，会引发冲突或让别人不舒服；
- 不说，又可能被误解；
- 回复消息，会被拖进更多对话；
- 吐槽某件事，会显得自己不好相处；
- 解释情绪，会显得暴露或麻烦。

### 2.3 产品机会

"嘴替角色"可以成为表达缓冲层：
- 它替用户承担一部分语气责任；
- 它让表达从"我本人说"变成"这个角色替我说"；
- 它让情绪变成可保存、可分享、可共鸣的对象；
- 它既像用户，又和用户保持一点距离。

### 2.4 产品与 Meetu 平台的关系

心情值班室不是 Meetu 的核心交易产品，而是**校园嘴替内容入口**——用低防御表达把用户从"看热闹"带到"愿意在 Meetu 留下一点状态"。

价值链：选状态 → 得到一句像自己的话 → 保存/复制/分享 → 进入 Meetu 广场/个人状态/同校互动。

不应该：选状态 → 强行注册 → 强行报名活动。强推交易会破坏低防御优势。

P0 承接方式：
1. 结果页强分享/保存/复制，先验证表达共鸣；
2. Meetu 内承接为"发到广场 / 保存到我的状态 / 换个嘴替"；
3. 角色结果和场景选择沉淀为轻量用户标签，但不要显得像心理诊断。

## 3. 产品原则

### 原则 1：先让用户认同，再解释功能

用户首先要感觉"这像我/像我会说的话"，而不是先读懂产品说明。

### 原则 2：角色是表达姿态，不是动物皮肤

每个角色都必须有：
- 内在动因；
- 说话方式；
- 可识别的人格；
- 与场景匹配的表达边界。

### 原则 3：Show, don't tell

不要在结果页告诉用户"这个角色适合你"。
要通过角色形象、名称、短语、quotes 和结果句，让用户自己感到"它懂"。

### 原则 4：避免触发用户防御心理

外显表达不能让用户觉得自己被诊断、被揭穿、被定义成负面人格。

避免：
- "你很脆弱"；
- "你不会社交"；
- "你就是懒"；
- "你很攻击"；
- "你需要被安慰"。

### 原则 5：不做情绪量化控制

不做：
- 语气 slider；
- 攻击程度；
- 疯癫程度；
- 温柔程度；
- 强弱档位。

结果页只保留"换个说法"。

### 原则 6：不超过 3 步生成结果

P0 主链路保持：

```text
选择状态/场景 → 选择嘴替/表达人格 → 生成结果页
```

不把平台选择、长测试、完整角色矩阵放进主链路。

## 4. P0 用户链路

### 4.1 四页结构

```text
P0 欢迎页  →  P1 选择场景  →  P2 选择嘴替  →  P3 结果页
```

### P0 欢迎页

- 产品介绍 / 引导进入
- 保持轻量，不做测试/多步选择
- 进入 CTA：单按钮到 P1

### P1 选择场景

- 展示 6 个场景（S1-S6）
- 字段：scene_title（例如"想把话轻轻带过"）+ scene_examples（例如"你咋了 / 不想解释 / 室友追问近况"）
- 用户选一个 → 进入 P2

### P2 选择嘴替

- 展示当前场景的 3 个角色选项（固定角色池，参见 §6）
- 每个选项展示：**角色名称 + 角色头像（profile 图）**
- 顺序：default role 置顶，backup 角色排后
- 用户选一个 → 进入 P3

### P3 结果页

- 结构见 §7（Block 1-6）

### 4.2 暂不把平台作为输入

P0 暂不让用户选择"朋友圈版 / QQ 版 / 小红书版"。

## 5. 五角色 final 定义

以下 A–E 角色名、物种、声线已锁定。

### A 嘴硬章鱼

- **role_id**：A
- **role_name**：嘴硬章鱼
- **物种**：章鱼
- **内在动因**：有状态，但不想承认，也不想解释。
- **用户感受**：嘴上没事，细节全在出卖。
- **个人资料**：八只手都在硬撑，嘴上永远没事。专业：永不承认，辅修：自我伪装。被关心时嘴上永远不承认，但心里其实希望被追问。最不擅长被人盯着看第二眼。
- **role_voice_principle**：嘴硬掩饰脆弱，渴望被关心但真实意图不明说
- **do**：先否认情绪 + 客观借口推卸 / 虚张声势的决绝；句末留一个出卖的小细节
- **don't**：直接说"我难过/我希望被关心"；自我揭示"其实我..."；卖惨
- **redline**：不能让用户看到 A 在求安慰；不能滑向脆弱诊断
- **default scene**：S1
- **backup scenes**：S2 / S5

### B 断电猫

- **role_id**：B
- **role_name**：断电猫
- **物种**：猫
- **内在动因**：不是不想理人，而是回应本身成为负担。
- **用户感受**：不是冷，是对话入口暂时关了。
- **个人资料**：长期处于"隐身"状态。专业：装没听见，辅修：配额管理。承认看到了消息，但回应这件事本身已经超出今日预算。不冷不傲不解释，不是不合群，是低能量人群。
- **role_voice_principle**：入口关闭/低能量；承认看见但行为或态度失能
- **do**：用系统/配额/状态/在线/低能量等技术化词描述自己关闭；承认接收
- **don't**：说"懒得理你/别烦我"；带怒气；把不接入解释成针对某个具体的人
- **redline**：不能冷暴力；不能高姿态
- **default scenes**：S2 / S5
- **backup scenes**：S1

### C 躺平树懒

- **role_id**：C
- **role_name**：躺平树懒
- **物种**：树懒
- **内在动因**：知道任务在那里，但启动不了。
- **用户感受**：任务在那，人也在这，中间没连上。
- **个人资料**：要做的事在那，它也在这，中间断线了。专业：慢，辅修：新建文件夹。最擅长凝视进度条，最不擅长启动；但对自己卡住这件事完全自知，不甩锅、不真摆烂。
- **role_voice_principle**：知道任务在但启动不了；保留自知，不真摆烂不甩锅
- **do**：用任务实操词反讽承认没动（文件夹/在写/明天/进度条）；保留自知动作
- **don't**：甩锅别人；说"我做不到"撂挑子；真摆烂式宣言
- **redline**：不能消极弃权；不能怪外部
- **default scene**：S3
- **backup scenes**：S4 / S6

### D 整活吗喽

- **role_id**：D
- **role_name**：整活吗喽
- **物种**：猴
- **内在动因**：认真解释太累，把状态变成一个怪但能懂的东西。
- **用户感受**：离谱但成立。
- **个人资料**：主见暂存中。专业：疯癫抽象，辅修：已读乱回。最擅长把任何问题升维成系统问题，最不擅长正常回答。问什么答什么但句句不对——离谱但能圆回来。
- **role_voice_principle**：现实回答失效，切到另一个解释系统（伪术语/伪逻辑/同字套娃/废话哲学）；离谱但成立
- **do**：用伪术语/伪学术/同字反复/废话哲学绕开正常回答
- **don't**：写正常解释；用病/症/崩溃/抑郁/疯字；胡言乱语到读不懂
- **redline**：不能精神疾病隐喻；不能完全没逻辑只为搞怪
- **default scene**：S4
- **backup scenes**：S1 / S3 / S6

### E 高情商刺猬

- **role_id**：E
- **role_name**：高情商刺猬
- **物种**：刺猬
- **内在动因**：不爽、不服、被安排或被冒犯，但不想亲自开怼。
- **用户感受**：有点不服，但不掀桌。
- **个人资料**：虽然没直说但你也能看到刺。专业：维护表面和平，辅修：听您的。最擅长让对方读到态度但抓不到把柄，最不擅长直接开怼。表面体面，里子有刺。
- **role_voice_principle**：有点不爽/不服/被冒犯，但不亲自开怼，4/10 刺感（对方读到态度但攻击不到把柄）
- **do**：表面体面 + 对仗反讽；让对方读到态度但抓不到把柄
- **don't**：指名道姓；爆料具体矛盾；阴阳怪气过重；用"低情商：xxx"显性攻击
- **redline**：不指人不爆料（PRD §5）；不论用何种 result_text 都不指向具体人
- **default scene**：S6
- **backup scenes**：S2 / S3 / S4 / S5

#### E voice boundary：「啊对对对」vs「好好好」

按**对象**区分，不按刺感强弱区分。

| 触发对象 | 用句 | 机制 | 对方读出 |
|---|---|---|---|
| 观点 / 说法 / 讲道理 / 催促话术 | 啊对对对 | 表面赞同观点 + 内心不耐烦 | 反讽对方能看出 |
| 事件 / 操作 / 局面 / 做了某事 | 好好好 | 表面接受事情 + 内心不爽 | 反讽对方能看出 |

S2·E "啊对对对" 特例：默认对应"被催回/被讲道理"的言论压力，不是泛指所有消息未回场景。

**S6·E "啊对对对！" 例外（DavidC 2026-05-12 22:59 拍板）**：
- S6 是"事件/局面"（这事离谱，但不想亲自开怼），按上表规则应使用"好好好"，但此场景 S6 E 默认 result_text 采用"啊对对对！"（带感叹号加强反讽力度）。
- 此为 DavidC 决策层拍板的 **规则例外**，不推翻本表总体区分原则。
- 后续如再写新 variants（S6 + 其他角色 + 其他场景），仍按上表区分，不类推扩用"啊对对对"到事件/局面对象。

## 7. 结果页结构（Block 1-6）

P3 结果页由 6 个 Block 组成。Block 1-4 + Block 6 是 **H5 页面里的动态展示**（前端渲染组件）。Block 5 是 **静态分享图**（前端 html2canvas 截图 / 后端生成 / 用户长按保存）。

### Block 1：嘴替结果展示区（H5 动态）

> H5 页面顶部的主展示区，用户在 H5 里看到的"主结果"。

展示：
- **角色形象**：使用 **单角色 PNG**（1080x1080，浅米底 #F9F7F3，从 contact sheet v10 裁剪，详见 §13）
- **角色名称**：参照文案 SoT（例如"嘴硬章鱼"/"断电猫"/"躺平树懒"/"整活吗喽"/"高情商刺猬"）
- **一句嘴替吐槽**：result_text（当前场景×角色的默认 variant，参见 §10）

不展示：
- 装饰元素（"硬撑"字 / 电池图标 / 进度条 / 弹窗 / 气泡等）——这些只出现在 contact sheet 全身写真里，单角色 PNG 裁剪时已剔除或弱化

### Block 2：嘴替 profile 介绍

> 角色卡。用户看完 Block 1 的结果，向下滚动看到"这是谁在替我说"。

展示（DavidC 23:32 final）：
- **角色形象**：使用 **profile 图**（1200x1200；profile 图按"头像"方式呈现——小图/圆形/方形/带框，自带 5 色背景作为视觉差异；DavidC 23:20 拍：profile 不影响整体页面背景）
- **角色名称**
- **风格短语**（style phrase，short phrase 7-12 字，取 §11.1 master）
- **3 条 master quote 并列展示**（从 §9 master quotes 取，usage=role_card；**DavidC 23:32：3 条并列展示作为"角色资料"的一部分**，不是选 1 条切换）
- **角色标签**（从 §11.2 取 1-2 个）

不展示：
- personality line（已删除，改用 quotes 替代）
- "它适合你" / "它适合这个场景"等诊断/解释式说明
- 过度说明式角色档案（个人资料是内部文案约束，不外显）

### Block 3：换个说法 CTA

> 同一场景、同一角色下，换一句吐槽表达。

交互：
- 点击后切换 result_text 到同一 {scene, role} 的另一 variant
- **不改变角色**、**不改变场景**、**不改变语气强度**
- 不做语气 slider / 攻击程度调节

### Block 4：换个嘴替 CTA

> 同一场景下换另一个嘴替。

展示该场景角色池里**除当前角色外**的另外 2 个角色。

每张 CTA 卡包含：
- **角色形象**：使用 **profile 图**（与 Block 2 一致）
- **角色名称**
- **风格短语**
- **quote preview**（从 §9 master/backup quotes 中 usage=preview 取）

用户点击后：
- 场景不变，角色池不变
- 当前角色切换为被点击角色
- 结果切回 Block 1，result_text 切换为该角色在当前场景下的默认 variant
- Block 4 继续展示同一角色池中剩下的两个角色

### Block 5：分享图（静态）

> **角色分享卡**。用户保存/分享用。含 result_text 与 Block 1 联动。

形式：**3:4 竖版图片**（建议 1080x1440 或 1200x1600）

**元素清单（DavidC 23:53 final v3）**：

| 元素 | 来源 | 说明 |
|---|---|---|
| **顶部标题** | 固定模板 | "心情值班室 · {角色名}"（产品名+角色专属，DavidC 21:57） |
| **角色形象** | 单角色 PNG（1080x1080 浅米底） | 与 Block 1 同一张 |
| **result_text** | 当前 variant.resultText（§10 取，与 Block 1 联动） | 前端叠加在底图预留位置（DavidC 23:53 新增）|

## 13. 视觉要求

### 13.1 从角色声线出发

设计不是先画动物再贴性格，而是先理解每个角色的表达姿态，再决定形象。

### 13.2 五个角色必须可区分

每个角色需要在以下层面有差异：
- 姿态；
- 表情；
- 轮廓；
- 视觉节奏；
- 和结果卡的关系。

### 13.3 不做刻板女性化

即使 TA 女性占比可能更高，也不应默认粉色、可爱、柔软、甜美。

### 13.4 世界资产质量统一

最终版不允许出现低质量贴图、CSS/emoji 占位、临时头像、与角色资产不在同一质量线的素材。

### 13.5 视觉方向

视觉 prompt 和风格探索在设计侧单独推进。当前方向共识：
- 画风：校园低保真手绘 / 粗糙 marker 墨线 / 简化动物造型；
- 色彩：干净底（不偏黄不黑底）+ 每角色一个高存在感"刺色"accent；
- 字体：图内不生成中文，前端叠字；
- 质感：不要 AI 软糖、不要治愈圆角、不要品牌精修 mascot；
- 角色 D 的抽象感来自环境（报错弹窗/系统 UI/飞溅），不靠解剖学变形。

具体 prompt 文本、色板 hex、试金石图在设计侧推进，不在本 PRD 中锁定。

换嘴替（Block 4）不独立成页，直接在 P3 内切换当前角色并刷新 Block 1 / Block 2 / Block 5。

### 14.3 结果页交互

- 换个说法（同角色同场景换 resultText）；
- 换个嘴替帮你说（同场景角色池内切角色）；
- 保存分享图；
- 复制配文；
- 重选状态。

### 14.4 底图无字 + 前端叠字

AI 生图不生成中文，不烧文字。文案池需要可换、AB 测试需要可控、前端叠字更稳定。角色名、style phrase、quotes、result_text 全部由前端 overlay 渲染。

## 16. 成功标准

### 16.1 产品判断标准

用户应能理解：
- 我选了什么状态；
- 当前是谁在替我说；
- 这个嘴替是什么性格；
- 这句话为什么像我会说的话；
- 我为什么想换另一个嘴替看看。

### 16.2 行为指标候选

- 结果生成完成率；
- 结果页换嘴替点击率；
- 换个说法点击率；
- 保存/复制/分享率；
- 重复生成率。

### 16.3 小样本测试标准

用户测试中希望听到：
- "这个角色像我/像我朋友"；
- "这句我可能会发/会存"；
- "我知道为什么想换另一个嘴替"；
- "没有觉得它在骂我/诊断我/教育我"。

---

## 17. P0 不做范围

- 平台专门适配流程；
- 抖音/视频/动效模板；
- 每个场景开放全 5 角色；
- 语气 slider 或强弱量化；
- 真实低落/需要安慰的严肃情绪；
- 严肃关系冲突、道歉、修复；
- 宿舍/小组矛盾具体爆料；
- 在未确认方向前锁最终视觉 prompt。
