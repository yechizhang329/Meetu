**核心改动**：从“状态卡生成器”升级为“具象角色替用户发声”。

## 0. 这次重构的起点

Jonathan 的关键判断：

> 朋友抽象成一个具象个体。朋友不是一个好的选择。排版小动物里每个动物是帮你写文案的，有个具象被喜欢的个体承接这些情绪发泄，有利于用户获得归属感和心理安慰从而建立依赖。

DavidC 的补充：

> 朋友锐评应该出现在用户分享图片后的评论区，而不是在展示结果的图片上。可以把不同场景、语气或对话风格人格化。

这两点改变产品核心：

- 原方向：用户选场景/状态/语气 → 生成状态卡 → 朋友锐评写在卡上。
- 新方向：用户选一个具象小角色 → 小角色替用户发声 → 用户分享后，评论区/群聊里的真人来锐评。

产品不再是“生成一张完整表达卡”，而是：

> 给用户一个可爱/抽象/嘴硬/发疯的具象代理人，让它替用户说出今天说不出口的话，并留下让别人接话的空间。

### 1.3 评论区信号

评论区里最关键的不是“好准”，而是四种动作：

1. **求这个角色/图/文案**  
   如“求”“来”“我我我”“这种文案大量求”。说明用户不是只看内容，而是想拿走一个表达工具。

2. **把角色当熟人称呼**  
   如“宝宝狗”“这狗”“我跟狗才是真玩”。说明具象角色会被用户拟人化，产生轻陪伴感。

3. **补梗/续写**  
   发疯文学评论区会继续贡献谐音梗和抽象回复。说明产品可以把评论区留给用户共创，而不是把所有锐评写死在图上。

4. **报答案/报类型**  
   SBTI/人格测试评论区大量报选项、报结果、互相求链接。说明“角色结果”天然适合接龙。

## 2. 心理机制：为什么“具象个体”比“朋友”更好

### 2.1 朋友太真实，角色更安全

“朋友锐评”如果直接写在图上，会有两个问题：

1. 用户会觉得被评价，防御心变强；
2. 分享出去后朋友没话说，因为图已经替朋友说完了。

具象小角色更好，因为它是第三方外壳：

> 不是我在抱怨，是这只小东西今天替我说话。

用户可以保留可否认性：

- “我只是发个小动物”；
- “不是我矫情，是它这样写的”；
- “像不像你们自己说”。

### 2.2 角色承接情绪，比文字更能形成依赖

纯文案解决一次表达；角色可以形成长期关系。

因为角色具备：

- 可记忆：用户能记住“那只总是嘴硬的鹅/猫/鼠”；
- 可投射：用户会把自己状态放到角色身上；
- 可陪伴：角色每日出现，像一个小小的固定对象；
- 可收集：不同角色/不同状态可形成卡册；
- 可社交：朋友可以说“今天你又是这只”。

这比“状态卡模板”更接近成瘾机制：

> 用户不是每天来生成一张图，而是每天来看看“我的那只小东西今天怎么替我说话”。

### 2.3 评论区锐评应该由真人完成

分享图上的内容要负责两件事：

1. 让用户愿意发；
2. 让别人有话回。

所以图上不应把“朋友锐评”写满。它应该留下空位：

- `请评论区补充说明。`
- `像谁，谁自己认。`
- `今天由它替我发言。`
- `本人暂不解释。`

朋友锐评应发生在图后：

- 群聊里朋友说“这不就是你”；
- 评论区有人补刀；
- 室友拿图改备注；
- 对桌说“你今天确实这个”。

产品要生成的是“评论区触发器”，不是“完整闭环文案”。

## 3. 产品定义

### 3.1 一句话定义

内部定义：

> 一个“具象情绪代理人”产品：用户选择一个小角色，让它替自己说出今天的状态，再生成一张适合发出去引发接话的图。

用户感知：

> 找一只今天替我说话的小东西。

更有梗版本：

> 今天不想自己解释，让它替我发言。

### 3.2 它不是

- 朋友圈文案生成器；
- AI 聊天伴侣；
- 正经心理测试；
- MBTI 说明书；
- 自介卡编辑器；
- 单纯表情包库。

### 3.3 它是

> 文案嘴替 + 情绪小宠物 + 状态卡生成器 + 评论区触发器。

核心价值不是“图好看”，而是：

1. 帮用户把情绪交给一个具象角色；
2. 降低用户表达自己的心理风险；
3. 让分享后别人能接话；
4. 让用户因为角色关系和日更状态回来。

## 4. Target Audience

核心用户：

> 有表达欲、分享欲，但不想高压、直白、像广告一样表达自己的大学生。

更具体：

| 用户类型 | 特点 | 为什么需要这个产品 |
|---|---|---|
| 嘴硬型 | 想被看见但不想承认 | 需要一个角色替自己说话 |
| 慢热型 | 不主动表达，但希望朋友懂 | 用图降低开口成本 |
| 发疯型 | 喜欢抽象梗和精神状态表达 | 需要新鲜、可转发的语言弹药 |
| 敏感型 | 感受很多，不知道怎么说 | 需要低压、非鸡汤的表达方式 |
| 群聊型 | 喜欢发图让朋友接话 | 需要能触发回复的内容对象 |
| 收集型 | 爱存图、状态图、表情包 | 需要角色/卡册/每日更新 |

## 5. 核心产品结构

### 5.1 从“选状态”改成“选角色”

旧流程：

```text
选场景 → 选状态 → 选语气 → 生成卡
```

新流程：

```text
今天谁替你说话？ → 它今天怎么了？ → 生成可分享卡
```

### 5.2 P0 角色人格

P0 不要上来做 16 个角色。先做 6 个足够鲜明的“文案代理人”。

| 角色 | 人格功能 | 负责场景 | 说话方式 |
|---|---|---|---|
| 嘴硬鹅 | 明明被说中但死不承认 | 朋友圈/群聊/合照/社交 | “我没有，只是稍微……” |
| 省电猫 | 低电量、懒得解释 | 早八/社交后/周末 | “人在，电不在。” |
| 发疯鸡 | 抽象、乱回、破防 | 已读乱回/上课/期末 | 谐音梗、短句、发疯文学 |
| 结界鼠 | 需要私人空间 | 宿舍/室友/边界 | 小声但有边界 |
| 过载羊驼 | 脑内弹幕很多 | crush/聊天/DDL | “表面正常，后台爆炸。” |
| 主理犬 | 热心但怕负责 | 群聊/组局/约饭 | “我可以帮，但别把我变负责人。” |

这 6 个不是动物测试结果，而是工具里的“替你发言的人”。用户会逐渐形成偏好：

- “我今天找省电猫”；
- “这事只能让发疯鸡说”；
- “我室友是结界鼠本鼠”。

### 5.3 P0 状态池

每个角色下挂 6-10 个状态，不必全局通用。

| 状态 | 可挂角色 |
|---|---|
| 开机失败 | 省电猫 / 发疯鸡 |
| 在线装死 | 省电猫 / 嘴硬鹅 |
| 今日过载 | 过载羊驼 |
| 结界不足 | 结界鼠 |
| 不想负责 | 主理犬 / 嘴硬鹅 |
| 已读乱回 | 发疯鸡 / 过载羊驼 |
| 想去但懒 | 省电猫 / 嘴硬鹅 |
| 需要朋友捞一下 | 结界鼠 / 省电猫 |
| 被安排过敏 | 嘴硬鹅 / 发疯鸡 |
| 表面正常 | 过载羊驼 / 嘴硬鹅 |

### 5.4 P0 输出卡结构

注意：分享图不写“朋友锐评”。

卡上写：

1. **角色名**：今天替你说话的是谁；
2. **角色声明**：它替你说的一句话；
3. **状态牌**：短标签，便于朋友评论；
4. **留白钩子**：引导别人补充/认领。

示例结构：

```text
今日代言：省电猫

人在。
但请不要让我营业。

状态：低电量社交中

评论区请勿拆穿。
```

图外/评论区发生：

```text
朋友：这不就是你？
朋友：你昨天也是这只。
朋友：我宣布你常驻省电猫。
```

## 6. 用户链路

### 6.1 P0 链路

```text
入口页
  ↓
选一个今天替你说话的小角色
  ↓
选它今天的状态
  ↓
生成 3 张卡
  ↓
用户保存/发群/发朋友圈/设微信状态
  ↓
朋友在评论区/群聊补刀或认领
  ↓
用户回到产品给朋友也生成一张 / 换一个角色
```

### 6.2 关键 friction 控制

不能让用户先想清楚“目的、偏好、边界”。那太重。

P0 只问两件事：

1. **今天谁替你说话？** 角色选择，本身有趣；
2. **它今天怎么了？** 状态选择，低认知负担。

可选第三步：

3. **发哪儿？** 群聊 / 朋友圈 / 微信状态。

不同出口对应不同版式和文案强度。

### 6.3 依赖机制

| 机制 | 如何形成依赖 |
|---|---|
| 角色偏好 | 用户会形成“我的默认嘴替” |
| 每日状态 | 每天状态不同，天然复访 |
| 卡册收集 | 用户保存自己生成过的角色卡 |
| 朋友互相贴标签 | 朋友说“你今天又省电猫了” |
| 评论区补刀 | 外部反馈成为奖励 |
| 给朋友生成 | 从自用扩散到社交关系 |

## 7. MVP 范围

### 7.1 P0 做什么

- 6 个具象角色；
- 每个角色 6-8 个状态；
- 每个状态 4-6 条角色口吻文案；
- 3 个输出用途：发群、朋友圈、微信状态；
- 每次生成 3 张候选；
- 保存图片；
- 换一句；
- 给朋友也生成一张；
- 无登录；
- 无 AI 实时生成；
- 无公开广场。

内容规模：

```text
6 角色 × 8 状态 × 5 文案 = 240 条核心文案
再加 3 种用途版式与少量钩子句
```

这个比“7场景×16状态×4语气”更轻，而且更有记忆点。

### 7.2 P0 不做什么

- 不做复杂编辑器；
- 不做 AI 自由对话；
- 不做心理诊断；
- 不做朋友匿名评价系统；
- 不做公开榜单；
- 不做强社交匹配；
- 不把朋友锐评写死在图上。

## 9. 视觉方向

视觉不应是“统一模板套文案”，而是每个角色有稳定识别点。

| 角色 | 视觉关键词 |
|---|---|
| 省电猫 | 电量格、趴着、眼神下线、蓝灰低饱和 |
| 嘴硬鹅 | 仰头、嘴硬表情、白底黑线、黄色贴纸 |
| 发疯鸡 | 爪子乱飞、短句弹幕、红章/警告感 |
| 结界鼠 | 小洞/边界线/勿扰牌、低声量灰米色 |
| 过载羊驼 | 脑袋旁弹幕云、表面平静、内部爆炸 |
| 主理犬 | 举手、流程板、想帮又后悔、橙色热心感 |

视觉机制：

- 角色负责记忆；
- 文案负责代言；
- 空白负责评论；
- 卡面不要太满。

## 10. 商业化与 Meetu 关系

这件事本身不直接收费。它作为 Meetu 的前置触点：

1. 高频触达：用户每天都能生成状态；
2. 传播入口：卡片自然进群聊/朋友圈/小红书；
3. 需求识别：用户选择的角色/状态能反映真实场景需求；
4. 场景承接：当用户频繁选择“周末空心/想被约但不主动/需要朋友捞一下”，可承接到 Meetu 的低压小局/搭子场景。

商业价值不来自单张图，而来自：

> 它能低成本捕捉用户此刻的社交状态，并把 Meetu 放进用户真实表达链路里。

## 11. 风险与修正

### 11.1 风险：变成普通表情包库

修正：角色必须能“替用户说话”，不是只可爱。

### 11.2 风险：变成心理测试

修正：不说精准人格，不做诊断，只说“今天谁替你说话”。

### 11.3 风险：卡片把话说满，朋友没法接

修正：图上不写朋友锐评，保留评论区锐评空间。
