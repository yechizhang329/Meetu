# 心情值班室 PRD v0.9｜嘴替修订版

> 状态：基于 v0.8 final 的修订稿。方向不变：具象情绪代理人 / 心情值班室。修订重点：把核心从“像我/符合心情”校准为“嘴替”，并解决旧执行里的缝合感、死气沉沉、产品边界过强和分享欲不足问题。

---

## 0. 本版结论

### 0.1 不换方向

保留 v0.8 的主结构：

- 产品名：心情值班室；
- 角色体系：具象情绪代理人；
- P0 4 角色：嘴硬鹅 / 低电量猫 / DDL 仓鼠 / 后台羊驼；
- 链路：轻选择 → 推荐今日嘴替 → 生成可分享状态图；
- 生图：用于资产生产，不进入用户运行时；
- 多 agent 协作：Lucy 文案、Phoebe 视觉、Dave 工程。

不再切到“社交天气 / 状态纸条 / Meetu 小局入口”。这些是偏航。

### 0.2 核心校准

旧表达：

> 这很像我 / 这很符合我心情。

新版核心：

> **这只嘴替把我不想说的话说了。**

用户的分享心理不是单纯“认领”，而是：

- 我不好意思直接说；
- 它替我说了；
- 我可以嘴硬说“不关我事”；
- 朋友看懂了可以来补刀。

### 0.3 本版第一原则

> **心情值班室不是测试我是谁，而是派一个具象角色替我开口。**

MVP 的约束不是“只能用某一种实现手段”，而是：

```text
限制 scope，不限制合理手段；控制成本，但不能做出廉价感。
```

因此 P0 不是样张合集，也不是只做 4 张 demo 图。P0 必须是完整系统的最小版本：核心角色体系、核心使用场景、文案池、生成链路、保存/分享链路、运营首发路径都要成立。

成本控制收的是资产深度、交互复杂度和实现精度，不收核心场景覆盖。先用 4 张强嘴替输出图建立质量标杆，但后续 H5 必须覆盖用户高频使用场景。

## 1. 产品定义

### 1.1 一句话定义

**心情值班室**是一套高频、低压、可分享的嘴替 H5：用户通过轻选择叫出今天在自己身体里值班的情绪代理人，让它替自己说一句不方便直接说的话，并生成一张可以发朋友圈/小红书/群聊的状态图。

### 1.2 用户感知

用户不应该觉得：

```text
我在做测试。
```

```text
我在用 AI 生成图片。
```

```text
产品给我总结了一张结果卡。
```

用户应该觉得：

```text
这句话我不想自己说，让它说。
```

```text
我发的是它，不是我。
```

```text
朋友要说像我，那是他们说的。
```

### 1.3 产品本质

不是：

- 人格测试；
- 情绪诊断；
- AI 图片工具；
- 泛状态卡；
- 小动物 IP 图鉴；
- Meetu 小局入口。

而是：

> 具象嘴替系统。

---

## 2. 用户与真实需求

### 2.1 用户为什么需要嘴替

目标用户有表达欲，但直接表达有压力：

- 直接说“我累了”太像求关心；
- 直接说“别催我”太攻击；
- 直接说“我不想去”太不给面子；
- 直接说“我被说中了”太丢脸；
- 直接说“我崩了”太沉重。

嘴替的价值是把这些话变成：

```text
不是我说的，是它今天值班。
```

### 2.2 用户为什么会分享

用户会发出去，不是因为图“好看”，而是因为图给了她 3 层保护：

1. **表达保护**：它替我说；
2. **否认保护**：我可以说“我没有”；
3. **互动保护**：朋友可以接梗，不需要严肃关心。

### 2.3 用户为什么会回来

每天都有不一样的“想说但不想自己说”：

- 今天不想营业；
- 今天嘴硬；
- 今天 DDL 追我；
- 今天后台炸了；
- 明天可能又换一只。

复用点不是“每天测我是谁”，而是：

> 今天派谁替我说话。

---

## 3. 母世界观

### 3.1 世界观一句话

> 你的身体里有一间很小的心情值班室。每天会有一只动物出来替你说一句你不想自己说的话。

### 3.2 为什么还是“值班室”

“值班室”有用，因为它提供了一个轻借口：

- 今天不是我本人营业；
- 今天是某只动物值班；
- 有话让值班的说；
- 我可以不用负责到底。

但注意：值班室不是办公室设定集。

不能把产品做成：

- 公司组织架构；
- 岗位牌堆叠；
- 完整办公室场景；
- SaaS 后台界面。

值班室只是嘴替出场的轻世界观。

### 3.3 统一性原则

统一不是“所有东西都像办公”。

统一应该是：

- 角色都像同一世界里的情绪代理人；
- 画风一致；
- 文案都像“它替我说”；
- 输出图都像能被用户直接发出去；
- 产品痕迹都轻。

## 4. P0 角色

P0 保留 4 个角色，不扩散。

| 角色 | 嘴替职责 | 用户不想直接说的话 | 它替用户说 |
|---|---|---|---|
| 低电量猫 | 替用户拒绝营业 | 我累了、别叫我、别让我决定 | “人在，电不在。” |
| 嘴硬鹅 | 替用户否认被说中 | 你说得对，但我不承认 | “我没有。” |
| DDL 仓鼠 | 替用户拖延和自救 | 我拖了，但别催 | “会做的，不是现在。” |
| 后台羊驼 | 替用户维持体面 | 我表面正常，里面已经炸了 | “表面好的，后台炸的。” |

### 4.1 角色不能只是可爱

每个角色必须有：

- 一句稳定嘴替口头禅；
- 一个可识别姿态；
- 一个朋友能接的评论点；
- 一个用户会重复使用的场景。

### 4.2 P1 不急着扩

勿扰刺猬、被窝水豚、夜班猫头鹰等先放 P1。

P0 先把 4 个角色做深、做活、做统一。

## 5. 输出图

### 5.1 输出图定位

输出图不是测试结果。

它是：

> 一张“今天它替我说”的可分享图。

用户发出去时的心理：

```text
我没说，是它说的。
```

朋友看到后的反应：

```text
别装，这就是你。
```

### 5.2 输出图结构

每张图只保留 4 个层级：

1. 角色状态图；
2. 嘴替句；
3. 极轻产品名/落款；
4. 可选的保存/分享配文，不烧进图里。

不放进图里：

- 朋友锐评；
- 人格标签；
- 大 logo；
- 诊断文案；
- 分数/雷达图；
- “朋友鉴定区”框；
- 一堆短标签。

### 5.2.1 输出图生产原则：先整体成图，再决定技术层

输出图不能以“HTML 组件拼接完成”为默认目标。

用户看到的最终图必须像一张完整的嘴替图，而不是：

```text
前端把背景、角色、标签、按钮、文字框拼在一起。
```

P0 采用三档生产策略：

| 方案 | 用途 | 优点 | 风险 |
|---|---|---|---|
| Image2 带文字整图 | 固定首发爆点图 / 运营海报 / 少量强传播样张 | 整体感最好，最不像产品拼接 | 改字和批量化成本高，中文字稳定性需逐张验 |
| Image2 无字大背景 + H5 叠字 | P0 主路径 | 画面整体性好，文案可换，成本可控 | 前端叠字若处理不好仍会有拼接感 |
| 纯 HTML/CSS 拼图 | 兜底 / 原型 / 内部调试 | 快、便宜、可控 | 最容易像产品卡片，不作为最终审美目标 |

默认不是“能用 HTML 做就不用 Image2”。默认是：

> 哪种方式最能让用户愿意直接发出去，同时成本可控，就用哪种。

验收时必须看最终导出的图，而不是看 H5 页面组件。

### 5.2.2 内容覆盖原则：不能因成本牺牲核心场景

MVP 可以减少图的数量，但不能减少用户真正会用的嘴替场景。

P0 至少覆盖 8 类核心使用场景：

1. 嘴硬否认：被说中但不想承认；
2. 低电量拒绝营业：人还在，但不想说话/不想动；
3. DDL / 拖延：会做，但不是现在；
4. 表面正常后台崩：嘴上好的，内心拒绝新增输入；
5. 想安静 / 勿扰：不想被靠近、不想被追问；
6. 被约出门 / 不想动：朋友约了，但床和身体不同意；
7. 消息不想回：不是不理你，是这会儿不想开口；
8. 被安排 / 被催：外界推着走，但本人想把话甩给代理人。

每类场景都必须至少有 3-5 条可发嘴替句，且至少能映射到一个 P0 角色。

视觉资产可以复用：同一角色主图可以承载多句嘴替；但内容不能空。验收时要检查“用户今天遇到一个常见尴尬/拒绝/拖延/崩溃时刻，是否能在系统里找到一句能发的话”。

### 5.3 朋友锐评机制

朋友锐评应该发生在用户发图之后。

产品只提供“可接话”的嘴替句，不在图里预写评论区。

例如：

```text
我没有。
```

朋友自然会接：

```text
你有。
```

这比图上写“朋友鉴定区：____”更自然。

### 5.4 P0 输出 demo

#### 嘴硬鹅

```text

```

复制配文：

```text

```

评论钩子：

```text

```

#### 低电量猫

图上文案：

```text

电不在。
```

复制配文：

```text

```

评论钩子：

```text

```

#### DDL 仓鼠

图上文案：

```text

不是现在。
```

复制配文：

```text

```

评论钩子：

```text

```

#### 后台羊驼

图上文案：

```text

后台：别再开窗口了。
```

复制配文：

```text

```

评论钩子：

```text
朋友会说：你后台一直没关过。
```

## 6. 设计语言

### 6.1 目标

设计要让用户觉得：

```text
这张图可以直接发。
```

不是：

```text
这是一张产品海报。
```

### 6.2 外部案例怎么学

排版小动物给我们的不是纸条外壳，而是：

- 整体性；
- 减法；
- 产品边界弱；
- 小角色服务表达。

Loopy / Chiikawa / Capoo 给我们的不是画风，而是：

- 角色有缺陷；
- 角色能被用户借用；
- 角色不替品牌卖萌；
- 用户愿意用它表达狼狈。

网易云/Spotify 给我们的不是音乐卡，而是：

- 第三方替我说；
- 品牌后退；
- 输出像“我的状态”。

### 6.3 我们自己的风格

心情值班室应该是：

> 年轻、鲜活、有一点荒诞、但不吵的情绪角色世界。

不是：

- 米色 SaaS；
- 卡通幼儿园；
- 真实办公室；
- 复杂海报；
- AI 插画作品集。

### 6.4 视觉硬规则

- 角色是视觉主角，但不是产品 mascot；
- 每张图只有一个状态动作；
- 道具最多 1-2 个；
- 不画完整办公室；
- 不做证书/结果卡/报告；
- 色调要更年轻鲜活，但必须统一；
- 品牌露出极轻。

### 6.5 UI 硬规则

H5 页面不能像问卷，也不能像 SaaS。

应该像：

- 用户在“叫一只出来”；
- 页面本身有角色存在；
- 每一步都轻、短、有反馈；
- 结果页突出“它替我说”，不是“你的结果是”。

## 7. H5 链路

### 7.1 链路原则

少问，快出嘴替。

用户不是来回答测试，而是来叫今天的嘴替。

### 7.2 首页

主标题：

```text
今天派谁出来替你说话？
```

副文：

```text
选一下今天的状态，让值班动物替你开口。
```

CTA：

```text
叫一只出来
```

### 7.3 Step 1：今天发生了什么

P0 选项：

1. 人在，电不在；
2. 被说中了，但我不认；
3. DDL 在追我；
4. 表面正常，后台很吵；
5. 想出门，但启动失败；
6. 想安静一点，别太靠近。

### 7.4 Step 2：今天想怎么嘴硬

P0 选项：

1. 直接否认；
2. 装作没事；
3. 礼貌勿扰；
4. 摆烂承认一半。

### 7.5 结果页

结果页主句：

```text
今天先让它替你说。
```

结构：

- 今日嘴替角色；
- 主状态图；
- 3 句可换嘴替句；
- 保存图；
- 换一句；
- 复制配文。

不要：

- 长结果分析；
- 朋友鉴定区框；
- 标签堆叠；
- “你是 xx 型”；
- 大量按钮。

## 8. 文案规则

### 8.1 文案的本质

文案不是“描述我”。

文案是：

> 它替我说一句我不好意思说的话。

### 8.2 好文案长什么样

好文案：

- 短；
- 像人话；
- 有否认权；
- 有一点嘴硬；
- 朋友能接；
- 不是完整解释。

### 8.3 坏文案长什么样

坏文案：

- 像运营写的；
- 像金句；
- 押韵；
- 太聪明；
- 太完整；
- 像人格测试结果。

### 8.4 文案池修订

旧 96 条不直接废，但不能作为 final。

处理方式：

- 保留角色 × 场景结构；
- 每条改写成“嘴替句”；
- 删除标签感和总结感；
- 先交每角色 8 条给 PM 验 taste，再扩展到完整文案池。

## 9. 生图和资产

### 9.1 生图通道角色

生图用于生产资产，不进入用户实时路径。

P0：预生成嘴替输出图、无字大背景、角色图、状态图、表情变体。

Image2 不只是“画角色素材”的工具，也可以用于生产更完整的图文背景。是否带文字由单张图的用途决定：

- 固定首发图：可以尝试 Image2 带文字整图，但必须逐字验收；
- H5 可变输出：优先 Image2 无字大背景 + 前端叠字；
- 内部原型：允许纯 HTML/CSS，但不能把原型质感当 final。

实现手段不做教条限制。每张输出图允许在以下方案中选择最合适的一种或组合：

- Image2 带文字整图；
- Image2 无字背景 + H5 文字层；
- 局部 Image2 资产 + 前端排版；
- 少量 HTML/CSS 原生绘制。

选择标准不是“哪种技术更酷”，而是：

1. 最终图是否像用户会发；
2. 是否有拼接/模板/廉价小程序感；
3. 单次修改成本是否可控；
4. P0 是否能以完整系统的最小版本交付。

### 9.2 出图流程

所有出图前必须先审 prompt。

每批包含：

- style header；
- 单图 prompt；
- negative；
- call 数；
- 本批验证问题。

每批 prompt 还必须说明：

- 本图是“带文字整图”还是“无字背景 + H5 叠字”；
- 如果前端叠字，文字位如何融入画面，避免贴片感；
- 本批 call 数上限；
- 失败时是否允许 retry，不能默认无限重跑。

成本控制规则：

- 成本控制是生产方法优化，不是产品质量打折；
- 每批出图前先给 prompt 审稿，不先跑后解释；
- 每批明确 call 上限和 retry 上限；
- 优先考虑多图一 call / contact sheet / 角色变体合图，再本地 crop 成单图资产；
- 同一角色的表情、动作、道具变体尽量合批生成，减少 call 次数；
- 每次出图任务必须写清：一 call 产几张、怎么裁、哪些能复用、失败怎么处理；
- 先做 1-4 张试金石，不直接批量扩；
- 若方向不对，先回到产品/视觉判断，不用更多 call 硬修；
- 若纯前端可达到同等效果，优先省 call；若纯前端明显廉价，则使用 Image2 提升整体性。

### 9.3 P0 资产

每个角色：

- 1 张主形象；
- 1 张主状态图；
- 2 张状态变体；
- 1 个小图标/道具。

4 角色共 16-20 张图。

先做 4 张核心输出图，通过后再扩资产。

## 10. 验收标准

每张输出图必须过 8 问：

1. 它是不是嘴替，而不是测试结果？
2. 用户会不会愿意发？
3. 文案像不像用户想说但不好意思说的话？
4. 朋友能不能自然接话？
5. 角色有没有记忆点？
6. 画面有没有产品广告感？
7. 4 张图是不是同一个世界？
8. 如果去掉 Meetu，用户还会不会觉得这张图成立？

不过即打回。

---

## 11. P0 顺序

### Phase 1：先做输出图

先做 4 张：

1. 嘴硬鹅；
2. 低电量猫；
3. DDL 仓鼠；
4. 后台羊驼。

不先做完整 H5。

### Phase 2：再做 H5 MVP

输出图通过后，再做：

- 首页；
- 2 个轻选择；
- 结果页；
- 保存 / 换一句 / 复制配文。

### Phase 3：运营首发
