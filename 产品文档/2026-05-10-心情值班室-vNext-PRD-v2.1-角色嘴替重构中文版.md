## 0. 本版更新重点

这版 PRD 基于 DavidC 对当前“心情值班室 v1.0/v1.2”的产品反馈重构，核心变化是：

1. **从“动物皮肤 + 场景文案”转为“用户认同的人格化嘴替”**  
   角色不是装饰，也不是换颜色；角色代表不同的表达姿态和社交处理方式。

2. **从“简单嘴替工具”转为“让用户觉得这像我/像我会说的话，但由它替我说”**  
   目标不是替用户生成一句漂亮话，而是让用户产生认同和低风险表达。

3. **从“结果页随便换动物”转为“每个场景固定 3 个合适嘴替”**  
   用户在同一个状态/场景下，可以换另外两个合适的嘴替看看，但不开放全角色乱切。

4. **从“调整语气 slider”转为“换个说法”**  
   不做语气强弱、攻击程度、疯癫程度等可量化控制，避免用户对情绪进行打分式操作。

5. **从“角色说明”转为“角色名称 + 角色声线 + quotes”**  
   不手把手解释“这个角色适合你”，而是让角色自己有个性，用户自行代入。

当前线上版本不立即修改。本 PRD 是 vNext 的产品源文档，用于后续文案、设计、工程拆解。

## 1. 产品一句话

心情值班室是一个面向在校学生的轻量 H5：用户选择一个当下状态，再选择一个“嘴替人格”替自己表达，生成一张可以保存或分享的状态图；用户可以在结果页“换个说法”，也可以在同一场景下换另一个嘴替看看。

产品要让用户感觉：

> “这很像我。”  
> “这句话我不想自己说，但它替我说了。”

---

## 2. 用户与问题

### 2.1 目标用户

P0 目标用户是高社交密度的在校大学生。

典型环境：
- 宿舍；
- 班级；
- 小组作业；
- 社团/学生组织；
- 课程/早八/期末；
- 消息、群聊、朋友圈/QQ 空间/小红书等表达场景。

用户画像倾向：
- 年龄主要在 18–22 岁；
- 女性用户可能更容易早期采用，但产品和视觉不能刻板“女性化”；
- 对社交表达、梗图、情绪卡片、状态分享有较高接受度；
- 会在表达前考虑“别人怎么看”“会不会被追问”“会不会显得我太严重/太刻薄/太脆弱”。

### 2.2 核心问题

用户不是简单“不会说话”，而是很多时候**不想亲自承担这句话的表达成本**。

常见表达成本包括：
- 说太认真，会显得自己状态很严重；
- 说太直接，会引发冲突或让别人不舒服；
- 不说，又可能被误解；
- 回复消息，会被拖进更多对话；
- 吐槽某件事，会显得自己不好相处；
- 解释情绪，会显得暴露或麻烦。

### 2.3 产品机会

“嘴替角色”可以成为表达缓冲层：
- 它替用户承担一部分语气责任；
- 它让表达从“我本人说”变成“这个角色替我说”；
- 它让情绪变成可保存、可分享、可共鸣的对象；
- 它既像用户，又和用户保持一点距离。

## 3. 产品原则

### 原则 1：先让用户认同，再解释功能

用户首先要感觉“这像我/像我会说的话”，而不是先读懂产品说明。

### 原则 2：角色是表达姿态，不是动物皮肤

每个角色都必须有：
- 内在动因；
- 说话方式；
- 可识别的人格；
- 与场景匹配的表达边界。

### 原则 3：Show, don't tell

不要在结果页告诉用户“这个角色适合你”。  
要通过角色形象、名称、短语、quotes 和结果句，让用户自己感到“它懂”。

### 原则 4：避免触发用户防御心理

外显表达不能让用户觉得自己被诊断、被揭穿、被定义成负面人格。

避免：
- “你很脆弱”；
- “你不会社交”；
- “你就是懒”；
- “你很攻击”；
- “你需要被安慰”。

### 原则 5：不做情绪量化控制

不做：
- 语气 slider；
- 攻击程度；
- 疯癫程度；
- 温柔程度；
- 强弱档位。

结果页只保留“换个说法”。

### 原则 6：不超过 3 步生成结果

P0 主链路保持：

```text
选择状态/场景 → 选择嘴替/表达人格 → 生成结果页
```

不把平台选择、长测试、完整角色矩阵放进主链路。

---

## 4. P0 用户链路

### 4.1 主链路

1. **选择状态/场景**  
   用户选择“现在发生了什么/我处在什么状态”。

2. **选择嘴替/表达人格**  
   用户选择一个像自己会采用的表达姿态。

3. **生成结果页**  
   系统生成结果图，并展示当前嘴替角色卡、换个说法、换个嘴替帮你说等操作。

### 4.2 结果页操作

结果页包含：
1. 结果图；
2. 当前嘴替角色卡；
3. 换个说法；
4. 换个嘴替帮你说；
5. 保存 / 复制配文 / 重选状态。

### 4.3 暂不把平台作为输入

P0 暂不让用户选择“朋友圈版 / QQ 版 / 小红书版”。

原因：
- 分享平台是用户心里的隐含变量，不适合变成显式步骤；
- 显式平台选择会拉长链路；
- 当前先验证“角色嘴替 + 状态表达”是否成立。

## 5. 五类嘴替角色

以下 A-E 是内部角色类型，不是最终角色名。

### A｜嘴硬漏风型

**内在动因**：有状态，但不想承认，也不想解释。  
**用户感受**：嘴上没事，细节全在出卖。  
**表达方式**：嘴硬、收着、装没事、轻微破绽。  
**适合处理**：被问状态、想轻轻带过、想被懂一点但不展开。  
**避免**：卖惨、求安慰、把用户说成脆弱。

### B｜离线挡门型

**内在动因**：不是不想理人，而是回应本身成为负担。  
**用户感受**：不是冷，是对话入口暂时关了。  
**表达方式**：离线、勿扰、接不动、先缓缓。  
**适合处理**：消息看见了但不想/不知道怎么回，社交电量不足，不想被拉进互动。  
**避免**：冷暴力、高姿态、懒得理你。

### C｜加载未启动型

**内在动因**：知道任务在那里，但启动不了。  
**用户感受**：任务在那，人也在这，中间没连上。  
**表达方式**：加载中、未启动、进度条没动、有自知的装死。  
**适合处理**：DDL、作业、论文、被催、任务还没开始。  
**避免**：真摆烂、甩锅、不负责。

### D｜抽象发疯型

**内在动因**：认真解释太累，把状态变成一个怪但能懂的东西。  
**用户感受**：离谱但成立。  
**表达方式**：抽象、发疯、玩梗、精神跑偏但可读。  
**适合处理**：校园日常突然离谱、早八、期末、荒诞小事、想把严肃感打散。  
**避免**：随机胡言、精神疾病隐喻、完全看不懂。

### E｜轻刺反骨型

**内在动因**：不爽、不服、被安排或被冒犯，但不想亲自开怼。  
**用户感受**：有点不服，但不掀桌。  
**表达方式**：轻刺、反骨、体面、有分寸。  
**适合处理**：小组作业不公、被安排、被催、事情离谱但不能撕破脸。  
**避免**：人身攻击、阴阳怪气过重、具体矛盾爆料。

## 6. P0 场景与角色池

P0 不做 6×5 全矩阵。每个场景固定 3 个合适嘴替，总计 18 个有效组合。

| 场景 | 外显场景方向 | 角色池 | 默认角色 | 说明 |
|---|---|---|---|---|
| S1 | 想把话轻轻带过 | A / B / D | A | 内部对应“被问你怎么了但不想解释”，但前台不能这么说 |
| S2 | 消息看见了，但现在接不住 | B / A / E | B | 重点不是不理人，而是入口暂时没开 |
| S3 | 任务在那，但人还没启动 | C / D / E | C | DDL/作业/论文/被催但启动不了 |
| S4 | 校园日常突然离谱 | D / E / C | D | D 的主场，要有抽象感 |
| S5 | 现在不想被拉进互动 | B / A / E | B | 宿舍、邀约、社交电量不足 |
| S6 | 这事离谱，但不想亲自开怼 | E / C / D | E | 小组作业、被安排、被占便宜、被催 |

## 7. 结果页结构

### 7.1 结果图

展示当前场景 + 当前嘴替生成的分享图。  
后续设计要保证“用户想说的话”和“嘴替形象”都足够重要，角色不能只是脚注。

### 7.2 当前嘴替角色卡

展示：
- 角色形象；
- 角色名称；
- 风格短语；
- 一句人格描述；
- 一条角色 quote。

不展示：
- “它适合你”；
- “它适合这个场景”；
- “它不能怎样”；
- 过度解释式说明。

### 7.3 换个说法

含义：同一场景、同一角色、同一表达边界下，换另一句表达。  
不改变角色，不改变语气强度，不让用户调节攻击/温柔/疯癫程度。

### 7.4 换个嘴替帮你说

展示该场景角色池里的另外两个角色。

每张 CTA 卡包含：
- 角色形象；
- 角色名称；
- 风格短语；
- 可选 quote preview。

用户点击后：
- 场景不变；
- 角色池不变；
- 当前角色切换为被点击角色；
- 结果句切换为该角色在当前场景下的默认版本；
- CTA 继续展示同一角色池中剩下的两个角色。

### 7.5 保存 / 复制配文 / 重选状态

保持轻量，不在结果页引入复杂新流程。

## 8. 结果页数据结构建议

以下字段名保留英文，方便后续工程实现；字段含义以中文解释为准。

```ts
type RoleId = 'A' | 'B' | 'C' | 'D' | 'E';
type SceneId = 'S1' | 'S2' | 'S3' | 'S4' | 'S5' | 'S6';

type Role = {
  id: RoleId;
  roleName: string;          // 角色名称，外显
  imageRef: string;          // 角色形象资源
  stylePhrase: string;       // 极短风格短语，外显
  personalityLine: string;   // 一句人格状态，外显
  voiceRules: string[];      // 内部声线规则
  forbiddenMoves: string[];  // 内部红线
  quotes: RoleQuote[];
};

type RoleQuote = {
  roleId: RoleId;
  quoteId: string;
  text: string;
  usage: 'role_card' | 'alternate_card' | 'result_support';
  intensity: 'safe' | 'strong'; // 内部字段，不展示
  sceneFit?: SceneId[];
};

type Scene = {
  id: SceneId;
  externalDirection: string;
  defaultRoleId: RoleId;
  rolePool: RoleId[]; // P0 固定 3 个
};

type ResultVariant = {
  sceneId: SceneId;
  roleId: RoleId;
  variantId: string;
  resultText: string;
  supportQuoteId?: string;
};
```

## 9. 角色 quotes 要求

### 9.1 为什么需要 quotes

quotes 不是装饰文案，而是角色人格样本。作用是：
- 让用户快速感到“它懂我”；
- 让角色不是功能标签，而是有说话方式；
- 增加结果页共鸣点；
- 让用户愿意换另一个嘴替看看。

### 9.2 P0 数量

每个角色先准备约 7 条：
- 3 条用于当前角色卡；
- 2 条用于换嘴替 CTA 卡；
- 2 条用于结果页补充氛围。

5 个角色合计约 35 条。

### 9.3 风格边界

A：嘴硬、漏风、不能卖惨。  
B：离线、挡门、不能傲慢。  
C：加载中、有自知、不能真摆烂。  
D：抽象、发疯、离谱但可读。  
E：有刺、反骨、有分寸，不做人身攻击。

## 10. 文案要求

### 10.1 所有角色相关文案都必须带角色声线

包括：
- 角色名称；
- 风格短语；
- 人格描述；
- quotes；
- 结果句；
- 换个说法后的句子；
- 换嘴替 CTA 卡短语。

### 10.2 禁止中性功能说明

不要写成：
- “适合不想解释的你”；
- “它会帮你委婉表达”；
- “该角色用于处理社交边界”。

应该让角色通过语言和姿态自己成立。

### 10.3 最终命名暂不锁定

角色名、页面组件名、最终文案交给文案专职 agent 在明确 brief 后生成。

---

## 11. 视觉要求

### 11.1 从角色声线出发

设计不是先画动物再贴性格，而是先理解每个角色的表达姿态，再决定形象。

### 11.2 五个角色必须可区分

每个角色需要在以下层面有差异：
- 姿态；
- 表情；
- 轮廓；
- 视觉节奏；
- 和结果卡的关系。

### 11.3 不做刻板女性化

即使 TA 女性占比可能更高，也不应默认粉色、可爱、柔软、甜美。

### 11.4 世界资产质量统一

最终版不允许出现低质量贴图、CSS/emoji 占位、临时头像、与角色资产不在同一质量线的素材。

---

## 12. 成功标准

### 12.1 产品判断标准

用户应能理解：
- 我选了什么状态；
- 当前是谁在替我说；
- 这个嘴替是什么性格；
- 这句话为什么像我会说的话；
- 我为什么想换另一个嘴替看看。

### 12.2 行为指标候选

后续可观察：
- 结果生成完成率；
- 结果页换嘴替点击率；
- 换个说法点击率；
- 保存/复制/分享率；
- 重复生成率；
- 用户测试中的“这像我”主观评分。

### 12.3 小样本测试标准

用户测试中希望听到：
- “这个角色像我/像我朋友”；
- “这句我可能会发/会存”；
- “我知道为什么想换另一个嘴替”；
- “没有觉得它在骂我/诊断我/教育我”。

## 13. P0 不做范围

- 平台专门适配流程；
- 抖音/视频/动效模板；
- 每个场景开放全 5 角色；
- 语气 slider 或强弱量化；
- 真实低落/需要安慰的严肃情绪；
- 严肃关系冲突、道歉、修复；
- 宿舍/小组矛盾具体爆料；
- 在未确认方向前锁最终角色名和最终页面文案。

## 16. 当前已锁与未锁

### 已锁

- TA：在校大学生中的高社交密度表达需求人群；
- 主链路：选状态/场景 → 选嘴替/表达人格 → 生成结果页；
- 五类嘴替内部类型：A/B/C/D/E；
- P0 六场景；
- 每个场景固定 3 角色池；
- 结果页包含当前角色卡、换个说法、换个嘴替帮你说；
- 不做语气 slider；
- 不把平台作为输入；
- 角色名和 quotes 要进入结果页；
- 所有角色相关文案必须带角色声线。

### 未锁

- 最终角色名称；
- 最终文案；
- 最终视觉形象；
- 每个组合具体结果句数量；
- quote 是否进入结果图内部，还是只在结果页角色卡展示。
