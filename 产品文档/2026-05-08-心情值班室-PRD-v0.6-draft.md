## 0. 本版为什么重写

这个 PRD 不是在“社交动物测试”基础上继续扩功能，也不是简单做“生成卡片工具”。

过去几轮讨论里，已经出现了几个关键纠偏：

1. **排版小动物之所以成立，不是因为动物本身，而是因为它抓住了内源表达需求**：用户本来就想表达自己、吐槽自己、让朋友认出自己，只是需要一个低压、有趣、可分享的外壳。
2. **“朋友”不是好的承接对象**：朋友太泛、太现实、太容易变成工具或社交压力。用户更容易喜欢一个具象角色，把情绪投射给它。
3. **“信使”太工具化**：它像传话工具，不像一个能被喜欢、被认领、被收藏的个体。
4. **朋友锐评不应该写死在分享图上**：锐评最好发生在用户分享后的评论区/群聊里，产品负责提供“可被锐评”的素材，而不是替朋友把话说完。
5. **MVP 不能过重**：不能一上来做复杂 AI、账号体系、社交关系链、匹配系统。P0 应该是低成本、可控、可传播、可验证的表达产品。
6. **生图通道已经打通**：这意味着设计资产生产能力提升，但不代表 P0 要做“用户实时 AI 生图”。P0 更适合用 Image2 生产角色资产和模板，前端用规则组合生成稳定结果。

所以本版重新定义产品：

> 不是“帮用户交朋友”，也不是“帮用户写文案”，而是让用户用一个可爱的、具体的、能承接情绪的角色，低压表达“今天的我”。

## 1. 一句话定义

### 1.1 内部定义

**Meetu 心情值班室**是一套高频、低压、可分享的心情表达系统：用户通过 2-3 次轻选择，让一个具象“值班角色”代表自己当前的状态，生成一张可发朋友圈/小红书/群聊的心情卡。

### 1.2 用户感知

用户不应该觉得：

```text
我在用一个 AI 工具生成图片。
```

用户应该觉得：

```text
今天这个东西有点像我。
```

或者：

```text
这就是我今天会发的状态。
```

或者：

```text
发出去我朋友一定会说：这不就是你？
```

### 1.3 对外可用名称候选

内部先用“心情值班室”，对外名称后续可 A/B：

1. 今日值班
2. 今天谁值班
3. 心情值班室
4. 今日形态
5. 今天的我由谁值班

P0 建议先用：

> 今天谁在你身体里值班？

它比“测试”更高频，比“生成器”更有人味，比“心情日记”更有梗。

## 2. 第一性原理

这个应用必须同时满足四个目标：

### 2.1 传播性

用户愿意发出去，不是因为功能完整，而是因为：

- 图像一眼有记忆；
- 文案像自己会说的话；
- 发出去不尴尬；
- 朋友容易接话、认领、补刀；
- 评论区能自然出现“这不就是你 / 我也是 / 我今天是这个”。

### 2.2 复用性

用户不是每天都要介绍“我是谁”，但每天都可能想表达“我今天是什么状态”。

因此核心不是身份卡，而是状态卡：

- 今天低电量；
- 今天嘴硬；
- 今天不想营业；
- 今天脑内很吵；
- 今天出门审批没过；
- 今天 DDL 小鬼在值班。

复用频率来自状态变化，而不是一次性人格标签。

### 2.3 情绪依赖性

依赖不是来自“工具帮我做事”，而是来自“这个角色懂我”。

用户会逐渐形成：

```text
今天我需要低电量猫出来值班。
```

```text
这句话只有嘴硬鹅能说。
```

```text
DDL 小鬼又来了。
```

这类角色记忆会产生轻度情感寄托。

### 2.4 爆款潜质

爆款需要：

- 角色可爱/可恨/可认领；
- 文案短、准、有情绪；
- 图适合截图传播；
- 朋友评论能二次创作；
- 系列感足够强，能持续扩展。

## 3. Target Audience

### 3.1 核心用户

**有社交表达需求，但不想用高压、直白、像广告的方式表达自己的大学生。**

他们不是没有表达欲，而是讨厌几类表达方式：

- 太认真：像情绪小作文，怕被看出脆弱；
- 太直白：像公开求关注，怕尴尬；
- 太广告：像运营内容，朋友不接；
- 太工具：像 AI 味，缺少人格；
- 太诊断：像心理测试审判自己。

他们更能接受：

- “我发个图，你懂就懂”；
- “我嘴上不认，但这确实有点像”；
- “我不是在求安慰，我只是在发疯”；
- “朋友可以评论，但不要让我先把话说满”。

### 3.2 行为习惯

结合 Agent-Reach 样本和社交动物测试传播过程，核心行为包括：

1. 用小红书/朋友圈/群聊表达状态；
2. 喜欢截图、梗图、测试结果、表情包、聊天截图等低压内容；
3. 评论区会用“求 / 蹲 / dd / 一起 / 群 / 私”等行动词；
4. 对强导流、硬广、过度包装非常敏感；
5. 喜欢“我不是这样但好像又是”的嘴硬式表达；
6. 更容易被具体场景触发，而不是被抽象产品介绍触发。

## 4. 真需求判断

### 4.1 这是内源需求，不是外部强推需求

用户本来就会做这些事：

- 发歌表达心情；
- 发截图暗示状态；
- 发测试结果让朋友评论；
- 发抽象梗图表达“今天的精神状态”；
- 用表情包代替直接说话；
- 在评论区报“我也是这个”。

产品不是创造新需求，而是降低这类表达的成本。

### 4.2 为什么现有产品没有完全满足

| 产品/内容形态 | 满足了什么 | 不足 |
|---|---|---|
| MBTI/SBTI/人格测试 | 身份认同、朋友对号入座 | 低频，一次测完后复用弱；容易变成标签审判 |
| 音乐分享 | 情绪表达、低压 | 不够具体，朋友未必读懂；无法形成角色认领 |
| 表情包 | 轻表达、高频 | 单张表达短，缺少“这是我”的身份/状态沉淀 |
| AI 文案/AI 生图 | 能生成内容 | 工具感强，用户需要知道自己要什么，输出常像模板 |
| 小红书大字报/梗图 | 传播强 | 不个性化，难持续形成自己的角色库 |
| 朋友圈文案模板 | 可复制 | 广告感/模板感强，朋友容易不接 |

我们的机会：

> 用具象角色承接情绪，用轻选择降低输入，用可分享卡片激发朋友评论。

## 5. 产品母框架：心情值班室

### 5.1 为什么是“值班室”

“值班”有几个优势：

- 它天然是“今天是谁出来”的逻辑，适合高频；
- 它允许角色轮换，不要求用户固定人格；
- 它可以容纳动物、小人、物件、小怪物、系统角色；
- 它带一点荒诞感，但不难懂；
- 它能形成口头禅：今天谁值班？

### 5.2 世界观

在用户身体/脑内/生活里，有一间“心情值班室”。

每天不同角色值班：

- 低电量猫负责拒绝营业；
- 嘴硬鹅负责“我没有”；
- 后台小人负责脑内开会；
- 结界鼠负责划安全距离；
- 出门审批员负责卡住出门申请；
- DDL 小鬼负责在最后一刻出现。

用户不是在“生成一张卡”，而是在“叫出今天值班的那个家伙”。

## 6. P0 角色体系

P0 不做大而全，先做 6 个高频角色。每个角色必须满足：

- 有明确情绪功能；
- 至少覆盖 5 个日常场景；
- 名字 1 秒能懂；
- 视觉可爱/可记/可被喜欢；
- 文案能形成稳定语气；
- 朋友看到后容易评论。

### 6.1 P0 六个值班角色

| 角色 | 类型 | 核心状态 | 典型句式 | 传播点 |
|---|---|---|---|---|
| 低电量猫 | 动物 | 不想营业 / 社交耗电 | 人在，电不在 | 高共鸣、高频 |
| 嘴硬鹅 | 动物/小怪 | 被说中但不认 | 我没有，别乱讲 | 评论区容易“别嘴硬” |
| 后台小人 | 小人/系统 | 脑内过载 / 复盘 | 表面没事，后台全开 | 适合聊天/社交局后 |
| 结界鼠 | 动物 | 边界 / 勿扰 / 需要空间 | 今日对外开放时间：无 | i人/宿舍/社交压力 |
| 出门审批员 | 小人/部门 | 想去但启动失败 | 出门申请正在走流程 | 周末/朋友约局高频 |
| DDL 小鬼 | 小怪物 | 拖延 / 期末 / 临时抱佛脚 | 我会做的，但不是现在 | 期末/作业/实习高频 |

### 6.2 P0 不选的角色类型

暂不做：

- 恋爱/crush 专属角色：流量强但风险高，容易歪到情感咨询/暧昧引导；
- 宿舍矛盾攻击型角色：痛点强但负面浓度高；
- 纯“发疯”角色：容易短期有梗，长期情感依赖弱；
- 过于抽象的原创怪物：理解成本高，P0 先不冒进。

## 7. 场景、状态、语气体系

### 7.1 P0 场景

场景不是功能分类，而是用户会产生表达冲动的时刻。

| 场景 | 用户触发 | 适配角色 |
|---|---|---|
| 不想营业 | 不想聊天、不想回消息、不想社交 | 低电量猫 / 结界鼠 |
| 被朋友约出门 | 想去但懒、临时被叫、出门启动失败 | 出门审批员 / 低电量猫 |
| 社交局结束后 | 复盘、后悔、脑内重播 | 后台小人 / 嘴硬鹅 |
| 被说中了但不想认 | 朋友评价太准、嘴硬反驳 | 嘴硬鹅 |
| 期末/DDL | 拖延、焦虑、假装冷静 | DDL 小鬼 / 后台小人 |
| 宿舍/私人空间 | 想安静、想划边界 | 结界鼠 |

### 7.2 P0 状态

P0 先控制在 16 个状态，避免信息过载。

1. 低电量
2. 不想营业
3. 已读但不想回
4. 想出门但启动失败
5. 被安排了
6. 嘴硬
7. 被说中
8. 表面正常
9. 后台过载
10. 复盘中
11. 勿扰
12. 需要结界
13. DDL 逼近
14. 拖延中
15. 想发疯但很体面
16. 需要朋友但不想开口

### 7.3 P0 语气

先做 4 种语气，不做复杂人格模型。

| 语气 | 用户感受 | 示例 |
|---|---|---|
| 嘴硬 | 表面否认，实际暴露 | 我没有，只是刚好很像 |
| 摆烂 | 放弃抵抗，轻松承认 | 行吧，今天就这样 |
| 礼貌勿扰 | 不攻击别人，只保护自己 | 今日暂不对外开放 |
| 假装正常 | 明明崩了但要体面 | 我很好，只是后台在报警 |

## 8. 用户链路

### 8.1 P0 最短链路

目标：用户 15-30 秒内出图。

```text
入口
→ 选择“今天什么情况？”（场景）
→ 选择“现在像什么状态？”（状态）
→ 系统推荐 1-3 个值班角色
→ 用户选一个 / 直接用推荐
→ 生成 3 张候选卡
→ 保存 / 换一句 / 发给朋友
```

### 8.2 降低 friction 的关键

DavidC 提醒过：降低 friction 和搜集足够信息之间要平衡，不能一刀切。

因此 P0 采用分层输入：

#### 快速模式：2 次点击

适合用户不知道自己要什么。

```text
今天什么情况？
我没电 / 我嘴硬 / 我脑子很吵 / 我不想出门 / 我有DDL / 我需要结界
```

系统直接推荐角色和文案。

#### 精准模式：3 次点击

适合用户想更准。

```text
场景 → 状态 → 语气
```

#### 编辑模式：可选

只提供轻编辑：

- 换一句；
- 换语气；
- 改 1 行自定义文字；
- 不做长 prompt 输入。

### 8.3 关键原则

不要要求用户清楚表达：

```text
我的目的是什么？我的偏好是什么？我的人设是什么？
```

而是让用户从低认知负担选项里找到：

```text
对，就是这个。
```

## 9. 输出形态

### 9.1 核心输出：心情值班卡

一张卡包含：

1. 今日值班角色
2. 角色形象
3. 状态短句
4. 一句核心文案
5. 可选小标签
6. Meetu 轻品牌 footer

示例：

```text
今日值班：嘴硬鹅

我没有不开心。
只是表情管理部门临时下班。

#别嘴硬 #已被看穿
```

### 9.2 分享图上不放“朋友锐评”

DavidC 的判断采纳：

> 朋友锐评应该出现在用户分享图片后的评论区，而不是在展示结果的图片上。

所以卡片只负责制造可评论空间，不把朋友的话写死。

### 9.3 分享后辅助

生成卡后，页面可以给用户 3 个“发出后可用的小动作”：

- 复制配文：`今天它值班，别问我。`
- 复制评论引导：`像吗？不像我删。`
- 给朋友生成：`帮朋友也叫一个值班的。`

但这些不进入图片主视觉。

## 10. 文案生成机制

### 10.1 P0 不依赖实时大模型

P0 用规则模板 + 文案池。

理由：

- 稳定；
- 可控；
- 成本低；
- 审核风险低；
- 前端静态可实现；
- 容易保证“像人话”。

### 10.2 模板结构

每条文案由四个字段组合：

```text
角色语气 + 状态事实 + 反差句 + 轻收尾
```

示例：

```text
角色：低电量猫
状态：不想营业
语气：礼貌勿扰

人在。
电不在。
今日社交请求请明天再试。
```

### 10.3 文案池规模

P0 建议：

- 6 角色；
- 每角色 20 条核心文案；
- 每角色 10 条短标签；
- 每角色 6 条配文；
- 合计约 216 条可控文案。

这比实时 AI 更适合 P0。

## 11. 生图与设计资产机制

### 11.1 生图通道的定位

Image2 / gpt-image 用于**设计资产生产**，不是 P0 用户实时生成。

P0 生产方式：

```text
Phoebe2 用 Image2 生成角色资产
→ 人工筛选和修 prompt
→ 固化成角色图库
→ Dave 前端用图库 + 模板生成用户卡
```

### 11.2 P0 资产清单

每个角色需要：

- 主形象 1 张；
- 情绪变体 3 张；
- 小图标 2 个；
- 背景纹理/场景元素 2 个；
- 分享卡安全版 1 个布局。

6 角色共约：

- 6 主图；
- 18 变体；
- 12 图标；
- 12 背景元素；
- 6 分享卡 layout 样例。

### 11.3 生图验收标准

每张角色图必须满足：

- 1 秒能认出角色功能；
- 不像普通 AI 萌宠；
- 不像儿童贴纸；
- 不像广告吉祥物；
- 可在 375px 手机屏看清；
- 可以和文字形成情绪反差；
- 角色之间属于同一个世界，但不能长得一样。

### 11.4 文件与 prompt 归档

每张图必须记录：

- prompt；
- 参考图；
- 模型/质量/尺寸；
- 输出文件；
- 适配角色；
- 失败原因（如果废弃）；
- 是否进入 P0 asset library。

## 18. 设计要求

### 18.1 设计母系统

不是“六张随机 AI 图”，而是一个统一世界：心情值班室。

需要统一：

- 卡片结构；
- 字体层级；
- 色彩规则；
- 角色命名；
- 图形线条；
- 轻微荒诞感；
- 手机缩略图可读性。

### 18.2 每个角色要有不同人格

不能只是换皮。

- 低电量猫：软、懒、没电；
- 嘴硬鹅：嘴硬、炸毛、眼神不服；
- 后台小人：忙、乱、多窗口；
- 结界鼠：小心、边界、拒绝靠近；
- 出门审批员：流程、章、表格、卡住；
- DDL 小鬼：坏笑、拖延、凌晨出现。

### 18.3 广告感红线

避免：

- 大 logo；
- 过度商业海报；
- 功能说明书；
- AI 塑料质感；
- 儿童贴纸风；
- 精神诊断感。

## 22. PM 自审

### 22.1 这是真需求吗？

判断：成立，但前提是产品必须是“低压表达”，不能变成“复杂生成工具”。

证据：

- 用户天然使用音乐、表情包、测试结果、截图表达状态；
- Agent-Reach 数据显示评论区高频出现“朋友/求/一起/学校/一个人/dd/搭子/群/私/蹲”等行动词；
- 社交动物测试的分享动力来自“这像我/朋友会接话”，不是来自测试本身；
- Jonathan 反复指出“内源需求”重要，排版小动物的成功是表达欲被具象角色承接。

### 22.2 链路是否太长？

v0.5 之前的风险是链路偏长：用户要想清楚场景、目的、偏好。

v0.6 通过快速模式降低：

```text
今天什么情况 → 直接出图
```

精准模式只是可选。

### 22.3 MVP 是否过重？

如果做实时 AI 生图，过重。  
如果做预生成资产 + 规则模板，MVP 可控。

所以 P0 明确不做用户实时 AI。

### 22.4 是否有商业化价值？

短期不是直接收入产品，而是：

- 拉新传播工具；
- Meetu 品牌语气资产；
- 用户状态/场景偏好数据；
- 后续校园低压小局/自习局/周末局的内容入口。

中长期可扩角色包、联名、会员、IP。

### 22.5 是否与社交动物测试重复？

相似点：

- 都用具象角色承接自我表达；
- 都靠分享图传播；
- 都需要朋友接话。

区别：

| 社交动物测试 | 心情值班室 |
|---|---|
| 一次性人格测试 | 高频状态表达 |
| 12 题后出结果 | 2-3 次轻选择出图 |
| “我是哪种人” | “我今天是什么状态” |
| 结果更稳定 | 每天可变 |
| 朋友锐评在结果体系内 | 朋友锐评发生在分享后评论区 |

### 22.6 最大风险

1. 角色不够招人喜欢；
2. 文案像 AI 模板；
3. 图像世界割裂；
4. 用户不愿意每天打开；
5. 运营内容太像广告；
6. 生成卡不够“我会发”。

对应措施：

- P0 角色少而精；
- 先用人工文案池；
- Phoebe 统一世界观；
- 首页做“今日值班”而不是“生成器”；
- 运营以用户晒图而非产品介绍；
- 每张卡必须通过“我会不会发朋友圈/群聊”自检。

## 25. 暂定结论

PRD v0.6 的核心收束：

> Meetu 心情值班室不是一个 AI 生图工具，而是一套具象情绪角色系统。它让用户用一个今天值班的角色表达此刻状态，用稳定模板和高质量视觉降低表达门槛，用分享后的朋友评论完成传播闭环。

P0 应该做：

- 少角色；
- 高频状态；
- 人工文案池；
- 预生成视觉资产；
- 快速出图；
- 分享后等朋友接话。

不要做：

- 大而全 AI 生成器；
- 复杂社交关系；
- 公开广场；
- 账号体系；
- 心理诊断；
- 硬导流。
