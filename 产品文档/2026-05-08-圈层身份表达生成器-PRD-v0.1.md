## 0. PRD 摘要

### 产品暂名

**Meetu 圈层身份表达生成器**

### 一句话定义

> 帮用户把“我是什么人、我想被怎样的人看见、我有哪些边界”生成一张不尴尬、可发布、可被同类接话的身份表达图和配套文案。

### 产品性质

它不是：

- 交友平台；
- 搭子匹配；
- 匿名墙；
- MBTI/心理测试；
- 单纯图片生成器；
- 自介卡模板站。

它是：

> 一个 **低压自我表达工具**，让用户先把“我是谁/我想找谁/我不想怎样”说得不尴尬。

### P0 目标

验证这件事是否成立：

> 用户愿意用 Meetu 生成一张表达自己圈层/状态/边界的图，并愿意保存、复制或发出去。

### 核心判断

这个方向比“低压小局/搭子接龙”更适合作为 P0，因为它是 **内源需求 + 短链路 + 生成后立刻可用**：

- 不需要用户等别人回复；
- 不需要运营组织；
- 不需要线下到场；
- 不需要平台承诺匹配成功；
- 用户生成后自己就能用。

## 1. 背景与研究依据

### 1.1 为什么从“低压小局”修正到“内源表达”

Jonathan 指出：低压小局虽然看似解决真实社交问题，但链路太长：

```text
群内回复 → 填表 → 等组织 → 匹配 → 确认 → 到场 → 复盘
```

每一步都依赖外部推动，且用户一开始并不一定有足够动机跨出去。

排版小动物这类东西更成立，是因为它抓的是用户自己的内源动作：

```text
我想表达自己 → 生成一个好玩的东西 → 立刻能发/能截图/能被朋友接话
```

所以本 PRD 的方向不是“帮用户马上认识人”，而是先做更短链路的：

```text
我想表达自己 / 找同类 / 表明边界 → 生成表达物 → 发出去 → 自然产生连接可能
```

## 2. 心理层面的需求理解

### 2.1 核心心理矛盾

大学生在社交表达里存在一个非常稳定的矛盾：

> 想被看见，但怕被看得太用力。  
> 想找同类，但怕显得太主动。  
> 想说明边界，但怕像在立规矩。  
> 想发自己，但怕像在营销自己。

所以他们需要一种 **有缓冲层的表达**。

这个缓冲层可以是：

- 梗图；
- 测试结果；
- 动物/人格符号；
- 大字报；
- 朋友圈文案；
- “朋友锐评”；
- 半开玩笑的自介卡。

本产品要提供的不是“信息表”，而是一个心理安全的表达外壳。

### 2.2 关键心理机制

#### 机制 1：间接自我呈现

直接说：

```text
我想找一个游戏搭子，最好别骂人，不要压力我。
```

会显得像征友/招聘/提要求。

换成图：

```text
游戏搭子说明书
嘴硬程度：中等
破防概率：看队友
边界：不骂人 / 不压力 / 输了能再来
```

用户心理压力会小很多。

原因：图不是严肃声明，而是半开玩笑的“人格外壳”。用户可以随时说：

```text
随便生成的，别太认真。
```

这给了用户退路。

#### 机制 2：可否认性

一个好用的身份表达图必须允许用户“嘴硬”。

用户不是要正式宣布“我就是这样的人”，而是要一种可以转圜的表达：

```text
有点像，但我不完全认。
```

这正是社交动物测试结果卡能传播的原因：用户可以发出去，让朋友认领，而不是自己认领。

因此本产品文案不能太肯定，不能像心理测评。要更多使用：

- 疑似；
- 可能；
- 当前状态；
- 今日版本；
- 朋友可参考；
- 不准也别骂我。

#### 机制 3：同类识别

用户真正想要的不是“所有人看到我”，而是“对的人看懂我”。

所以卡片不应该追求信息完整，而应追求 **识别信号明确**：

- 我是什么圈层；
- 我能接受什么社交强度；
- 我希望怎样开始；
- 我有哪些边界；
- 我是不是你同类。

这比“姓名/年龄/学校/爱好/身高”这种传统自介更重要。

#### 机制 4：低成本发起

很多人不是没有社交需求，而是缺一个低成本开口方式。

卡片的作用是把开口成本从：

```text
我能不能问一句，有没有人跟我一样？
```

降低成：

```text
我把图放这了，同类自己出现。
```

这不是匹配，但它创造了匹配发生的前置条件。

#### 机制 5：朋友介入带来的传播

如果一张图只能自己看，它价值低。  
如果一张图能让朋友说“这不就是你”，它就有传播价值。

所以产品必须设计“朋友接话点”：

- 太像你了；
- 你别嘴硬；
- 同类来了；
- 这个品种我见过；
- 建议贴主页；
- 你把我也生成一下。

## 3. 产品目标与非目标

### 3.1 P0 目标

1. 用户能在 1 分钟内生成一张身份表达图；
2. 用户愿意保存图；
3. 用户愿意复制配套文案；
4. 用户愿意发到小红书/群聊/朋友圈/主页置顶；
5. Meetu 能沉淀圈层、场景、边界、语气偏好。

### 3.2 P0 非目标

P0 不解决：

- 自动匹配；
- 找到人；
- 私信系统；
- 公开展示用户；
- 活动报名；
- 付费；
- 账号体系；
- 安全认证。

P0 只验证：

> 用户是否愿意用 Meetu 生成身份表达物。

## 4. 用户画像

### Persona A：慢热但想认识同类的人

- 不想高压社交；
- 不想上来查户口；
- 希望先用轻松方式释放信号；
- 典型语气：嘴硬、低压、自嘲。

需要的输出：

```text
低压同类招领
品种：慢热
特点：熟了话多
禁区：上来查户口
适合：慢慢认识，不催回复
```

### Persona B：有明确兴趣圈层的人

- 游戏、Kpop、二次元、乙游、livehouse、桌游、运动；
- 想找同类，但不想发得像招募；
- 需要圈层黑话和边界表达。

需要的输出：

```text
游戏搭子说明书
在线时间：晚上
破防概率：看队友
边界：不骂人 / 不压力 / 输了能再来
```

### Persona C：想发状态但怕太矫情的人

- 想表达“想出门/想被捡走/想有人一起”；
- 但怕看起来像求关注；
- 需要梗图化处理。

需要的输出：

```text
今日状态
想出门。
不想组织。
可以被捡走。
但请提前说几点几地几人几钱。
```

### Persona D：活动/小局前需要破冰的人

- 已经参加 Meetu 或其他小局；
- 怕第一次见面尴尬；
- 需要提前说明自己的社交电量和边界。

需要的输出：

```text
今日入场说明
可聊：电影 / 游戏 / 学校怪事
不聊：收入 / 前任 / 查户口
电量：52%
熟了会自动开机
```

## 5. 使用场景

### 场景 1：小红书主页置顶

用户想把自己包装成一个可被理解的人，而不是写一份“交友简历”。

输出组合：

- 图片卡；
- 小红书正文；
- 评论区接话。

### 场景 2：群聊发图试探

用户想找搭子/同类，但不想公开发一大段需求。

输出组合：

- 群聊图；
- 群内短句；
- 被问时的回复。

### 场景 3：朋友圈状态表达

用户只是想表达当前状态，不一定找人。

输出组合：

- 状态图；
- 朋友圈配文；
- 低品牌露出。

### 场景 4：Meetu 活动前破冰

用户参加活动前生成“入场卡”，帮助降低初见尴尬。

输出组合：

- 入场卡；
- 可聊/不聊；
- 今日电量；
- 活动主持人可参考。

## 6. 产品流程

### 6.1 P0 主流程

```text
入口页
  ↓
选择生成目的
  ↓
选择圈层/兴趣
  ↓
选择边界
  ↓
选择语气/风格
  ↓
生成结果
  ↓
保存图片 / 复制文案 / 再生成
```

### 6.2 用户输入

#### Step 1：你这张图想干嘛？

选项：

- 找同类；
- 找搭子；
- 表达状态；
- 发朋友圈；
- 活动前破冰。

#### Step 2：你是哪类人？

选项：

- 游戏；
- Kpop；
- 二次元/乙游；
- livehouse/音乐；
- 运动；
- citywalk/拍照；
- 自习/学习；
- 桌游；
- 慢热/i人；
- 其他。

#### Step 3：你的边界是什么？

多选，最多 4 个：

- 不尬聊；
- 可以少说话；
- 不压力；
- 不熬夜；
- AA；
- 女生优先；
- 不拍脸；
- 不催回复；
- 不突然查户口；
- 可临时退出；
- 不消失。

#### Step 4：你想被谁看到？

选项：

- 同校；
- 同城；
- 同兴趣；
- 同状态；
- 熟人也行；
- 只给朋友看。

#### Step 5：语气风格

选项：

- 正常；
- 抽象；
- 嘴硬；
- 大字报；
- 朋友圈；
- 群聊。

#### Step 6：可选信息

- 城市/学校，可跳过；
- 昵称，可跳过；
- 不上传真人照片。

## 7. 输出结构

每次生成 3 件套：

### 7.1 图片卡

结构：

- 标题；
- 当前身份/状态；
- 3-5 个标签；
- 边界；
- 接话点；
- Meetu 弱品牌。

### 7.2 发布文案

用于小红书/朋友圈。

要求：

- 不像广告；
- 不解释产品；
- 有人味；
- 可短可长；
- 至少给 2 个版本。

### 7.3 群聊发法

用于微信群/小红书群。

要求：

- 不带链接；
- 不像拉人；
- 可以嘴硬；
- 让别人自然接话。

## 9. 视觉原则

来自 Phoebe 的研究框架，P0 使用 **身份型 + 情绪型 + 传播型** 组合。

### 9.1 不要做成

- 交友广告；
- 简历模板；
- 过度精修海报；
- AI 味很重的插画；
- 大 logo 品牌图；
- 二维码/下载引导图。

### 9.2 应该像

- 自己做的梗图；
- 一张说明书；
- 一张贴在主页的身份卡；
- 一张朋友能转发吐槽的状态图；
- 一张可以发群里的低压边界卡。

### 9.3 视觉机制

不同用途对应不同视觉：

| 用途 | 视觉机制 |
|---|---|
| 发小红书 | 大字报 / 卡片 / 主页置顶图 |
| 发群聊 | 截图感 / 信息块 / 少字大字 |
| 发朋友圈 | 低饱和 / 备忘录 / 状态图 |
| 活动破冰 | 说明书 / 边界卡 / 清单 |

## 11. 成功指标

### P0 及格线

| 指标 | 及格线 |
|---|---:|
| 开始生成率 | ≥70% |
| 完成生成率 | ≥60% |
| 保存图片率 | ≥40% |
| 复制文案率 | ≥25% |
| 再生成率 | ≥20% |
| 用户自报愿意发 | ≥20% |
| 负反馈“像广告/尴尬” | <10% |

### P0 强信号

出现以下任一项，都说明方向值得继续：

- 有人评论/私信问“在哪做”；
- 用户把生成图发群里并有人接话；
- 某个模板被反复生成；
- 用户主动要求“能不能加某某圈层”；
- 用户把图当主页置顶或朋友圈图使用。

### P0 失败信号

- 用户只玩一次，不保存；
- 生成物被评价“像广告/像求偶/像招聘”；
- 用户只选择搞笑状态，不填写场景/圈层；
- 没有人问入口；
- 保存率低于 20%。

## 12. 安全与边界

### 必须保护

- 不要求实名；
- 不要求手机号；
- 不要求真人照片；
- 学校/城市可跳过；
- 不公开展示任何用户生成内容；
- 不自动推荐别人；
- 不承诺线下见面。

### 敏感方向不做

- 恋爱/脱单导向；
- 匿名吐槽；
- 校园墙公开投稿；
- 外貌/身材标签；
- 精神疾病梗；
- 高风险线下邀约。

### 文案安全

避免用户感觉被 judge。表达方式必须是：

```text
你可以这样介绍自己
```

而不是：

```text
我们来定义你是什么人
```

## 13. P0 页面结构

### 13.1 入口页

核心文案方向：

```text
给自己做一张不尴尬的说明书。

不用写简历。
不用装外向。
不用把边界说得像规章制度。

选几个词，生成一张能发出去的图。
```

CTA：

```text
开始生成
```

### 13.2 选择页

每一步都要像聊天，不像问卷。

错误：

```text
请选择您的社交需求类型。
```

正确：

```text
这张图主要想替你说什么？
```

### 13.3 结果页

模块：

1. 图片预览；
2. 保存图片；
3. 复制文案；
4. 换个语气；
5. 再生成一张。

不放强 CTA，不放下载 App。

## 14. 与 Meetu 主产品关系

P0 不把用户直接导入产品。

但它能为 Meetu 提供 3 个长期资产：

1. **真实圈层需求库**：哪些圈层/场景在大学生中高频；
2. **表达语言库**：用户愿意使用什么语气表达自己；
3. **视觉模板库**：什么样的图更愿意被保存和转发。

P1 再考虑：

- 高需求圈层对应的小局；
- 活动前破冰卡；
- 主理人招募卡；
- 同校低压身份墙，但必须经过安全设计。

## 17. Target Audience 与产品定位补充

### 17.1 这个产品到底服务谁

这个产品的 target audience 不是“所有大学生”，也不是“想交朋友的人”。

更准确的核心人群是：

> **有社交表达需求，但不想用高压、直白、像广告的方式表达自己的大学生。**

他们的共同点不是 i/e、男/女、某个兴趣圈层，而是：

- 有某种身份/状态/需求想被别人看见；
- 但害怕表达得太用力；
- 需要一个轻松外壳替自己说话；
- 生成物必须能直接发出去，而不是停留在产品里。

### 17.2 三层用户结构

#### 第一层：核心用户

**慢热但有连接欲的人。**

特征：

- 想认识同类，但不想直接发“扩列/交友”；
- 对社交压力敏感，怕尬聊、怕查户口、怕被催回复；
- 更接受“低压”“不压力”“不消失”“可少说话”这类边界表达；
- 喜欢用嘴硬、自嘲、梗图来表达真实需求。

他们是 P0 最该服务的人，因为他们最需要“表达缓冲层”。

典型心理：

```text
我不是不想认识人。
我只是不想一上来就把自己摆上货架。
```

#### 第二层：传播用户

**喜欢发梗图、测试结果、朋友圈文案的人。**

特征：

- 已经习惯用图表达自己；
- 愿意保存、截图、发群聊/朋友圈/小红书；
- 不一定真的要找人，但愿意参与“这不就是你/这不就是我”的互动；
- 对“好笑、像我、朋友会接话”敏感。

他们带来流量和传播，但不一定带来真实连接。

对他们来说，产品价值是：

```text
这个东西替我说话，而且朋友看了能笑。
```

#### 第三层：潜在承接用户

**已经有具体圈层或场景需求的人。**

包括：

- 游戏搭子；
- 自习搭子；
- 拍照/citywalk 搭子；
- Kpop/二次元/livehouse 同好；
- 运动/桌游/展览同类；
- 活动前需要破冰的人。

他们不是一开始就要匹配，但他们的生成内容里会暴露出高价值需求。

对 Meetu 来说，这一层是后续活动、社群、线下小局的入口。

### 17.3 不是目标用户

P0 不优先服务：

1. **强脱单/恋爱目的用户**：流量大，但安全、骚扰、品牌风险高；
2. **纯求职/简历/竞赛模板用户**：需求硬，但偏职业成长，不是 Meetu 主线；
3. **匿名吐槽/校园墙用户**：传播强，但隐私、攻击、学校管理风险高；
4. **强交易/兼职/跑腿用户**：商业化更直接，但会把 Meetu 拉向校园交易平台；
5. **只想看搞笑图不愿表达自己的人**：可以贡献浏览，但不是产品核心。

## 18. 用户特点与行为习惯

### 18.1 他们不是不表达，而是不想“正经表达”

从样本看，大学生大量使用这些外壳表达自己：

- 梗图；
- 精神状态图；
- 朋友圈文案；
- 测试结果；
- 自介卡/扩列卡；
- 评论截图；
- 校园墙投稿；
- 备忘录/清单。

这说明：他们不是缺表达欲，而是缺一种 **不尴尬、可否认、可转发** 的表达方式。

### 18.2 他们对“像广告/像招聘/像求偶”非常敏感

如果生成物像这样，就会失败：

```text
本人女大，想找高质量同频朋友，要求情绪稳定，有边界感。
```

它太像交友广告，也太用力。

更适合的方式是：

```text
低压同类招领
可少说话
不查户口
熟了会自己开机
```

同样的信息，换成“说明书/招领/状态卡”后，社交压力下降。

### 18.3 他们喜欢“朋友帮我认领”的机制

不是自己说“我就是这样”，而是让朋友说：

```text
这不就是你？
你别嘴硬。
这个品种见过。
```

所以产品要给朋友留接话口，不能只做自我描述。

### 18.4 他们会在评论区做动作

本轮评论高频词包括：`求 / dd / 蹲 / 私 / 群 / 一起 / 搭子`。这说明他们习惯在平台内容下面完成轻动作：

- 求链接；
- 求模板；
- 求同款；
- 报名；
- 找同类；
- 私信。

但 P0 不应该主动制造复杂互动，只要让生成物能引发这些动作即可。

### 18.5 他们的使用场景是碎片化的

不是“我打开一个产品认真完善资料”，而是：

- 刷到一个图，觉得像我；
- 点进去生成一张；
- 保存；
- 发给朋友/群聊；
- 被朋友锐评；
- 可能再生成一张。

所以流程必须轻，不能像注册资料表。

## 19. 对标产品与对标内容形态

这个方向没有一个完全等价的单一竞品。更合理的对标方式是按机制拆。

### 19.1 对标一：人格测试 / 结果卡类

代表：MBTI、16Personalities、各类人格测试、社交动物测试。

可借鉴：

- 用结果降低自我表达压力；
- 用标签帮助用户快速认领；
- 结果卡天然适合截图传播；
- 朋友可以围绕结果接话。

不能照搬：

- 不能假装心理学权威；
- 不能把用户“判定”为某种人；
- 不能每次都走测试流程，容易疲劳；
- 不能让文案像咨询/诊断。

我们和它的区别：

> 不是测试你是谁，而是帮你把“你想怎么被看见”表达出来。

### 19.2 对标二：自介卡 / 扩列卡 / 搭子卡

代表：小红书、QQ、同好圈层里的自介卡、扩列卡、OC/圈层卡、搭子招募图。

可借鉴：

- 用户已经接受“卡片化介绍自己”；
- 圈层身份、边界、雷点、可聊话题都可以结构化；
- 图片比文字更容易发群和主页置顶。

不能照搬：

- 传统自介卡太像资料表；
- 扩列卡容易低质、像求偶/交友广告；
- 信息暴露过多，有安全风险；
- 容易吸引错的人。

我们和它的区别：

> 不做“把自己摆上货架”的自介卡，而做“低压说明书”。

### 19.3 对标三：Canva / 创客贴 / 醒图模板类

代表：Canva、创客贴、醒图模板、黄油相机、小红书封面模板。

可借鉴：

- 模板化降低制作门槛；
- 输出图片即价值；
- 风格多样，适合社交平台传播。

不能照搬：

- 它们解决的是“怎么做得好看”，不是“我该怎么介绍自己才不尴尬”；
- 模板太泛，缺少大学生社交语境；
- 用户需要自己写内容，心理成本仍在。

我们和它的区别：

> 不只是排版工具，而是把心理边界和社交语气一起生成。

### 19.4 对标四：Soul / 积目 / 探探等社交产品

代表：Soul、积目、探探等。

可借鉴：

- 用户确实有陌生人连接需求；
- 兴趣、身份、标签是连接前置条件；
- 低压表达能降低破冰成本。

不能照搬：

- 这些产品一进入就是“找人/聊天/匹配”，心理压力更高；
- 恋爱/暧昧/骚扰风险高；
- 需要强运营和安全体系；
- 与 Meetu 目前“在大学生身边”的轻工具策略不一致。

我们和它的区别：

> 不先让用户进入陌生人社交场，而是先给用户一个可以带走的表达物。

### 19.5 对标五：小红书内容形态

代表：

- 精神状态梗图；
- 朋友圈文案；
- 评论截图；
- 校园墙投稿；
- 大字报；
- 测试结果晒图。

这是最重要的对标，不是传统产品。

可借鉴：

- 第一眼要像内容，不像工具；
- 输出要能独立传播；
- 标题/图像/评论区要给朋友接话空间；
- 不要强引导外链，不要强品牌。

不能照搬：

- 不能只做内容热闹；
- 不能没有数据沉淀；
- 不能只追求疯癫感而丢掉产品价值。

我们和它的区别：

> 小红书内容是一次性表达，Meetu 要把这些表达背后的圈层、边界和场景沉淀下来。

## 20. 产品定位结论

### 20.1 最准确定位

> 面向有低压自我表达和同类识别需求的大学生，提供一套可生成、可发布、可被朋友接话的身份表达工具。

### 20.2 不要这样定位

不要说：

```text
帮大学生找到同频朋友。
```

太大、太虚、太像社交 App。

不要说：

```text
一键生成搭子卡。
```

太窄、太像模板工具。

不要说：

```text
AI 生成你的社交人格。
```

太像测试/诊断，也容易让用户被 judge。

### 20.3 推荐外部表达

更适合说：

```text
给自己做一张不尴尬的说明书。
```

或：

```text
把“我是谁”说得没那么像自我介绍。
```

或：

```text
不是交友卡，是低压同类识别器。
```

### 20.4 产品战略位置

它是 Meetu 的 **前置表达层**。

关系如下：

```text
表达自己 → 被同类识别 → 产生轻互动 → 暴露高频需求 → Meetu 再承接活动/小局/社群
```

所以它不是最终商业闭环，但它可能是比“直接做活动/搭子”更低成本、更自然的入口。

## 21. 社交表达痛点：用户到底卡在哪里

### 21.1 痛点不是“不会自我介绍”，而是“自我介绍太像自我介绍”

传统自我介绍的问题是：

```text
我是谁 / 我喜欢什么 / 我想找什么人 / 我有什么要求
```

这些信息一旦被直白写出来，就容易变成：

- 像简历；
- 像求偶；
- 像招聘；
- 像卖自己；
- 像在提要求；
- 像很用力地想交朋友。

大学生不是没有表达能力，而是不想在半熟人/陌生人场景里显得“太用力”。

因此产品要解决的是：

> 让自我介绍变得不像自我介绍。

---

### 21.2 痛点一：想被看见，但怕被 judge

用户想表达自己的状态、圈层和需求，但又害怕别人觉得：

- 你怎么这么想交朋友；
- 你要求怎么这么多；
- 你是不是在装；
- 你是不是在营销自己；
- 你是不是太把自己当回事。

所以他们需要“第三方外壳”：

- 测试结果；
- 梗图；
- 说明书；
- 大字报；
- 朋友锐评；
- 今日状态卡。

这个外壳让用户可以说：

```text
不是我认真写的，是这个东西生成的。
```

这就是可否认性。

---

### 21.3 痛点二：想找同类，但不想主动喊人

直接说：

```text
有没有人跟我一起自习？
有没有人跟我打游戏？
有没有人愿意认识一下？
```

会有被冷场、被拒绝、被截图嘲笑的风险。

如果换成一张图：

```text
低压同类招领
需要一个能一起坐着的人
不用聊天，不查进度，不突然卷我
```

用户的心理压力会低很多，因为这不是“我在求你”，而是“我放一个信号”。

---

### 21.4 痛点三：想说明边界，但怕显得难搞

很多真实社交问题都来自边界没有提前说：

- 不想尬聊；
- 不想被催回复；
- 不想太晚；
- 不想被拍脸；
- 不想高压社交；
- 不想上来查户口。

但直接写“我的要求如下”很像规章制度。

产品要把边界变成轻松表达：

```text
使用说明：
可少说话。
熟了会自动开机。
别上来查户口。
```

这既表达了边界，又不显得攻击性强。

---

### 21.5 痛点四：用户不知道怎么写得“像人”

用户不是不会填信息，而是不知道怎么把信息转译成自然、有梗、不油腻的表达。

同样的信息：

```text
慢热，想找朋友，希望对方不要催回复。
```

如果产品转译成：

```text
低压同类招领
品种：慢热
特点：熟了话多
禁区：上来查户口
适合：慢慢认识，不催回复
```

用户才会觉得“这张图可以发”。

所以产品的核心能力不是排版，而是 **社交语气转译**。

---

### 21.6 痛点五：用户希望表达物可以被朋友接话

一张图发出去，如果别人只能点赞，它传播价值有限。

更强的是别人能回：

- 这不就是你；
- 你别嘴硬；
- 这个品种我见过；
- 帮我也生成一个；
- 我也是这个。

所以输出物必须自带“接话点”，而不是只做漂亮。

---

## 22. 为什么现有产品没有充分满足

### 22.1 社交 App：解决“找人”，但放大压力

代表：Soul、积目、探探等。

它们的问题：

- 一进入就是陌生人社交/匹配/聊天；
- 用户会觉得自己在“求连接”；
- 恋爱和暧昧意味重；
- 容易带来骚扰、安全和筛选压力；
- 需要持续经营资料页和聊天。

它们满足不了本方向的核心需求：

> 我只想先轻轻表达自己，不想马上进入一场社交关系。

---

### 22.2 模板工具：解决“好看”，但不解决“怎么说”

代表：Canva、创客贴、醒图、黄油相机、小红书封面模板。

它们的问题：

- 给你排版，但不懂你的社交边界；
- 给你模板，但不帮你把“尴尬需求”转成自然表达；
- 用户仍要自己写内容；
- 输出容易像海报/广告/模板图。

它们满足的是视觉制作需求，不是社交表达需求。

---

### 22.3 自介卡/扩列卡：形式接近，但气质容易跑偏

这类是最接近的替代方案。

它们的问题：

- 信息太满，像资料表；
- 容易像求偶/征友广告；
- 隐私暴露多；
- 低质量扩列感强；
- 很容易吸引错的人。

我们要借鉴“卡片化身份表达”，但不能照搬“把自己摆上货架”。

核心差异：

```text
自介卡：我把资料列给你看。
低压身份表达：我用一个好发的外壳释放信号。
```

---

### 22.4 人格测试/MBTI：解决标签认领，但不解决当前意图

测试类产品满足了：

- 低成本自我认领；
- 可截图传播；
- 朋友接话；
- 标签化身份。

但它们的问题：

- 它在“定义我”，不是“帮我表达我想怎么被看见”；
- 结果是固定的，不一定对应当前需求；
- 不能表达边界和场景；
- 热点过去后复用价值下降。

测试是强传播机制，但不是完整表达工具。

---

### 22.5 小红书内容：满足灵感，但不满足个性化生成

小红书上有大量精神状态图、朋友圈文案、自介卡、评论截图，但用户的问题是：

- 看到别人发得好，不知道自己怎么写；
- 想要同款，但复制会显得不属于自己；
- 想改成自己的圈层/边界/场景，但没有工具；
- 评论区“求模板/怎么做/同款”说明生产成本仍在。

小红书是灵感库，不是生成器。

---

## 23. SBTI 满足了什么，没满足什么

### 23.1 SBTI 为什么爆

公开资料里，SBTI 被描述为一种“发疯版 / 恶搞版 / 沙雕人格测试”，它把人格测试、发疯文学、截图社交压缩在一起。它的爆点不是心理学，而是社交传播。

它满足了几个关键痛点：

1. **给用户一个不严肃的标签**
   - 用户不需要认真声明“我是什么人”；
   - 测试替他说；
   - 错了也可以说“破测试”。

2. **提供可否认性**
   - 用户可以嘴硬：不准；
   - 朋友可以接话：别装；
   - 这种拉扯正好形成评论和转发。

3. **把自嘲做成社交货币**
   - 结果越缺德，越容易截图；
   - 朋友越能认领，传播越强。

4. **输出物天然可分享**
   - 结果图/人格名/一句话标签都适合发群聊、朋友圈、小红书。

5. **借用 MBTI 的认知框架**
   - 用户不用学习玩法；
   - 一看就知道：做题 → 得结果 → 晒图。

所以 SBTI 确实满足了我们讨论中的一部分痛点：

> 用户需要一个“安全的外部标签”来表达自己，同时让朋友参与认领。

---

### 23.2 SBTI 没满足什么

但 SBTI 仍然不是我们这个产品的完整答案。

#### 第一，它是“被测试”，不是“主动表达”

SBTI 的逻辑是：

```text
你做题 → 系统判你是什么类型
```

我们的方向应该是：

```text
你选择想怎么表达 → 系统帮你说得不尴尬
```

一个是被定义，一个是表达辅助。

#### 第二，它表达的是人格，不是当前社交意图

SBTI 可以告诉别人“我是什么类型”，但不能表达：

- 我现在想找自习搭子；
- 我不想尬聊；
- 我只想同城同兴趣的人看到；
- 我参加活动前有哪些边界；
- 我这张图是发主页、群聊还是朋友圈。

它不能承接当前场景。

#### 第三，它没有用户可控边界

SBTI 的结果是固定输出。用户只能接受或吐槽。

但我们的目标用户需要表达边界：

- 不查户口；
- 不催回复；
- 不压力；
- 不拍脸；
- 可少说话；
- 不消失。

这些边界不是人格测试能自然覆盖的。

#### 第四，它是热点型，不是可持续工具型

SBTI 的高峰来自新鲜感、爆梗和刷屏。一旦大家都测过，复用会下降。

而“身份表达生成器”如果做对，可以围绕不同场景反复使用：

- 今天找自习搭子；
- 明天发朋友圈状态；
- 周末找拍照同类；
- 活动前做入场卡；
- 新学期做主页说明书。

它有更多使用场景。

---

### 23.3 我们应该学习 SBTI 的什么

应该学：

1. **不严肃**：不要心理测评感；
2. **可截图**：输出必须是一张图；
3. **可嘴硬**：允许用户说“不准”；
4. **可被朋友认领**：朋友能接话；
5. **命名有梗**：不要功能名太产品化；
6. **结果有一点冒犯但不攻击**：轻微贴脸，不能羞辱。

不应该学：

1. 不要做成又一个测试；
2. 不要假装权威；
3. 不要固定判定用户；
4. 不要只追求短期刷屏；
5. 不要让用户被动接受结果。

---

### 23.4 和 SBTI 的定位差异

| 维度 | SBTI | 圈层身份表达生成器 |
|---|---|---|
| 用户动作 | 做题，被判定 | 选择信息，主动表达 |
| 核心价值 | 自嘲标签、朋友认领 | 低压表达、同类识别、边界说明 |
| 输出 | 人格结果 | 身份表达图 + 文案 + 群聊发法 |
| 使用频率 | 热点期强，后续下降 | 可随场景反复生成 |
| 场景 | 晒结果、发群聊 | 主页置顶、群聊试探、朋友圈状态、活动破冰 |
| 数据价值 | 人格偏好/结果分布 | 圈层、场景、边界、语气偏好 |
| 风险 | 跟风疲劳 | 变成低质交友卡/广告卡 |

一句话：

> SBTI 满足了“我想用一个好笑标签表达自己”的痛点；但没有满足“我想低压表达我的当前社交意图和边界”的痛点。

这正是我们的机会。

---

## 24. 和“社交动物测试”的关系：同源，但不是同一个产品定位

### 24.1 相似点：它们解决的是同一类心理机制

“社交动物测试”和“圈层身份表达生成器”底层都在服务同一类用户心理：

> 用户想表达自己，但不想直白、用力、像广告。

二者共享 5 个机制：

1. **第三方外壳**
   - 不是我自己硬写“我是这样的人”；
   - 是测试/卡片/系统/朋友锐评替我说。

2. **可否认性**
   - 用户可以嘴硬：不准；
   - 朋友可以接话：别装；
   - 这让表达变得低压。

3. **标签化表达**
   - 把复杂的人变成一个好记、好说、好截图的标签。

4. **朋友参与认领**
   - 输出物不是给用户自己看完就结束；
   - 朋友能接：“这不就是你？”

5. **截图传播**
   - 最终都依赖一张可以被转发、评论、群聊接话的图。

所以社交动物测试不是跑偏项目，它是对这个方向最小成本的一次机制验证。

---

### 24.2 关键区别：社交动物测试是“被判定”，身份表达生成器是“主动表达”

| 维度 | 社交动物测试 | 圈层身份表达生成器 |
|---|---|---|
| 用户动作 | 做题，被系统判定 | 选择场景/边界/语气，主动生成 |
| 核心心理 | “看看我是哪类人” | “我想这样被别人看见” |
| 表达主语 | 系统替用户下判断 | 用户借工具表达自己 |
| 输出内容 | 动物结果 + 朋友锐评 | 身份表达图 + 场景文案 + 边界说明 |
| 使用场景 | 晒结果、发群聊、引发朋友认领 | 主页置顶、群聊试探、活动破冰、找同类、朋友圈状态 |
| 使用频率 | 偏一次性/热点型 | 可随场景反复使用 |
| 数据价值 | 结果分布、传播效果 | 用户圈层、场景意图、边界偏好、表达语气 |
| 商业化潜力 | 传播入口/获客工具 | Meetu 长期前置表达层 |

一句话：

> 社交动物测试回答“我被看起来像什么”；身份表达生成器回答“我想怎样被别人轻轻看见”。

---

### 24.3 为什么社交动物测试不能直接升级成最终产品

社交动物测试的优势是传播强，但它有 4 个天然限制：

1. **结果固定**
   - 用户只能接受动物结果；
   - 不能表达“我今天想找什么/我不想要什么”。

2. **场景弱**
   - 它能让朋友笑；
   - 但不一定能帮用户发起一次真实连接。

3. **边界不可控**
   - 用户不能声明“不尬聊/不催回复/可少说话/只限本校”。

4. **复用频率有限**
   - 大多数人测一次、晒一次就结束；
   - 除非持续做新测试，否则留存弱。

所以它更像：

> 一个传播实验 + 语气实验 + 结果卡实验。

不能把它误认为 Meetu 的长期产品本体。

---

### 24.4 身份表达生成器应该继承社交动物测试的什么

应该继承：

1. **语气**：不严肃、不官方、不自我感动；
2. **外壳**：动物园/说明牌/朋友锐评/使用说明这类第三方表达；
3. **截图结构**：大标题 + 一句话钩子 + 朋友可接话点；
4. **轻微冒犯**：贴脸但不羞辱；
5. **朋友视角**：让别人看了能说“这不就是你”。

不应该继承：

1. 纯测试流程；
2. 固定结果分类；
3. 一次性刷屏逻辑；
4. 让用户只能被系统判定；
5. 只为了好笑，不承接真实场景。

---

### 24.5 产品演进关系

更准确的演进关系是：

```text
社交动物测试
= 验证“用户愿不愿意用第三方标签表达自己”

圈层身份表达生成器
= 把这个机制扩展成“用户可主动控制的社交表达工具”
```

也就是说：

1. 社交动物测试验证 **传播外壳**；
2. 身份表达生成器验证 **真实表达需求**；
3. 如果二者都成立，Meetu 才能进入更后面的连接/活动/匹配承接。

因此当前不能急着做复杂社交链路。下一步应该先验证：

- 用户是否愿意主动选择场景和边界；
- 用户是否愿意发生成图；
- 朋友是否会自然接话；
- 有没有人因为这张图产生“我也想认识/我也想加入/我也想生成”的行动。

这才是它和社交动物测试最大的区别。

---

## 25. 用户链路 friction 复盘：当前方案门槛偏高，必须从“自我认知输入”改成“情境选择 + 默认生成”

### 25.1 客观判断

当前 PRD v0.1 的链路是：

```text
选择生成目的 → 选择圈层/兴趣 → 选择边界 → 选择被谁看到 → 选择语气 → 生成结果
```

这个链路逻辑完整，但对 P0 来说 friction 偏高。

主要问题是：它假设用户已经清楚知道：

- 我这张图要干嘛；
- 我属于哪个圈层；
- 我有哪些边界；
- 我想被谁看到；
- 我想用什么语气表达。

这对核心用户反而太难。因为目标用户本来就是“想表达，但不想高压直白表达”的人。他们很多时候不是没有需求，而是需求处在模糊状态：

```text
我有点想被看见，但我不想显得很想被看见。
我想找同类，但我不知道怎么开口。
我有边界，但我不想先把边界列出来。
```

如果产品一上来要求他们把目的、偏好、边界讲清楚，就会重新变成“填写自我介绍表”。这和我们要解决的问题冲突。

结论：

> P0 不能让用户先完成清晰自我认知，再生成表达物；应该先给用户一个容易认领的情境外壳，让用户在低压选择中被带出来。

---

### 25.2 主要 friction 点

#### Friction 1：目标选择太像产品问题

问题：

```text
这张图想干嘛？找同类 / 找搭子 / 表达状态 / 发朋友圈 / 活动前破冰
```

这是 PM 视角的分类，不是用户当下的心理语言。用户很可能不知道自己到底是想找同类、找搭子，还是只是想发个状态试探一下。

更低摩擦的方式应该是情境选择：

```text
你现在更像哪种状态？
A. 有点想认识人，但不想主动
B. 想发点东西，但不想太明显
C. 想找人一起做点事，但怕尬
D. 想说明边界，但不想显得难搞
```

这样用户不需要先定义目的，只需要认领状态。

---

#### Friction 2：边界选择太早、太理性

“你的边界是什么？”这个问题在产品逻辑上重要，但在用户心理上很硬。

边界是敏感信息。用户不一定愿意一开始就承认：

- 我不想尬聊；
- 我不想被催回复；
- 我不想被拍脸；
- 我不想查户口。

这些直接列出来，会让用户感觉自己在填写社交规则，甚至觉得自己“要求很多”。

更好的方式是把边界藏进表达模板里，作为可编辑结果，而不是前置必选：

```text
生成后默认出现：
使用说明：熟了会自动开机，别上来查户口。

用户可以点“换一句边界”。
```

也就是说：

> 边界应该默认生成、后置调整，而不是前置填写。

---

#### Friction 3：圈层/兴趣选择容易变成标签压力

让用户选“游戏/Kpop/二次元/livehouse/运动/citywalk”等圈层，看似降低输入，但也会带来两个问题：

1. 用户怕选了以后输出太窄；
2. 用户不确定自己是否“够格”属于某个圈层。

例如“我偶尔听 Kpop，但不算追星”；“我想 citywalk，但不想显得很 lifestyle”。

因此 P0 不应该把圈层作为第一层必选，而应该把它变成可选增强项：

```text
先选状态 → 生成通用表达 → 可选加一点兴趣味道
```

---

#### Friction 4：语气选择对用户要求太高

“正常/抽象/嘴硬/大字报/朋友圈/群聊”是内容生产视角，不是普通用户视角。

用户通常不会想：“我要嘴硬风。”

他们更可能想：

```text
别太认真。
损一点。
像朋友帮我写的。
别像广告。
能不能更疯一点。
```

所以语气选择应该改成结果页调节按钮，而不是流程步骤：

- 换损一点；
- 换正常一点；
- 换更像朋友圈；
- 换更适合发群里。

---

#### Friction 5：6 步流程过长，不适合作为冷启动入口

P0 的核心验证是“愿不愿意生成并发出去”。如果生成前需要 5-6 次选择，用户还没看到价值就先流失。

参考社交动物测试能跑通的原因：用户先做题，是因为测试本身有娱乐性。但身份表达生成器如果只是连续选择，就没有同样的娱乐补偿。

因此 P0 应该控制在：

```text
2 步生成，结果页再调。
```

---

### 25.3 建议改成“低认知负担链路”

#### 新 P0 链路

```text
入口页
  ↓
选择一个当下状态（1题）
  ↓
选择一个使用场景（1题）
  ↓
直接生成 3 张候选图
  ↓
用户保存 / 换一句 / 换风格 / 加兴趣标签
```

#### Step 1：不是问目的，而是问状态

```text
你现在比较像哪种？

A. 有点想认识人，但不想主动
B. 想发点东西，但不想太明显
C. 想找人一起做点事，但怕尬
D. 想说明边界，但不想写得像规章制度
```

#### Step 2：不是问“你要表达什么”，而是问“你准备发哪”

```text
这张图准备放哪？

A. 小红书/朋友圈
B. 群聊
C. 主页置顶
D. 活动前破冰
```

#### 直接生成

系统根据状态 + 使用场景，默认生成：

1. 一张图；
2. 一句标题；
3. 一段可复制文案；
4. 一个默认边界句；
5. 一个朋友接话点。

用户看到结果后，再做轻调整。

---

### 25.4 结果页才是主要编辑区

P0 不应该把编辑压力放在生成前，而应该放在生成后，因为用户看到结果后才知道自己想不想改。

结果页按钮：

- 换一句更像我；
- 损一点；
- 正常一点；
- 更适合发群里；
- 加一点兴趣标签；
- 换张图；
- 保存。

这样用户不是在空白状态里“定义自己”，而是在一个已有结果上“认领/修正”。

心理上这更轻：

```text
不是让我从 0 写我是谁，
而是给我一个像我的东西，我挑刺。
```

这个机制更接近 SBTI 和社交动物测试的低摩擦点：先给结果，再让用户嘴硬。

---

### 25.5 P0 应降低为“半生成、半测试”的体验

完全自由生成会让用户压力大；纯测试又会失去主动表达能力。

更合适的 P0 形态是：

```text
1 分钟内，选 2 个轻问题，生成 3 张“像你但可编辑”的表达卡。
```

它不是测试，但可以借测试的低摩擦：

- 不让用户写长文本；
- 不要求用户明确自我认知；
- 先输出一个可吐槽结果；
- 让用户通过“换一句/损一点/正常一点”表达偏好。

这比原先“选择目的/圈层/边界/语气”的链路更适合冷启动。

---

### 25.6 修订后的 P0 及格线

原及格线只看开始生成率/完成生成率/保存率。修订后应重点看 friction 是否真的降低：

| 指标 | 目标 |
|---|---|
| 入口页 → 第一步选择 | ≥75% |
| 两步完成率 | ≥65% |
| 看到结果后保存/复制 | ≥30% |
| 点击“换一句/损一点/正常一点” | ≥25% |
| 用户没有保存但截图/停留超过 10 秒 | 作为弱信号记录 |
| 用户评论“这个像我/帮我也做一个/怎么生成” | 强信号 |

如果两步完成率低于 50%，说明这个方向仍然太抽象，不该继续加功能。

---

### 25.7 当前产品判断

这个方向仍然有真实需求，但原 PRD 链路高估了用户的自我认知清晰度。

更准确的产品原则应该是：

> 不要让用户先想清楚自己是谁；先给他一个可以嘴硬认领的表达物。

因此 P0 应从“问卷式生成器”调整为“低压认领式生成器”：

```text
少问、先生成、结果页再调。
```

这能同时保留社交动物测试的低 friction，又把它推进到“用户可主动表达”的方向。

---

## 26. Friction 与输出质量的平衡：从“一刀切少问”修正为“分层输入 + 渐进编辑”

### 26.1 对第25章的修正

第25章强调“少问、先生成、结果页再调”，这是为了避免把产品做成高压自我介绍表。但这个原则不能被理解为“尽量不收集信息”。

如果输入太少，输出会出现两个问题：

1. **内容泛化**：生成结果像通用朋友圈文案，用户觉得“不像我”；
2. **场景错位**：用户想发群聊，结果像小红书；用户想找自习搭子，结果变成精神状态图。

因此 P0 的正确原则不是“少问”，而是：

> 用最少的必填问题，收集最高信息密度的输入；再用可选问题和结果页编辑补足个性化。

也就是：

```text
低 friction ≠ 低信息量
低 friction = 不让用户在空白状态下做高认知决策
```

---

### 26.2 输入分层模型

P0 应将输入分为 3 层。

#### L1：必填输入，用来保证结果不跑偏

必填不应该超过 3 个问题，但每个问题都必须直接影响输出。

建议必填：

1. **当前状态**
   - 你现在更像哪种？
   - 决定整体心理基调。

2. **使用场景**
   - 这张图准备发哪？
   - 决定文案长度、语气和视觉结构。

3. **表达方向**
   - 你更想让它替你说什么？
   - 决定 output 的核心任务。

示例：

```text
你更想让它替你说什么？
A. 我是什么样的人
B. 我想找什么同类
C. 我有哪些相处边界
D. 我现在是什么精神状态
```

这 3 个问题可以把输出从“泛泛好玩”拉回“符合预期”。

---

#### L2：可选输入，用来提升个性化

用户可以跳过，但产品要引导：

```text
想更像你，可以再选几个词；不选也能生成。
```

可选项：

- 兴趣/圈层：游戏、Kpop、二次元、livehouse、运动、自习、拍照、桌游；
- 边界：不尬聊、不催回复、不查户口、可少说话、不拍脸、AA；
- 人设语气：嘴硬、正常、抽象、朋友锐评、大字报、群聊；
- 地域/关系范围：同校、同城、同兴趣、熟人可见、只给朋友。

关键：这些不是问卷步骤，而是 **“加料项”**。

用户不选，系统也能生成；用户选了，结果更准。

---

#### L3：结果页编辑，用来收集真实偏好

结果页是最适合收集偏好的地方，因为用户已经看到一个初稿，知道自己哪里不满意。

按钮不应该叫“编辑”，而应该叫：

- 更像我一点；
- 换个不那么尴尬的说法；
- 损一点；
- 正常一点；
- 别太像广告；
- 加一点边界；
- 加一点兴趣味；
- 更适合发群里；
- 更适合发小红书。

这些点击本身就是高价值偏好数据，比前置问卷更真实。

---

### 26.3 推荐 P0 链路 v2

```text
入口页
  ↓
Step 1：选当前状态（必填）
  ↓
Step 2：选使用场景（必填）
  ↓
Step 3：选表达方向（必填）
  ↓
可选加料：兴趣/边界/语气（可跳过）
  ↓
生成 3 张候选
  ↓
结果页调节：更像我/损一点/正常一点/加边界/换场景
  ↓
保存图片 / 复制文案 / 再生成
```

这个链路不是“一刀切两步”，而是“3 个高信息密度必填 + 可跳过加料 + 结果页渐进编辑”。

---

### 26.4 为什么这个链路更平衡

| 问题 | 原 6 步链路 | 一刀切 2 步链路 | 修正版 v2 |
|---|---|---|---|
| friction | 高 | 低 | 中低 |
| 信息量 | 高 | 偏低 | 足够 |
| 用户压力 | 高 | 低 | 可控 |
| 输出准确性 | 较高 | 不稳定 | 较高 |
| 个性化 | 强但像问卷 | 弱 | 渐进增强 |
| 数据价值 | 前置声明多但可能不真实 | 数据不足 | 结果页行为数据更真实 |

修正版的关键是：

> 必填问题负责防止输出跑偏，可选输入负责个性化，结果页行为负责真实偏好。

---

### 26.5 必填问题如何设计才不增加压力

必填问题必须满足 3 个条件：

1. **像认领，不像填写**
   - 错误：请选择您的社交目的。
   - 正确：这张图更像要替你说哪句话？

2. **选项是状态语言，不是产品分类**
   - 错误：找搭子 / 破冰 / 身份表达。
   - 正确：想认识人但不想主动 / 想发点东西但不想太明显。

3. **每题不超过 4 个选项**
   - 让用户凭直觉选，不要让用户比较 10 个标签。

P0 最好不要出现输入框。自由文本会显著提高压力，也会增加审核和生成不稳定性。

---

### 26.6 输出质量的最低保障

为了避免“低 friction 导致低质量”，系统必须内置足够强的模板和默认逻辑。

每个输出至少由 5 个变量决定：

```text
状态 × 使用场景 × 表达方向 × 默认边界 × 语气模板
```

例如：

```text
状态：想认识人但不想主动
使用场景：群聊
表达方向：找同类
默认边界：不尬聊、不查户口
语气模板：朋友锐评
```

输出就不会泛化成普通文案，而会更像：

```text
低压同类招领
需要一个能一起坐着的人
可少说话，不查户口，熟了会自动开机
```

这说明：低 friction 不能靠少问硬省，而要靠产品预设更聪明。

---

### 26.7 新的产品原则

综合第25章和第26章，P0 原则修正为：

1. **必填少，但必须高信息密度；**
2. **能跳过，但不能让输出失真；**
3. **不让用户先写自己，而是先认领状态；**
4. **把边界/语气/圈层从前置问卷改成可选加料；**
5. **把结果页编辑当成主要偏好采集；**
6. **生成结果至少给 3 个候选，避免一次不准就流失。**

最终一句话：

> P0 不是减少问题，而是减少用户做困难决定的次数。

这是 friction 和 output quality 的平衡点。

---

## 27. 技术复杂度复盘：MVP 必须收缩为“规则模板生成器”，不能做真正智能生成器

### 27.1 客观判断

如果按第26章完整设想直接实现：

```text
3个必填输入 + 可选加料 + 3张候选图 + 多种结果页编辑 + 多场景文案 + 多视觉模板
```

并且每次都希望输出高度个性化，那么技术复杂度会偏高，不像 MVP。

复杂点主要来自：

1. **文案生成复杂**：要根据状态、场景、表达方向、边界、兴趣、语气组合生成自然文案；
2. **视觉生成复杂**：不同场景需要不同卡片样式；
3. **结果编辑复杂**：换一句、损一点、正常一点、加边界，如果都是真生成，会变成多轮生成系统；
4. **质量控制复杂**：自由生成容易出现油腻、广告感、误伤、错语气；
5. **性能和成本复杂**：如果接 AI 图片或大模型实时生成，成本、延迟和失败率都会上升；
6. **审核复杂**：如果允许用户自由输入，内容安全和限流风险都会增加。

所以：

> 这个方向成立不等于 P0 要做“AI 生成器”。P0 应该做“看起来像生成器的规则模板系统”。

---

### 27.2 P0 技术边界：不做什么

P0 明确不做：

1. 不做账号系统；
2. 不做登录；
3. 不做公开发布墙；
4. 不做匹配/私信/群聊；
5. 不做自由文本输入；
6. 不做拖拽式图片编辑器；
7. 不做实时 AI 图片生成；
8. 不做大模型实时文案生成；
9. 不做用户作品存储；
10. 不做复杂埋点平台，只保留基础事件。

这样才能保证它还是 MVP。

---

### 27.3 P0 应采用的技术方案

P0 技术上应做成：

```text
静态 H5 + 规则映射 + 预设模板 + html2canvas 导出
```

#### 数据结构

用本地数据表维护：

- 状态选项；
- 使用场景；
- 表达方向；
- 可选加料标签；
- 文案片段库；
- 视觉模板配置；
- 结果卡模板。

#### 生成逻辑

不是调用 AI，而是规则拼装：

```text
状态 × 使用场景 × 表达方向 → 选定模板
模板 + 默认边界 + 语气片段 → 生成 3 张候选
可选加料 → 替换局部词句
```

#### 结果页编辑

“损一点 / 正常一点 / 更适合发群里”不是实时生成，而是切换预设 variant：

```text
same payload + toneVariant = roast / normal / group / xhs
```

这样可以保持稳定、低成本、低风险。

---

### 27.4 推荐 MVP 范围

MVP 只需要这些能力：

1. **3 个必填问题**
   - 当前状态；
   - 使用场景；
   - 表达方向。

2. **可跳过加料项**
   - 最多 8-12 个 chip；
   - 用户可不选。

3. **生成 3 张候选卡**
   - 不是无限生成；
   - 每张来自预设模板组合。

4. **结果页 4 个按钮**
   - 保存图片；
   - 复制文案；
   - 换个语气；
   - 再生成。

5. **基础分享图导出**
   - 复用社交动物测试已有 html2canvas 经验；
   - 控制尺寸和长按保存路径。

6. **轻量埋点**
   - start；
   - complete；
   - save；
   - copy；
   - reroll；
   - tone_change。

这已经足够验证核心问题：

> 用户是否愿意生成、保存、复制、发出去。

---

### 27.5 模板数量也要控制

P0 不需要覆盖全部大学生场景。

建议只做：

- 4 个当前状态；
- 4 个使用场景；
- 4 个表达方向；
- 4 套视觉模板；
- 每套 3 个语气 variant。

理论组合很多，但实际不需要全部手写。可以用基础模板 + 局部片段替换。

P0 真实工作量应控制在：

```text
4 套视觉模板
40-60 条文案片段
12 张人工精选 golden sample
一个规则映射函数
```

这才像 MVP。

---

### 27.6 为什么不建议 P0 接 AI

AI 可以放在 P1，不建议放在 P0。

原因：

1. **生成不稳定**：语气可能油腻、过度解释、像营销；
2. **审核难**：用户输入和生成内容都有风险；
3. **延迟高**：影响完成率；
4. **成本不可控**；
5. **验证目标会混淆**：我们想验证的是需求，不是模型能力。

P0 应先用规则模板验证：

- 用户是否愿意玩；
- 生成物是否愿意发；
- 朋友是否接话；
- 哪类模板保存率最高。

如果这些成立，再在 P1 接 AI 提升个性化。

---

### 27.7 技术实现复杂度评估

按收缩后的方案，复杂度类似“社交动物测试 H5 的变体”，不是新平台。

| 模块 | 复杂度 | 说明 |
|---|---|---|
| 选择流程 | 低 | 3题 + chip 选择 |
| 文案生成 | 中低 | 规则模板，不接 AI |
| 卡片视觉 | 中 | 4套 HTML/CSS 模板 |
| 图片导出 | 中 | 复用 html2canvas 经验 |
| 结果编辑 | 中低 | variant 切换，不是真编辑器 |
| 数据存储 | 低 | P0 可不存用户作品 |
| 后端 | 可无 | 静态 H5 即可跑 |
| 风险控制 | 中低 | 无自由输入，风险可控 |

因此：

> 如果做成 AI/编辑器/账户/发布平台，会过重；如果做成静态规则模板 H5，是合理 MVP。

---

### 27.8 P0 成败判断必须和技术范围绑定

P0 成功不是证明“完整产品已经成立”，而是证明：

1. 用户愿意完成 3 个轻输入；
2. 生成结果有“像我”的感受；
3. 用户愿意保存/复制；
4. 用户愿意发到外部场景；
5. 外部朋友有接话行为。

P0 失败也要能判断原因：

- 如果完成率低：输入仍太重；
- 如果保存率低：输出不像人/不好看；
- 如果保存高但没人发：使用场景不成立；
- 如果发了没人接话：表达物没有传播钩子；
- 如果用户说像广告/自介表：产品气质跑偏。

所以 MVP 技术实现必须轻，才能快速判断这些问题，而不是陷在工程复杂度里。

---

### 27.9 修订后的产品原则

综合技术复杂度，当前 PRD 的 P0 原则进一步修正为：

> 用静态规则模板，做一个“像生成器”的低压表达卡 H5，验证用户是否愿意把它发出去。

不追求一次就个性化到极致，不做自由创作工具。

P0 的关键词不是：

```text
智能生成 / 完整编辑 / 高自由度 / 平台化
```

而是：

```text
低输入 / 稳定输出 / 愿意保存 / 愿意发 / 朋友能接话
```

这才符合 MVP。
