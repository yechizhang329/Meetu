## 0. PM 结论

**心情值班室方向继续。**

被否定的不是“具象情绪代理人 / 心情值班室 / 动物员工 / 生图资产 / 静态 H5”这个方向，而是此前做出来的产品状态：

- 像产品在生成结果卡；
- 像测试/分类/标签；
- 像设计系统拼装；
- 不像用户真的会顺手发出去的嘴替内容。

本轮修正后的核心不是：

> 这很像我 / 这很符合我的心情。

而是：

> **这只东西替我说了我不想自己说的话。**

所以后续所有判断都围绕一句话：

> **用户愿不愿意把这张图发出去，让它替自己开口？**

只要答案是否定，不管设计多完整、技术多顺、文案多巧，都不推进。

## 1. 客户视角：她为什么会用

### 1.1 她不是来“做测试”的

她不是想知道自己是什么类型，也不是想被系统判定。她已经知道自己今天很累、嘴硬、拖延、表面正常。

她真正想要的是：

- 我不想亲口说“我累了”；
- 我不想显得自己在求关心；
- 我不想直接拒绝别人；
- 我不想承认被说中了；
- 我想发点东西，但又想留一点嘴硬空间。

所以产品不是替她“识别状态”，而是替她“开口”。

### 1.2 她为什么需要具象角色

因为一句话如果由她自己说，会太重；由角色说，就变轻。

例如：

```text
我今天不想营业。
```

这句话直接发，有点像情绪宣言。

但如果变成：

```text
低电量猫今天替我值班：
人在，电不在。
```

它就变成一个可以被朋友接住的梗。

角色的功能不是“像她”，而是：

1. **替她承担表达**：不是我说，是它说；
2. **替她降低攻击性**：拒绝也变成玩笑；
3. **替她保留嘴硬空间**：朋友说像我，我还能说“没有”。

### 1.3 她为什么会分享

她会分享的不是“产品做得好”，而是这张图帮她完成了一个社交动作：

> 我把话放出去了，但没把自己放得太重。

分享成立需要 4 个条件：

1. **一句话本身值得发**：不解释产品也能成立；
2. **角色承担尴尬**：图里有个可爱的代理人帮她挡一下；
3. **没有产品边界感**：不像广告、测试结果、系统海报；
4. **朋友有接话点**：能评论“别装”“这就是你”“它今天也在我身体里”。

## 2. 产品第一原则

### 2.1 产品一句话

**心情值班室是一套具象嘴替 H5：用户轻选择今天不想自己说出口的话，让一只动物员工替自己说，并生成一张可以直接发出去的嘴替图。**

### 2.2 世界观一句话

> 你的身体里有一间心情值班室。每天会有一只动物出来，替你说一句你不想自己说的话。

### 2.3 不能再偏航成什么

不能做成：

- 测试结果卡；
- 情绪诊断报告；
- 精致 AI 插画集；
- 小动物设定图鉴；
- 便签/纸条表面模仿；
- Meetu 社交入口；
- 设计系统展示页。

可以学习外部案例的整体性和减法，但不能抄成别人的产品形态。

## 3. 继续保留的结构

Jonathan 指出“之前结构没问题”，所以 v0.8 的以下结构继续保留：

### 3.1 P0 4 个角色继续保留

| 角色 | 它替用户说什么 | 用户真实需求 |
|---|---|---|
| 嘴硬鹅 | “我没有。” | 被说中但不想承认 |
| 低电量猫 | “人在，电不在。” | 想拒绝营业/拒绝出门 |
| DDL 仓鼠 | “会做的，不是现在。” | 拖延、DDL、被催 |
| 后台羊驼 | “表面好的，后台炸的。” | 表面礼貌，内心过载 |

### 3.2 轻选择链路继续保留

不是问卷测试，而是帮用户定位“今天不想自己说哪类话”。

推荐链路：

1. **首页**：今天哪句话不想自己说？
2. **选场景**：今天是哪种“不想说”？
3. **选语气**：想让它怎么替你说？
4. **结果**：今天让这只替你说。
5. **保存/换一句/换一只**。

### 3.3 静态 H5 + 预生成资产继续保留

- P0 不做用户实时 AI 生图；
- Image2 用于角色和输出图资产生产；
- H5 只做选择、文案组合、导出；
- 输出图必须先过分享测试，再进工程精修。

补充执行原则：H5 不是“拼图机”。如果大量 HTML/CSS 组件拼接会让最终图看起来像产品卡片，就应该改用 Image2 生成更完整的大背景或带文字整图，再由 H5 只叠必要的可变文字。

P0 产出分三档：

1. **Image2 带文字整图**：适合固定首发爆点图，整体感强，但改字成本高；
2. **Image2 无字大背景 + H5 叠字**：P0 主路径，兼顾整体画面、可变文案和成本；
3. **纯 HTML/CSS 拼图**：只作为原型和兜底，不作为最终审美目标。

验收对象必须是最终导出的图：如果用户一眼看出是前端组件拼接，直接打回。

MVP 约束补充：实现手段不做限制，scope 必须收敛，但系统必须完整。P0 不是 4 张样张，而是“核心角色体系 + 核心场景覆盖 + 文案池 + 生成/保存/分享链路 + 运营首发路径”都成立的最小系统。4 张强嘴替输出图只是质量标杆，不是产品全量。

实现方案选择优先级：

1. 能不能让目标用户愿意发；
2. 有没有廉价拼贴/模板感；
3. 是否能用有限 Image2 call 和有限工程时间交付；
4. 是否保留后续扩展空间。

如果一个方案很省钱但廉价，淘汰；如果一个方案效果好但 scope 失控，也淘汰。P0 要在 scope 和效果之间取平衡。

成本控制是方法，不是给产品打折。出图应优先采用多图一 call / contact sheet / 角色变体合图，再在本地 crop；同一角色的动作、表情、道具变体尽量合批。每个出图任务必须说明“一 call 产几张、怎么裁、哪些复用、失败怎么处理”。

内容覆盖不能因成本牺牲。P0 至少覆盖：嘴硬否认、低电量拒绝营业、DDL/拖延、表面正常后台崩、想安静/勿扰、被约出门/不想动、消息不想回、被安排/被催。每类至少 3-5 条可发嘴替句。

## 4. 必须删除或弱化的旧元素

以下元素会把“嘴替”做成产品卡片，必须删除或降到不可见：

| 旧元素 | 问题 | 新处理 |
|---|---|---|
| 顶部大品牌 / banner | 像广告 | 品牌极小，最多角落水印 |
| 角色标签 / DDL / 焦虑 / 拖延 | 像分类和诊断 | 不出现在分享主图，必要时仅内部数据 |
| 朋友鉴定区框 | 像表单 | 朋友评价发生在分享后的评论区 |
| 结果卡结构 | 像测试结果 | 输出图像“它说了一句话” |
| 完整办公室设定 | 像职业 IP 设定集 | 保留“值班”借口，不堆办公室物件 |
| 复杂多按钮 | 像工具页 | 主动作只保留“保存这句 / 换一句 / 换一只” |
| 过度克制米黄 SaaS | 死气沉沉 | 角色色、动作和一句话要鲜活 |

## 5. 输出图验收标准

在做 H5 之前，先验证 4 张嘴替输出图。

每张图必须通过 8 问：

1. **不看产品名，这句话能不能单独发？**
2. **用户会不会觉得“这是它替我说的”，而不是“产品评价我”？**
3. **朋友能不能自然接一句？**
4. **有没有产品广告感？**
5. **有没有测试/诊断/分类感？**
6. **角色是不是帮助表达，而不是抢表达主体？**
7. **画面是否鲜活、年轻、有个性，而不是死气沉沉？**
8. **如果我是目标用户，我会不会真的发？不发就失败。**

只有 4 张样图至少 3 张通过，才允许推进 H5。

## 6. 四张 P0 嘴替输出图 Brief

> 这不是最终 prompt，是给 Lucy / Phoebe / Dave 对齐“输出物是什么”的 PM brief。

### 6.1 嘴硬鹅

用户要说但不想自己说：

```text
我没有。
```

输出图应让人感到：

- 它正在替用户嘴硬；
- 它不承认，但全身都在露馅；
- 朋友看到会想评论“别装”。

主句候选：

```text
我没有。
只是每个证据都刚好路过我。
```

或：

```text
我没被说中。
我只是沉默得比较像默认。
```

禁止：

- 做成警卫鹅设定图；
- 做成“拒签部部长”职业梗过重；
- 把“嘴硬”解释太满。

### 6.2 低电量猫

用户要说但不想自己说：

```text
今天别叫我。
```

输出图应让人感到：

- 它替用户拒绝营业；
- 拒绝是可爱的，不是攻击性的；
- 朋友看到会懂“今天别约她”。

主句候选：

```text
人在。
电不在。
```

或：

```text
今天可以找我。
但不建议唤醒我。
```

禁止：

- 做成“电量测试”；
- 做成低电量 UI 卡；
- 过度可爱到幼态。

### 6.3 DDL 仓鼠

用户要说但不想自己说：

```text
别催了，我知道。
```

输出图应让人感到：

- 它替用户拖延和自救；
- 焦虑是荒诞的，不是沉重的；
- 朋友会评论“你又这样”。

主句候选：

```text
会做的。
不是现在。
```

或：

```text
我没有拖。
我只是在等一个更危险的时间。
```

禁止：

- 做成可爱仓鼠贴纸；
- 做成 DDL 教育海报；
- 物件太多、太焦虑。

### 6.4 后台羊驼

用户要说但不想自己说：

```text
我表面正常，但其实已经炸了。
```

输出图应让人感到：

- 它替用户维持体面；
- 表面礼貌和后台崩溃形成反差；
- 朋友会评论“你平时就是这样”。

主句候选：

```text
我在听。
只是后台开了十八个窗口。
```

或：

```text
表面：好的。
后台：不要再来了。
```

禁止：

- 做成软件 UI 报警；
- 做成办公系统插画；
- 表情太木，没有反差。

## 7. H5 体验重设

### 7.1 首页

首页不是 landing page，不解释产品价值。

首页要像一个入口动作：

```text
今天哪句话不想自己说？

叫一只出来替你说。
```

主 CTA：

```text
叫一只出来
```

首页必须有一个角色锚点，但不能像品牌吉祥物展示。它应该像“已经在等你开口”的嘴替。

### 7.2 场景选择

问题不是“今天你是什么状态”，而是：

```text
今天哪句话最不想自己说？
```

选项应是用户的真实难开口场景：

- 今天别叫我；
- 我没有被说中；
- 别催，我知道；
- 我表面没事；
- 我不想解释；
- 我想先躲一下。

### 7.3 语气选择

语气不是测试维度，而是“你希望它替你怎么说”：

- 嘴硬一点；
- 客气一点；
- 摆烂一点；
- 阴阳一点。

### 7.4 结果页

结果页主标题：

```text
今天先让它替你说。
```

结果页不展示“你是 XX”。展示：

- 一只角色；
- 三句它可以替你说的话；
- 保存/换一句/换一只。

## 8. 文案重写原则

旧 96 条文案的矩阵结构可以保留，但文案本身不再当 final。

新文案规则：

1. **像角色替我说，不像产品给我写金句**；
2. **短，能截图，能当朋友圈状态**；
3. **保留嘴硬空间，不把话说死**；
4. **不解释状态，不讲道理**；
5. **有生活细节或反差，不靠押韵和工整**；
6. **朋友能接话**。

错误方向：

```text
我只是把社交带宽借给自己用一下。
```

问题：像精心设计的产品段子。

更接近的方向：

```text
今天别叫我。
我会假装没看见。
```

或：

```text
我没有生气。
我只是突然很会安静。
```

## 9. 设计重写原则

设计不是“更精致”，而是更像用户愿意发的嘴替图。

### 9.1 视觉主体

主体不是产品框，不是角色设定，也不是 UI 卡片。

主体是：

> 角色替用户说出的那句话。

角色服务这句话。

### 9.2 角色占比

不能机械规定 10%、40%、50%。按嘴替关系决定：

- 如果角色动作足够强，角色可以更大；
- 如果文字才是主梗，角色可以变小；
- 但无论大小，角色不能变成“产品吉祥物站台”。

### 9.3 品牌处理

品牌只作为出处，不作为视觉元素。

原则：

> 用户分享时不能觉得自己在替产品打广告。

### 9.4 色彩处理

不能继续死气沉沉，也不能变成粉甜模板。

需要：

- 角色色带来个性；
- 背景轻，但不灰；
- 每个角色有鲜明但克制的色彩记忆；
- 画面有一个情绪重心。
