## 0. 本版为什么存在

v1.0 的核心方向“动物嘴替 / 心情值班室”仍成立，但 v1.0 在执行范围上留下了歧义：

- 容易被误执行成单张低电量猫 demo；
- 容易被误执行成 8 个默认组合；
- 没有把 `8 场景 × 4 动物 = 32 结果组合` 写成硬要求；
- 没有把 scene / character 分离建模写成工程硬约束；
- 没有把结果页 4 动物切换、32 组合批量 QA 写成验收标准。

因此 v1.1 只做一件事：**把 P0 产品完整性写死，作为今晚及后续执行唯一基准。**

如本文件与 v1.0 或 Slock 过程消息冲突，以本文件为准。

## 1. 产品一句话定义

**心情值班室是一套具象嘴替 H5：用户选择一个今天不想自己说出口的场景，再选择/切换一只动物代理人，生成一张“它替我说了”的今日代班凭条。**

用户心理：

```text
这句话我不想自己说，但它替我说了。
不是我说的，是这只动物代班说的。
```

---

## 2. P0 不再是 demo，必须是完整产品

### 2.1 P0 硬范围

P0 必须完整覆盖：

```text
8 个场景 × 4 个动物 = 32 个结果组合
```

这 32 个组合都必须能：

- 在数据层存在；
- 在结果页访问/切换；
- 渲染为同一视觉系统下的结果图；
- 导出 1080×1350 PNG；
- 通过批量 QA 的基本质量检查。

### 2.2 MVP 可以降级什么

可以降级：

- 纸纹、油墨、字体等 final 精修；
- 部分动物头像的细节精度；
- 动效；
- 运营首发物料；
- 高级编辑能力。

不可以降级：

- 8 个场景；
- 4 个动物；
- 32 个结果组合；
- 结果页 4 动物切换；
- 保存图导出；
- 无明显错字、溢出、遮挡、读法错误；
- 动物身份和场景语义可识别。

**场景不全、动物不全、组合不全，都只能叫 demo，不叫 P0 产品。**

## 3. P0 场景与动物矩阵

### 3.1 8 个场景

| 场景 ID | 场景名 | 用户时刻 | 场景选择页表达 |
|---|---|---|---|
| S1 | 嘴硬否认 | 被朋友说中但不想承认 | 被说中了，但我不准备承认 |
| S2 | 低电量拒绝营业 | 不想说话、不想动 | 人还在，电先下班了 |
| S3 | DDL 拖延 | 被催任务/作业 | 会做的，不是现在 |
| S4 | 表面 OK 后台崩 | 表面礼貌答应，内心过载 | 表面好的，后台别来了 |
| S5 | 想安静别问 | 不想被追问 | 想安静一点，先别问 |
| S6 | 约但身体没签 | 被约出门但身体拒绝 | 朋友约我，但身体没签字 |
| S7 | 消息看到没回 | 看到了但不想回 | 消息看到了，嘴没上班 |
| S8 | 被催被安排 | 被安排、被推着走 | 被催到了，但我想把话甩出去 |

### 3.2 4 个动物

| 动物 ID | 动物名 | 职能 | 视觉/语气关键词 |
|---|---|---|---|
| goose | 嘴硬鹅 | 嘴硬、否认、边界防守 | 心虚但嘴硬 |
| cat | 低电量猫 | 下线、拒绝营业、低电量 | 没电、不营业 |
| hamster | DDL 仓鼠 | 拖延、先放一放、临门一脚 | 忙乱但不急 |
| alpaca | 后台羊驼 | 表面镇定、礼貌撑住、后台崩 | 表面 OK 后台尖叫 |

### 3.3 32 组合原则

每个场景都可以由每只动物代班，因此：

```text
S1 × goose/cat/hamster/alpaca
S2 × goose/cat/hamster/alpaca
...
S8 × goose/cat/hamster/alpaca
```

不能把某个场景硬绑定成唯一动物。可以有默认推荐动物，但默认推荐不等于产品范围。

## 4. 数据模型硬要求

### 4.1 工程模型

必须分离：

```ts
sceneBase[sceneId]
characterLayer[characterId]
overrides[sceneId][characterId]
```

渲染入口必须支持：

```ts
renderReceipt({ sceneId, characterId })
```

### 4.2 sceneBase 字段

每个 scene 至少包含：

```ts
type SceneBase = {
  id: 'S1' | 'S2' | ... | 'S8'
  label: string              // 场景选择页文案
  l2Lines: [string, string, string]  // 嘴替主句三行
  scope: string              // 负责范围，如“拒绝营业”
  stampLines: [string, string]       // 红章两行，如“低电量 / 值班中”
  footerLines: string[]      // footer 钩子，可统一也可按场景微调
}
```

### 4.3 characterLayer 字段

每个 character 至少包含：

```ts
type CharacterLayer = {
  id: 'goose' | 'cat' | 'hamster' | 'alpaca'
  name: string               // 嘴硬鹅 / 低电量猫 / DDL 仓鼠 / 后台羊驼
  signText: string           // 硬鹅 / 低猫 / DDL / 羊驼
  accent: string             // 角色色
  avatar: string             // avatar asset key
  handoffVerb?: string       // 接管 / 代班 / 顶上等，默认“接管”
}
```

### 4.4 overrides 字段

如果某个 scene×character 组合直接拼接会违和，用 override 修正，不允许删组合。

```ts
type CombinationOverride = {
  l2Lines?: [string, string, string]
  scope?: string
  stampLines?: [string, string]
  footerLines?: string[]
  note?: string              // 为什么 override
}
```

## 5. 结果图视觉系统

### 5.1 当前锁定方向

当前 P0 视觉系统为：

```text
B-young-adult：今日代班凭条
```

参照物：

- 奶茶小票；
- 外卖/快递签收单；
- 电子票；
- 生活里低权威、可截图、可自嘲的小凭条。

不是：

- 学生证 / 校园通知 / 课代表；
- 工牌 / 公司单据 / 会议工单；
- 红头文件 / 政府证明 / 正式授权书；
- 手账日记页。

### 5.2 固定版式

输出图统一 1080×1350，五层结构：

1. L1 表头：`心情值班室 · 今日代班凭条` + 编号 + `已签收`；
2. L2 嘴替主句：三行大字；
3. L3 动物接管：`本次由：{动物名} 接管` + `负责范围：{scope}` + 签名；
4. L4 今日状态：生效时间 / 有效期 / 歪章；
5. L5 footer：`这张单子可以：` + 轻量权益 + 弱 `No.xxx`。

### 5.3 质量底线

低保真也必须满足：

- footer 不出画；
- 红章文字正常可读；
- 动物 avatar 能识别出是哪只动物；
- 三行嘴替不溢出；
- 签名不遮挡信息；
- `No.xxx` 不像广告署名；
- 没有 `meetu.asia` 之类破坏 UGC 感的显性域名；
- 没有校园/职场/机关残留词。


### 5.4 Image2 使用原则：质量优先，call 效率优化

成本控制不是不用 Image2，也不是用低质量 CSS stub 替代关键质感元素。

P0 必须用 Image2 或同等级高质量素材解决影响产品质感的可复用元素：

- 4 个动物 avatar / sticker portrait；
- 纸纹底材；
- 铁锈红油墨章纹理；
- 抓痕 / 手写签名装饰。

成本控制方式是提高 call 效率：

- 一次 call 产 contact sheet / 多元素素材包；
- 无字素材优先，避免中文文字不可控；
- 本地裁切、抠图、复用；
- 4 动物资产跨 32 组合复用；
- 纸纹、章纹、抓痕作为模板级资产复用。

不推荐用 Image2 生成 32 张带字整图，因为文字稳定性、后续改文案、32 组合维护都会失控；但这不等于不用 Image2。

每次 Image2 生产必须说明：本 call 目标、一次出哪些素材、如何裁切复用、预计总 call 数。

## 6. H5 体验要求

### 6.1 链路

P0 链路仍是：

```text
Intro → Scene Select → Result
```

### 6.2 Scene Select

必须展示 8 个场景。

用户选择的是“不想自己说出口的场景”，不是先选动物。

### 6.3 Result

用户进入结果页后，必须能看到：

- 当前 scene 的结果图；
- 当前 character；
- 同一 scene 下 4 个动物版本的切换入口；
- 保存这张；
- 换一句 / 换一只（如实现成本冲突，至少保留 4 动物切换）；
- 结果图预览必须等同最终可保存图，不做 DOM 复刻预览。

### 6.4 路由建议

建议支持：

```text
#/result/:sceneId/:characterId
```

例如：

```text
#/result/S2/cat
#/result/S2/goose
```

如果内部仍用 hash route，可保持现有工程习惯，但语义必须支持 sceneId + characterId。

## 7. 文案要求

### 7.1 文案交付形态

Lucy 交付不是 8 条，也不是 32 条纯手写死表，而是：

1. `sceneBase`：8 个场景基础嘴替；
2. `characterLayer`：4 个动物口吻/签名/角色字段；
3. `overrides`：32 组合中需要微调的地方。

### 7.2 文案质量线

每个组合必须满足：

- 用户可能真会想这么说；
- 动物说出来更轻、更好发；
- 朋友能自然接话；
- 不像广告 slogan；
- 不像测试结果；
- 不像心理诊断；
- 不出现校园/职场/机关错位词。

## 8. 工程验收标准

### 8.1 功能验收

必须全部通过：

- Intro 页面可进入；
- Scene Select 显示 8 场景；
- 每个 scene 可进入结果页；
- 每个 scene 下可切 4 动物；
- 32 个 scene×character 组合都有结果图；
- 32 张导出图都是 1080×1350；
- 保存图在桌面可下载；
- iOS/微信 fallback 仍可长按保存；
- proof theme 可回退；
- active theme 为 `duty-badge-young-adult`。

### 8.2 批量 QA

必须有一条批量 QA 路径，至少检查：

- 32 组合是否都能渲染；
- 32 张 canvas 是否都是 1080×1350；
- 是否存在明显 JS error / pageerror；
- 是否存在空文案 / placeholder / internal id；
- 是否存在超出画布的 footer 或主句。

建议 QA 输出：

```text
artifacts/qa/receipt-matrix/S1-goose.png
...
artifacts/qa/receipt-matrix/S8-alpaca.png
```

### 8.3 统一审核，不逐图 gate

PM 不再对每张图逐步 gate。下一次 PM 审核看完整批量产物：

- H5 链路；
- 32 组合矩阵；
- 批量 QA 截图；
- 保存链路；
- 三方质量问题清单。
