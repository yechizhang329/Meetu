# Agent-Reach 深度研究：Meetu 产品/需求匹配与低成本高收益方向

负责人：Fiona  
研究工具：Agent-Reach / XHS CLI，只读采样；未点赞、未收藏、未评论、未关注、未发布。

> 重要更正：本报告推翻前一版「排版小动物相邻样本」的窄口径。这里不再研究“还能做什么像排版小动物”，而是研究：大学生在小红书上真实暴露了哪些高频需求、哪些需求有行动意图、哪些和 Meetu 的产品能力匹配，并从低成本实现/高潜在收益的比值里锁一个方向。

## 3. 关键发现

### 3.1 大学生在小红书上不是只“看内容”，大量场景是在把评论区当临时产品用

高信号样本：

- `想认识各专业的大学生！！！`：评论区大量直接报专业，像一个“专业身份报到广场”。
- `赐我一个长久聊天搭子吧`：评论区大量 `07女大dd`、`蹲一个聊天搭子`、`不要次抛`。
- `找搭子，可加wx，一起努力吧`：评论区直接按年级/科目/学习方式报到。
- `大学生互帮互助群，一起来加油`：互助群本身成为需求承接。
- `学校二手群笑死我了` / `跳蚤群不是垃圾群`：校园二手群不仅交易，也承载梗、信任、校内身份。

这说明：用户已经在用小红书“发帖 + 评论 + 私信”完成找人、找资源、找群、找物、找活动。只是这个流程很乱、低效、不安全、难沉淀。

### 3.2 最高赞的“信息差”不是最适合做 P0 产品，但它说明了一个底层需求：大学生需要一个低门槛的“校园入口/门牌”

`大学生如何打破信息差`类笔记收藏极高，说明用户愿意保存“资源入口”。但如果 Meetu 直接做信息差资料库，会遇到三件事：

1. 红海：已有大量资料号、公众号、飞书表、网盘资料。
2. 更新成本：实习、竞赛、校内群、资料链接容易失效。
3. Meetu差异弱：它更像内容站，不像校园社交/交易/活动的桥梁。

但它给我们的启发是对的：用户缺的不是“再一篇科普”，而是当下具体问题该去哪里找人/找资源/找机会。

### 3.3 找搭子/找人类需求互动分不最高，但行动意图最高

找搭子类样本里，“评论就是动作”：

- `dd`
- `蹲`
- `求带`
- `可加wx`
- `不要日抛`
- `想找话多的`
- `视频监督不露脸`

这类内容的商业/产品价值不在高赞，而在“每条评论都是一个可匹配的需求”。这比单纯点赞收藏更接近 Meetu 要的真实关系和交易闭环。

### 3.4 宿舍关系/孤独情绪很大，但 P0 不该直接碰

宿舍关系样本中，评论高度真实，痛感强，但主要是倾诉、共情、求安慰。它可以作为内容话题和用户理解来源，不适合作为第一版产品入口：

- 风险：隐私、矛盾升级、负面情绪、网暴/挂人。
- 产品难点：用户不是要一个“工具”，而是要被理解、被支持、被验证。
- Meetu切入方式：后续可做“匿名倾诉/宿舍避雷话题”，但不应作为低成本高收益 P0。

### 3.5 线下活动/周末去哪有高收藏，但供给侧比需求侧更难

`和朋友出去玩除了吃饭还能做的一些事`、志愿者攻略、城市资源类内容表现好，说明用户需要活动灵感。但真做起来会遇到：

- 本地供给持续维护；
- 活动安全与履约；
- 组织者质量；
- 城市/学校分散。

所以它适合变成“需求卡”的一种类型，而不是先做完整活动平台。

## 5. 推荐锁定方向

# 同校找找卡：把大学生临时小需求，变成一张能发出去、能被回应、能沉淀的卡

一句话：

> 学生不是缺“又一个社交平台”，而是缺一个不尴尬、够清楚、能发出去的“我想找____”表达工具。Meetu 先帮他把需求包装成卡，再逐步把卡背后的需求沉淀成校园网络。

它不是测试，也不是排版工具。它本质上是一个“需求表达/需求流通”工具。

### 5.1 它要解决的真实问题

现在学生会在小红书、学校群、朋友圈里发这些：

- 想认识各专业的大学生；
- 蹲一个不日抛聊天搭子；
- 找自习搭子/考研搭子/饭搭子；
- 周末有人一起去某个地方吗；
- 有没有同校二手群/资料群/实习信息群；
- 求拼车/代取/跑腿/租房避雷；
- 想找一个互相监督的人。

痛点不是“他们不知道自己要什么”，而是：

1. 不好意思问；
2. 问得太散，别人看不懂；
3. 容易被平台判导流；
4. 评论/私信难管理；
5. 学校、时间、边界、要求没写清；
6. 需求过去就消失，Meetu 没法沉淀。

### 5.2 P0 形态

一个 H5，用户 30 秒生成一张“同校找找卡”。

表单字段控制在 5 个：

1. 我想找：搭子 / 局 / 物 / 资料 / 群 / 互助 / 经验
2. 场景：饭、自习、运动、周末、二手、资料、实习、拼车、代取等
3. 学校/城市：可填可不填
4. 边界：只女生 / 同校 / 不日抛 / 不露脸 / 预算 / 时间
5. 回复暗号：例如“评论区打 dd / 私我 / 回一个关键词”

输出 2 个东西：

- 一张可保存的图片卡：适合发小红书群、朋友圈、学校群；
- 一段可复制文案：适合直接发帖/评论/群聊。

### 5.3 示例输出

**搭子卡**

> 今日找找：长期自习搭子  
> 学校：武汉 / 同校优先  
> 要求：不日抛，不卷人，能互相提醒  
> 暗号：评论区发“自习”

**信息卡**

> 今日求助：有没有本校二手群  
> 需求：想收一辆小电驴 / 顺便蹲租房避雷  
> 边界：只要真实学生群，不要中介  
> 暗号：发我“群”

**小局卡**

> 今日组局：周末想出去但没人  
> 地点：武汉  
> 想法：不要只吃饭，想找点新鲜事  
> 暗号：回“周末”

### 5.4 为什么它是低成本高收益

低成本：

- 不需要先做匹配算法；
- 不需要先做登录；
- 不需要先做供给库存；
- 前端表单 + 模板渲染 + 保存图片即可上线；
- 轻后端只记录需求类别、学校、场景、是否保存/复制。

高潜在收益：

- 每次生成都是一个真实需求样本；
- 每张卡都会被用户带到已有群/小红书/朋友圈，天然外部分发；
- 后续可以把高频需求转成 Meetu 的频道、活动、交易和社群；
- 它同时覆盖搭子、信息差、二手互助、周末局、学习监督，不押单一场景。

### 5.5 为什么不是“直接做匹配平台”

直接做匹配平台最大问题是冷启动：没人、没供给、没信任。  
找找卡反过来：先让用户把需求发出去，再从发出去的需求里发现供需密度。

这更像低成本探针：

- 哪些学校需求多；
- 哪些场景需求多；
- 哪些卡被保存/复制最多；
- 哪类文案更容易引发回复；
- 哪些需求值得进入 Meetu 正式产品。

## 6. Runner-up 与不选理由

### 6.1 校园信息差/资源导航

值得做，但不建议作为第一探索方向。

优点：搜索热、收藏强、低成本内容化。  
问题：内容维护重，差异化弱，容易变成资料号。  
建议：作为“找找卡”的一个类型：`求资源 / 求群 / 求渠道`。

### 6.2 校园二手/互助交易

很符合 Meetu 长期“校内网+交易闭环”，但不是最低成本。

优点：真实交易，信任来自同校身份。  
问题：需要风控、履约、纠纷、类目治理。  
建议：P0 不做交易闭环，只做“求闲置/求代取/求拼车”的需求卡；如果数据强，再进入交易模块。

### 6.3 周末活动/小局

很符合 Meetu，但供给侧更重。

优点：线下社交方向一致。  
问题：要持续维护活动供给和安全边界。  
建议：P0 不做活动平台，只做“组个局/找人一起去”的卡。

### 6.4 宿舍关系/情绪

话题很大，但不是 P0。

优点：评论量、共鸣强。  
问题：安全/隐私/负面情绪风险高。  
建议：作为内容研究方向，不作为第一工具。

## 7. 下一步：进入 PRD 前要确认的问题

如果认可“同校找找卡 / 校园需求卡”方向，写 PRD 前我需要先确认 8 个边界：

1. P0 是否允许用户留下联系方式？如果不允许，默认只生成图片和文案。
2. 是否要登录？我建议 P0 不登录，只记录匿名生成事件。
3. 是否允许学校字段？如果允许，会更像“同校需求”，但也会带隐私边界。
4. 首批卡类型选几个？我建议 4 个：找搭子、找局、找资源/群、找闲置/互助。
5. 是否要结果页露出 Meetu 品牌？建议弱露出，重点是卡好用。
6. 是否需要后台收集数据？建议至少收集类型、学校/城市、保存/复制事件。
7. 是否要做公开广场？我建议 P0 不做，避免审核和安全问题。
8. 发布路径是小红书群/学校群/公众号，还是先内部测试？不同路径影响文案和风格。

## 8. PM 结论

这轮大样本后，我不再把机会定义成“生成图片”或“排版小动物同类”。真正值得探索的是：

> **大学生有大量临时、小型、弱关系需求，但缺一个低尴尬、低成本、可传播、可被回应的表达容器。**

所以建议锁定：

# 同校找找卡 / 校园需求卡

先做一个 30 秒生成图片和文案的 H5，用它验证真实需求分布；如果某些需求密度足够高，再把它升级成 Meetu 的校园需求广场、搭子匹配、活动组局或校内交易入口。
