## 0. 一句话结论

这个产品不应该被定义为“小动物卡片生成器”。

它更准确的定义是：

> 一个低门槛的 **具象情绪代理人系统**：用户召唤一个被喜欢、可投射、可复用的小角色/物件/系统人格，让它替自己表达今天的状态，并生成一张适合发出去引发朋友接话的图。

用户感知不是：

> 我来生成一张卡。

而是：

> 今天我想找一个东西替我说话。

## 1. 第一性原理

这个应用必须同时满足四个条件，否则不值得做。

### 1.1 传播性

用户生成后必须愿意发出去。

判断问题：

- 这张图单独发群里，别人能不能接话？
- 朋友能不能评论“这不就是你”？
- 用户愿不愿意把它当微信状态/朋友圈/小红书配图？
- 它有没有被截图二传的可能？

反例：

- 只是漂亮；
- 只是准确；
- 只是像 AI 生成的情绪句子；
- 发出去别人只能点个赞，没话说。

### 1.2 复用性

用户不是来测一次，而是能在不同日子、不同场景、不同情绪下反复使用。

判断问题：

- 今天能用，明天还能不能用？
- 发群、发朋友圈、发微信状态能不能都用？
- 同一个角色能不能承接多个状态？
- 用户能不能逐渐形成“我常用这个角色”的偏好？

反例：

- 一次性测试结果；
- 一个梗用完就没了；
- 只能表达一种状态；
- 只能靠新鲜感驱动。

### 1.3 情感情绪依赖性

产品要形成依赖，不靠复杂功能，而靠“角色关系”。

判断问题：

- 用户会不会觉得它懂我？
- 用户会不会说“今天我要找它替我发言”？
- 用户会不会记住某个角色的说话方式？
- 用户会不会把角色当成自己的嘴替、状态替身、情绪容器？

反例：

- 用户只觉得“文案还行”；
- 没有角色记忆点；
- 每次生成都像随机模板；
- 用户对产品没有“回来找谁”的心理路径。

### 1.4 爆款潜质

爆款不是“内容很好”，而是具备社交扩散结构。

判断问题：

- 角色名字能不能被用户传播？
- 图能不能被朋友用来贴标签？
- 评论区能不能形成接龙？
- 用户会不会想给朋友也生成一张？
- 它有没有成为系列 IP 的可能？

反例：

- 输出完整闭环，朋友没法参与；
- 文案太自解释，像产品介绍；
- 角色太泛，没人记住；
- 视觉太模板，像营销素材。

## 2. 真实需求判断

### 2.1 用户的根本需求

目标用户不是单纯需要图片，也不是单纯需要文案。

他们需要的是：

> 在不显得太认真、不显得太矫情、不显得像广告的情况下，把自己的状态表达出去，并让别人自然接话。

这背后有四层心理需求：

1. **表达欲**：我想被看见，我想让别人知道我现在的状态；
2. **防御性**：但我不想直接说“我累了 / 我不开心 / 我需要人理我”；
3. **可否认性**：如果别人说我矫情，我可以说“我只是发个图”；
4. **被接住**：我发出去不是为了广播，而是希望有人回一句。

### 2.2 为什么“朋友”不是好的承接物

“朋友锐评”如果由产品直接写在图上，会过早闭环。

问题：

- 用户会觉得自己已经被评价，防御心变强；
- 朋友看到后没什么可说，因为锐评已经写完；
- 产品像在审判用户，容易产生不适；
- 分享后的社交互动被产品抢走。

更好的结构：

```text
产品生成：一个可被评论的情绪触发器
朋友完成：锐评、认领、补刀、贴标签
```

所以，朋友锐评应该发生在分享之后的评论区/群聊里，而不是写死在图上。

### 2.3 为什么“具象代理人”更好

具象代理人提供三种安全感：

1. **外壳安全**：不是我在抱怨，是它替我说；
2. **情绪安全**：我不用把情绪说得很重，可以交给一个轻角色；
3. **社交安全**：朋友可以评论这个角色，不是直接评价我。

它让用户从：

```text
我今天很累，不想社交。
```

变成：

```text
今天由低电量图标替我发言：
人在，电不在。
```

这就是低压表达。

## 3. 产品定位

### 3.1 内部定位

> 一个面向大学生高频社交表达的具象情绪代理人生成应用。

### 3.2 用户侧定位

备选表达：

1. `今天找谁替你说话？`
2. `找个东西替你发言。`
3. `今天不想解释，让它替你说。`
4. `把你的状态交给一个会说话的小东西。`

### 3.3 它不是

- 不是心理测试；
- 不是 MBTI/SBTI 替代品；
- 不是朋友圈文案生成器；
- 不是 AI 聊天伴侣；
- 不是公开交友墙；
- 不是设计模板站。

### 3.4 它是

```text
情绪嘴替 + 角色 IP + 状态表达卡 + 评论触发器
```

其中最重要的是：**角色 IP 和评论触发器**。

## 4. Target Audience

### 4.1 核心人群

> 有社交表达需求，但不想用高压、直白、像广告的方式表达自己的大学生。

### 4.2 用户特点

| 特点 | 表现 | 产品机会 |
|---|---|---|
| 想被看见但不想明说 | 发状态、发梗图、发朋友圈但不写长文 | 用角色替他说 |
| 喜欢低压互动 | 不想认真求安慰，但希望朋友回一句 | 卡片留接话口 |
| 习惯截图传播 | 微信状态、群聊截图、表情包、XHS图文 | 输出必须适合截图 |
| 讨厌营销感 | 对“精准分析/必测/下载/加群”敏感 | 产品不能像推广 |
| 喜欢给朋友贴标签 | 这不就是你 / 你今天又这样 | 角色要容易被朋友认领 |
| 有收藏和复用习惯 | 存表情包、状态图、文案 | 角色和文案要可复用 |

### 4.3 首批最适合的人

1. **嘴硬型**：想被懂，但嘴上不认；
2. **低电量型**：想社交，但容易耗电；
3. **脑内过载型**：表面正常，内心弹幕很多；
4. **边界型**：需要空间，但不好意思直说；
5. **发疯型**：喜欢抽象表达和精神状态梗；
6. **群聊型**：喜欢发图让朋友接话。

## 5. 核心产品假设

### H1：用户更愿意分享“角色替我说”的内容，而不是“我被分析”的内容

因为前者低压、可否认、可二创；后者容易像审判。

验证信号：

- 用户保存/分享率；
- 评论里出现“这不就是你”；
- 用户说“这句我偷了”；
- 用户给朋友生成。

### H2：角色依赖比模板依赖更强

用户可能不会记住某个模板，但会记住一个角色。

验证信号：

- 用户重复选择同一角色；
- 用户说“我今天又是它”；
- 评论里朋友用角色名称呼用户；
- 用户请求更多这个角色的句子。

### H3：朋友锐评必须后置

图上留白，朋友才有发挥空间。

验证信号：

- 分享后群聊/评论区有补刀；
- 用户截图朋友评论二次传播；
- “朋友锐评”成为外部互动，而不是产品内文案。

### H4：P0 不需要 AI，也不需要复杂编辑器

只要角色、状态、文案和视觉足够准，规则模板就能验证需求。

验证信号：

- 规则模板生成的卡也能被保存和分享；
- 用户主要反馈“像/好发/想偷”，而不是“能不能自由改字”；
- 换一句率高，但不是因为第一句不可用。

## 6. 角色系统

### 6.1 角色不是“小动物”，而是情绪代理人

角色可以是：

- 生物：猫、鹅、鸡、蘑菇、小怪物；
- 物件：勿扰牌、低电量图标、便利贴、闹钟；
- 系统：弹窗、错误码、加载条、后台进程；
- 校园微神明：床神、DDL 小鬼、饭点幽灵；
- 脑内部门：嘴硬部、脑补组、社交售后部。

核心不是它是什么，而是它能不能承担一种情绪功能。

### 6.2 角色筛选标准

每个角色满分 30，P0 只选 24 分以上。

| 维度 | 问题 |
|---|---|
| 一眼记忆 | 用户能否 1 秒记住名字和形象？ |
| 情绪承接 | 它是否能稳定承接一种高频状态？ |
| 复用范围 | 它能否覆盖至少 5 个日常场景？ |
| 分享接话 | 朋友看到后是否容易评论？ |
| 喜欢程度 | 它是否可爱/好笑/招人喜欢，而不是只怪？ |
| 设计稳定性 | 是否能形成稳定视觉，而非随机 AI 图？ |

### 6.3 P0 推荐角色组合

我建议 P0 不用纯动物，也不要纯系统。采用混合组合，兼顾亲和、传播、IP 感和复用。

| 角色 | 类型 | 情绪功能 | 典型发言方向 |
|---|---|---|---|
| 省电猫 | 生物型 | 低电量 / 拒绝营业 | 人在，电不在 |
| 嘴硬鹅 | 生物型 | 被说中但不认 | 我没有，只是稍微 |
| 后台进程 | 系统型 | 脑内过载 / 复盘 | 表面正常，后台开会 |
| 勿扰牌 | 物件型 | 边界 / 私人空间 | 今日不对外开放 |
| 出门审批处 | 部门型 | 想去但启动失败 | 申请已提交，床不同意 |
| DDL 小鬼 | 校园微神明 | 拖延 / 期末 / 焦虑 | 还有时间，理论上 |

这组的好处：

- 有动物亲和力，但不被动物框死；
- 有系统/物件带来的截图感；
- 有校园语境；
- 每个角色都能跨多个场景；
- 每个角色都有稳定说话习惯。

### 6.4 角色说话习惯

| 角色 | 固定语言机制 |
|---|---|
| 省电猫 | 短句、低电量、请求勿扰 |
| 嘴硬鹅 | 否认开头，但内容自爆 |
| 后台进程 | 表面/后台对照 |
| 勿扰牌 | 礼貌、克制、边界明确 |
| 出门审批处 | 流程、公文、审核、驳回 |
| DDL 小鬼 | 时间幻觉、拖延、自我安慰 |

用户依赖的不是“角色介绍”，而是它的稳定语言人格。

## 7. 状态系统

### 7.1 P0 状态池

状态不要太多，先覆盖最高频表达需求。

| 状态 | 可用角色 |
|---|---|
| 低电量 | 省电猫 / 勿扰牌 |
| 在线装死 | 省电猫 / 嘴硬鹅 |
| 被说中了但不认 | 嘴硬鹅 |
| 脑内开会 | 后台进程 |
| 社交售后复盘 | 后台进程 / 嘴硬鹅 |
| 今日勿扰 | 勿扰牌 / 省电猫 |
| 出门审批中 | 出门审批处 |
| 想去但懒 | 出门审批处 / 省电猫 |
| DDL 在追我 | DDL 小鬼 / 后台进程 |
| 表面正常 | 后台进程 / 勿扰牌 |
| 需要朋友捞一下 | 省电猫 / 勿扰牌 |
| 已读乱回 | DDL 小鬼 / 后台进程 |

### 7.2 状态不是用户负担

用户不应该被问：

> 你的目的是什么？你的偏好是什么？你的表达边界是什么？

这太重。

P0 只问：

```text
今天谁替你说话？
它今天怎么了？
发到哪里？（可跳过）
```

## 8. 输出设计

### 8.1 卡片不写死朋友锐评

卡片结构：

1. 今日代言角色；
2. 角色替用户说的一句话；
3. 状态标签；
4. 留白钩子。

示例：

```text
今日代言：后台进程

表面：没事。
后台：开会、复盘、模拟三种结局。

状态：脑内过载中

请勿强制关机。
```

朋友可能评论：

```text
你每次回消息都像写论文。
这不就是你。
后台进程常驻了。
```

### 8.2 三种输出用途

同一角色状态，输出要适配不同场景。

| 用途 | 文案强度 | 视觉策略 | 目标 |
|---|---|---|---|
| 发群版 | 最好笑、可被接话 | 大字、强钩子、留白 | 引发朋友评论 |
| 朋友圈版 | 更体面、更含蓄 | 更完整、更像状态图 | 展示状态但不尴尬 |
| 微信状态版 | 极短、像签名 | 单句强记忆 | 高频复用 |

### 8.3 输出示例

#### 省电猫 / 低电量 / 发群版

```text
今日代言：省电猫

人在。
电不在。

状态：低电量社交中

请不要突然安排我。
```

#### 嘴硬鹅 / 被说中 / 朋友圈版

```text
今日代言：嘴硬鹅

我没有被说中。
只是这张图比较会碰瓷。

状态：本人暂不认领

像不像你们自己说。
```

#### 后台进程 / 脑内开会 / 发群版

```text
今日代言：后台进程

我表面回了一个“哈哈”。
后台已经开了三轮复盘会。

状态：高负载运行中

谁来结束进程。
```

#### 勿扰牌 / 边界 / 微信状态版

```text
今日代言：勿扰牌

今日开放时间不稳定。

状态：边界修复中
```

#### 出门审批处 / 想去但懒 / 发群版

```text
今日代言：出门审批处

你的出门申请正在审核中。
目前卡在：床的意见。

状态：流程未走完

请勿催办。
```

#### DDL 小鬼 / 期末 / 朋友圈版

```text
今日代言：DDL 小鬼

还有时间。
理论上。

状态：正在用乐观拖延

别问，问就是快了。
```

## 9. 用户链路

### 9.1 P0 主链路

```text
入口页：今天找谁替你说话？
  ↓
选择角色：6 个角色卡 + 一句代表发言
  ↓
选择状态：每个角色 6-8 个状态
  ↓
选择用途：发群 / 朋友圈 / 微信状态（可跳过）
  ↓
生成 3 张候选卡
  ↓
用户保存 / 换一句 / 换角色 / 给朋友生成
  ↓
用户发出去
  ↓
朋友在群聊/评论区接话
  ↓
用户回流：再给自己或朋友生成
```

### 9.2 降低 friction，但不一刀切

需要平衡两件事：

- 太少输入：输出不贴脸，不形成依赖；
- 太多输入：用户还没玩就累了。

P0 最优输入是：

```text
必选 2 步：角色 + 状态
可选 1 步：用途
```

这比“自由输入目的/偏好/边界”轻很多，也比“一键随机”更容易贴脸。

### 9.3 一键随机不能作为主入口

可以有“今天随机找个嘴替”，但不能只靠随机。

原因：

- 用户需要一点选择权，才会觉得“这是我的”；
- 角色偏好是依赖机制的基础；
- 如果全随机，角色关系无法形成。

## 10. 传播机制

### 10.1 分享图是“社交对象”

图不是为了表达完整观点，而是为了让朋友接话。

好的分享图应该让朋友产生三种反应：

1. `这不就是你？`
2. `这句我偷了。`
3. `给我也生成一个。`

### 10.2 留白比完整更重要

卡片不要解释太多，不要把所有笑点写完。

应该留下：

- 朋友认领空间；
- 评论补刀空间；
- 用户二次截图空间；
- 朋友互相贴标签空间。

### 10.3 扩散路径

```text
用户生成卡
  ↓
发群/朋友圈/状态
  ↓
朋友评论“像你”
  ↓
用户截图朋友评论
  ↓
朋友问链接/求角色
  ↓
用户回流生成朋友版
```

这个链路比“用户点击外链”更自然。

## 11. 复用和依赖机制

### 11.1 每日状态

用户每天状态不同，但角色关系可以持续。

例：

- 今天找省电猫；
- 明天找后台进程；
- 期末找 DDL 小鬼；
- 朋友局前找出门审批处。

### 11.2 默认嘴替

用户会逐渐形成偏好：

- “我默认是省电猫”；
- “嘴硬鹅太会替我说了”；
- “这事只能让后台进程说”。

这就是情绪依赖的核心。

### 11.3 卡册/历史

P0 可以先用 localStorage 做轻历史：

- 最近生成；
- 我常用的角色；
- 我收藏的句子。

不必登录，但要让用户觉得“我和这些角色有关系”。

### 11.4 给朋友生成

这是从自用到社交的关键按钮。

按钮文案不要叫“分享给朋友”，而是：

- `给朋友也找一个`
- `给室友生成一张`
- `让它也替 ta 说话`

## 12. MVP 范围

### 12.1 P0 做什么

- 6 个首发角色；
- 每个角色 6-8 个状态；
- 每个状态 4-6 条代表发言；
- 3 种用途版式：发群 / 朋友圈 / 微信状态；
- 生成 3 张候选卡；
- 保存图片；
- 换一句；
- 换角色；
- 给朋友生成；
- 本地历史/收藏；
- 基础埋点。

内容规模：

```text
6 角色 × 8 状态 × 5 文案 = 240 条核心文案
再乘 3 类用途做轻微改写和版式适配
```

### 12.2 P0 不做什么

- 不做 AI 自由生成；
- 不做账号系统；
- 不做公开广场；
- 不做匿名评价；
- 不做聊天机器人；
- 不做角色养成数值；
- 不做复杂编辑器；
- 不做心理诊断。

### 12.3 为什么技术上仍像 MVP

P0 可以是规则模板 H5：

- 前端静态内容表；
- 角色/状态/用途选择；
- 模板映射生成文案；
- Canvas/html2canvas 导出图片；
- localStorage 保存历史；
- 基础事件埋点。

不需要后端、不需要 AI、不需要登录、不需要数据库即可验证核心假设。

## 13. 视觉原则

### 13.1 每个角色必须有稳定识别点

不是统一模板换名字。

| 角色 | 视觉识别点 |
|---|---|
| 省电猫 | 低电量、趴、蓝灰、眼神下线 |
| 嘴硬鹅 | 仰头、嘴硬嘴型、白底黑线、黄色贴纸 |
| 后台进程 | 多窗口、进度条、系统灰、窗口堆叠 |
| 勿扰牌 | 门牌、边界线、低声量、米白灰 |
| 出门审批处 | 公章、流程单、床的意见、审批状态 |
| DDL 小鬼 | 红色倒计时、凌晨台灯、纸团、坏笑 |

### 13.2 视觉不能像广告

避雷：

- 大 logo；
- 过度精修；
- AI 质感强但没有人格；
- 功能说明书感；
- 太像模板海报；
- 太像品牌吉祥物硬推。

### 13.3 视觉要服务用户动作

| 用户动作 | 视觉策略 |
|---|---|
| 停留 | 大标题、一眼角色、强情绪钩子 |
| 分享 | 图上文字少、角色清晰、留白可接话 |
| 收藏 | 文案可偷、视觉不尴尬 |
| 复用 | 角色识别稳定，状态可变化 |
| 朋友评论 | 留出“像谁/认领/补刀”空间 |

## 14. 内容原则

### 14.1 不是分析用户，而是替用户说话

错误：

```text
你是一个边界感很强的人。
```

正确：

```text
今日代言：勿扰牌

我不是冷漠。
我只是今天不对外开放。
```

### 14.2 不要太完整

完整解释会降低传播。

错误：

```text
你今天因为社交消耗过大，所以需要独处恢复能量。
```

正确：

```text
人在。
电不在。
```

### 14.3 要有可偷句

用户会传播的是一句能直接拿走的话。

例：

- `人在，电不在。`
- `我没有被说中，只是这张图比较会碰瓷。`
- `你的出门申请卡在床的意见。`
- `表面：没事。后台：开会。`

## 15. 埋点和成功指标

### 15.1 核心指标

| 指标 | 说明 | 目标方向 |
|---|---|---|
| 生成完成率 | 进入后生成卡片 | 验证 friction |
| 保存率 | 保存图片 / 生成成功 | 验证输出价值 |
| 换一句率 | 换一句 / 生成成功 | 验证文案池需求 |
| 角色复选率 | 多次选择同一角色 | 验证角色依赖 |
| 给朋友生成率 | 点击给朋友生成 | 验证社交扩散 |
| 二次生成率 | 同一用户再次生成 | 验证复用 |
| 外部求链接 | 评论/私信/群聊求入口 | 验证传播 |

### 15.2 定性成功信号

优先级最高的不是“好看”，而是这些话：

- `这不就是我？`
- `这句我偷了。`
- `给我也生成一个。`
- `我朋友说我是这个。`
- `我今天又是它。`
- `这个角色太懂了。`

## 16. 风险与修正

### 风险 1：角色只是可爱，但不能替用户说话

修正：每个角色必须先写 20 条代表发言，再决定是否保留。

### 风险 2：角色太怪，不招人喜欢

修正：怪可以，但必须可亲近、可投射、可截图。猎奇不是爆款。

### 风险 3：输出太像营销图

修正：降低 logo、CTA、功能说明；视觉像用户自发内容，不像品牌广告。

### 风险 4：用户不知道怎么选

修正：角色卡先展示一句代表发言，不用用户理解设定。

### 风险 5：图上说太满，朋友没法接话

修正：删除朋友锐评；保留开放钩子。

### 风险 6：只有一次新鲜感

修正：每日状态、默认嘴替、给朋友生成、卡册收藏四个机制一起做。

## 17. 验证计划

### 阶段 1：角色压力测试

产出：30 个角色候选，每个角色 5 条代表发言。

评估：

- 是否愿意发；
- 是否能被朋友接话；
- 是否有复用场景；
- 是否有视觉记忆点；
- 是否有人想继续看它说话。

### 阶段 2：低保真视觉小样

选 12 个角色做低保真卡片，每个 1 张。

不追求精致，先看：

- 人格是否成立；
- 图文是否同频；
- 用户是否能一眼理解；
- 是否像广告。

### 阶段 3：P0 6 角色 H5

做极简 H5：

```text
选角色 → 选状态 → 生成 3 张卡 → 保存/换一句/给朋友生成
```

### 阶段 4：渠道测试

测试渠道：

- 小红书单图/多图；
- 微信群内部传播；
- 公众号图文；
- 朋友圈/微信状态；
- 大学生小群定向测试。

关注：

- 用户是否求链接；
- 是否报角色；
- 是否@朋友；
- 是否发自己的生成图；
- 是否出现二创语言。

## 18. 最小 Demo 方向

### 18.1 Landing

```text
今天谁替你说话？

有些话自己说太认真。
找个东西替你说。
```

### 18.2 角色选择卡

```text
省电猫
人在，电不在。
适合：不想营业 / 在线装死 / 需要缓一缓
```

```text
后台进程
表面正常，后台开会。
适合：脑补 / 复盘 / 表面没事
```

```text
出门审批处
你的出门申请卡在床的意见。
适合：想去但懒 / 被约出门 / 临时局
```

### 18.3 生成结果

```text
今日代言：嘴硬鹅

我没有破防。
只是刚好每个字都比较贴脸。

状态：本人暂不认领

像不像你们自己说。
```

### 18.4 分享后朋友回复

```text
别嘴硬。
这鹅是你亲戚吧。
本人已认领。
```

这才是完整产品体验。

## 19. 当前最重要的产品判断

这个方向是否成立，不取决于：

- 图片是否精致；
- 角色是否很多；
- 文案是否“准确分析”；
- 是否用了 AI；
- 是否有复杂编辑器。

它取决于：

> 用户是否愿意把情绪交给一个具象角色，并把这个角色生成的内容发出去，期待朋友接话。

如果这个成立，产品有机会从一次性内容工具变成高频表达入口。

如果这个不成立，再多角色、再多模板、再好看的图都没有意义。

## 20. 下一步待决策

1. 是否同意产品定位从“小动物状态卡”升级为“具象情绪代理人系统”？
2. P0 是否采用混合角色组合，而不是纯动物组合？
3. 是否先做 30 角色压力测试，再让设计完整产出？
4. P0 输出场景是否锁定：发群 / 朋友圈 / 微信状态？
5. 是否接受 P0 不做 AI，只做规则模板内容池？
6. 首发验证渠道优先小红书还是微信群/朋友圈？

我的建议：

> 先做 30 个角色候选和 150 条代表发言，快速内部筛出 6 个最有传播和依赖潜质的角色，再进入 H5 MVP。不要现在就把视觉完整做死。
