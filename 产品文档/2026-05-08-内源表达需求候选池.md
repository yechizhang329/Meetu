# 内源表达需求候选池：从“排版小动物”回到需求本体

日期：2026-05-08  
负责人：Fiona  
背景：Jonathan 指出“低压小局/搭子接龙”链路太长，不能类比排版小动物。排版小动物成立的关键不是“卡片”，而是用户本来就有一个内源需求：把自己/圈层/状态包装成可发、可被认领、可被朋友接话的表达物。

---

## 0. 修正结论

我撤回“武汉低压小局 + 场景化搭子接龙是当前最佳方向”的判断。

它可能是一个真实运营场景，但不是当前要找的最佳低成本高回报产品切口。原因是：

- 用户必须回复；
- 用户必须填边界；
- 运营必须组织；
- 线下必须到场；
- 每一步都有流失；
- 成功依赖运营推动，不是用户内源动作自然外溢。

更接近“排版小动物”的方向应该满足：

> 用户本来就在表达/包装/求模板/求生成；产品只需要降低制作成本、提高传播效果，而不是创造一条新行为链路。

---

## 1. 新筛选标准

从 full-scale 研究的 300 条深读笔记 + 4404 条评论里，我重新按“内源表达需求”筛选，标准如下：

1. **用户是否已经主动做这件事**：不是我们教育用户做。
2. **是否有求模板/教程/同款/帮改/文案/图的评论**：说明有生产成本痛点。
3. **生成物是否能立刻使用**：发小红书、朋友圈、群聊、私信、头像、资料页。
4. **是否不依赖他人配合**：用户自己生成后即可完成价值闭环。
5. **是否和 Meetu 相关**：能帮助用户表达身份、社交状态、兴趣圈层，或作为后续连接入口。
6. **是否可商业化或沉淀数据**：不能只是一次性玩具。

## 3. 排名后的判断

### 第一梯队：值得立即探索

#### A. 圈层身份表达生成器

不是“自介卡”本身，而是：

> 帮用户把“我是谁 / 我想被怎样的人看见 / 我不想被怎样的人打扰”生成一个可发的身份表达物。

它可以包含：

- 兴趣圈层：二次元 / Kpop / 游戏 / livehouse / 运动 / citywalk；
- 社交边界：慢热 / 不尬聊 / 可以少说话 / 分享欲强 / 不消失；
- 当前需求：找搭子 / 找同校 / 找队友 / 找学习搭子 / 找拍照搭子；
- 风格输出：小红书图、群聊图、朋友圈图、个人主页置顶图。

为什么比“低压小局”更接近排版小动物：

- 用户自己就有表达和包装自己的需求；
- 生成后立刻可用；
- 不需要别人立即回应也有价值；
- 但它能自然引出连接。

风险：

- 如果做成泛“交友卡”，会很土、很低质；
- 如果字段像问卷，会像营销模板；
- 如果过度暴露个人信息，有安全风险。

P0 方向应该不是“搭子卡”，而是 **圈层身份卡 / 低压自我介绍图**。

---

#### B. 精神状态 / 圈层梗图生成器

用户已经在大量消费和转发“大学生现状”“上课专用图”“抽象上学日记”“小比梗图”等内容。数据里这类方向命中 30 条深读样本，样本点赞 31.3 万、评论 4.0 万。

本质需求：

> 用户想用一个梗图替自己说话。

可做形态：

- 今天的大学生精神状态图；
- 我的宿舍生存图鉴；
- 我的期末状态图；
- 我的社交电量图；
- 我的搭子需求图；
- 我的朋友圈人格图。

优点：

- 内源表达强；
- 传播强；
- 生成成本低；
- 和 H5/图片生成能力匹配。

缺点：

- 商业化弱；
- 很容易变成一次性娱乐；
- 如果不接回 Meetu 场景，只是内容工具。

适合做流量入口，不适合单独作为长期产品本体。

---

#### C. 朋友圈/小红书文案 + 配图风格生成器

数据里“朋友圈文案/截图表达”命中 21 条深读样本，点赞 18.7 万、评论 2.45 万；评论里出现“文案、滤镜、设备、互扩、链接”等真实行为。

本质需求：

> 用户不是不会发，而是不知道怎么把自己的生活包装得刚刚好。

可做形态：

- 今天这张图怎么发才不尬；
- 用我的照片生成 3 种小红书标题/正文/封面字；
- 把普通生活照包装成“大学生日常”；
- 朋友圈九宫格文案生成；
- 同校/同城出门局文案生成。

优点：

- 用户强内源；
- 可直接使用；
- AI 生成优势明显。

缺点：

- 和 Meetu 的社交连接间接；
- 已有竞争多；
- 容易变成泛内容工具。

可作为工具能力，不建议作为 Meetu 第一主线。

---

### 第二梯队：可借鉴机制，不建议直接产品化

#### D. 评论截图 / 热评二创

这类内容传播强，但需求更多是“观看热闹”，不是“我想生成”。适合借鉴“评论比正文好笑”的机制，进入我们的结果页/卡片/运营内容。

可迁移：

- 朋友锐评卡；
- 群友评论生成；
- 把自我介绍转成“别人会怎么评价我”。

不建议做成“热评生成器”独立产品。

#### E. 校园墙 / 投稿截图外壳

校园墙样本说明匿名/半匿名投稿外壳很强，但风险也高：隐私、谣言、引流、学校管理、广告感。适合学习“投稿截图”的视觉语言，不适合直接做匿名墙。

可迁移：

- 公开安全的“需求投稿卡”；
- 非匿名、可撤回、低风险的“今天想找一个人一起……”卡。

#### F. 清单 / 期末生存卡

需求硬，但偏自我管理。可以作为季节性内容/工具，不是 Meetu 核心。

---

### 第三梯队：需求很硬，但偏离 Meetu

#### G. 简历 / 竞赛 / 信息差模板

这类数据最强：命中 62 条深读样本，点赞 75.9 万，求模板/教程/怎么做评论多。但它是职业成长/信息差产品，不是 Meetu 的核心社交定位。

除非 Meetu 要转向校园信息差工具，否则不应追。

## 4. 我现在更推荐的 P0 方向

### 方向名

**圈层身份表达生成器**

暂定一句话：

> 把“我是什么人、我想找什么同类、我有哪些边界”生成一张不尬的图。

### 它和排版小动物的相似点

排版小动物满足：

- 用户想表达自我；
- 输出物轻、可发、可被朋友认领；
- 生成后不依赖平台关系链；
- 视觉形式本身有传播力。

圈层身份表达生成器也满足：

- 用户想表达“我是怎样的人”；
- 用户想降低自我介绍成本；
- 用户想被同类看见，但不想显得太主动；
- 输出物能发小红书/群聊/朋友圈/主页置顶；
- 被别人看到后可以自然开启对话。

### 它不是

- 不是找搭子平台；
- 不是自介卡模板站；
- 不是匿名墙；
- 不是一键交友；
- 不是 MBTI 测试。

### 它应该是

一个轻工具：

1. 输入少量信息；
2. 选择语气和圈层；
3. 生成图 + 文案；
4. 用户拿去发；
5. Meetu 观察哪些需求/圈层更容易被回应；
6. 后续再把高频需求接到真实场景。

---

## 5. P0 使用场景

### 场景 1：小红书主页置顶

用户想表达“我是谁/想找什么同类”，但不想写得像交友广告。

输出：

- 一张圈层身份图；
- 一段短正文；
- 评论区回复模板。

### 场景 2：小红书群/微信群发图

用户想在群里找搭子/队友/同类，但直接发“有人一起吗”很尴尬。

输出：

- 一张低压需求卡；
- 三种群内发法：正常 / 抽象 / 嘴硬。

### 场景 3：朋友圈/QQ空间表达状态

用户不一定要找人，只是想发一个“这是我”的状态图。

输出：

- 精神状态图；
- 朋友圈文案；
- 不想太营销的配字。

### 场景 4：活动/小局前的身份破冰

用户参加 Meetu 小局前，可以生成“低压入场卡”：我能聊什么、我不想聊什么、我今天电量多少。

这能和 Meetu 线下场景接起来，但不要求 P0 一开始就组织线下局。

## 6. MVP 设计

### 输入字段控制在 6 个以内

- 我现在的状态：想出门 / 想找同类 / 想学习 / 想打游戏 / 想拍照 / 想安静；
- 我的圈层：游戏 / Kpop / 二次元 / 运动 / livehouse / citywalk / 自习 / 其他；
- 我的边界：慢热 / 不尬聊 / 可少说话 / 不熬夜 / 女生优先 / 不消失；
- 我的学校/城市：可选；
- 我想被怎样的人看到：同校 / 同城 / 同兴趣 / 同状态；
- 风格：正常 / 抽象 / 嘴硬 / 大字报 / 朋友圈。

### 输出

- 1 张图片；
- 1 段小红书正文；
- 1 条群聊发法；
- 1 条评论区接话模板。

### 不做

- 不自动匹配；
- 不公开墙；
- 不做登录；
- 不收隐私；
- 不保证找得到人。

## 7. 商业化/战略价值

短期商业化不强，但战略价值比单纯梗图更高：

1. **低成本获客**：用户为表达自己生成内容，内容自带 Meetu 弱品牌；
2. **需求数据沉淀**：圈层、边界、场景、城市/学校比泛点赞更接近产品数据；
3. **后续活动入口**：当某类需求高频出现，Meetu 再组织线下/线上小局；
4. **设计系统资产**：可沉淀出圈层视觉语言；
5. **运营内容素材**：每种高频卡都可变成小红书内容选题。

它解决的根本问题不是“交朋友”，而是：

> 用户想被同类看见，但不想用尴尬、像广告、像求偶、像招聘的方式介绍自己。

这是比“搭子接龙”更内源、更短链路的需求。

---

## 8. 风险和验证指标

### 风险

- 生成物太模板化 → 用户不愿发；
- 太像交友广告 → 小红书/用户反感；
- 太抽象 → 不能产生连接；
- 太暴露信息 → 安全风险；
- 只被当玩具 → 没有后续价值。

### 7 天 MVP 指标

- 完成生成率 ≥ 60%；
- 保存/复制率 ≥ 40%；
- 用户愿意发出去的自报比例 ≥ 20%；
- 评论/私信问“怎么做/在哪生成”出现；
- 生成卡中有明确场景/圈层的比例 ≥ 50%；
- 至少出现 3 个高频圈层或场景；
- 负反馈（像广告/尴尬/泄露隐私）< 10%。

## 10. 下一步建议

不要再继续争“搭子接龙是否可行”。

下一步应该开一个新的 P0 探索：

> **圈层身份表达生成器 PRD**

先确认 5 个问题：

1. 输出物更偏“我是谁”还是“我想找谁”；
2. 是否允许带学校/城市；
3. 视觉风格走大字报、卡片、截图风还是动物/符号；
4. 是否接入 AI 图片生成，还是先用 HTML/CSS 模板；
5. 是否只做保存图，还是同时生成小红书/群聊文案。

这个方向比“低压小局”更像排版小动物的需求结构：用户已经想表达自己，我们只是在帮他表达得更好、更可发、更不尴尬。
