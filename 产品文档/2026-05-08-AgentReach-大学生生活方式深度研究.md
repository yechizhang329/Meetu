日期：2026-05-08  
负责人：Fiona  
工具：Agent-Reach / XHS CLI  
账号：Meetu 小助理（已按 Jonathan 授权进行只读研究，并在高相关内容上少量点赞用于养号）

> 本报告不是为了证明某个既定产品方向正确，而是重新理解：当代大学生在交友、娱乐、恋爱、课余生活、兴趣圈层、校园信息、城市生活里，真实暴露了哪些需求；哪些需求只是内容消费，哪些已经出现行动意图；哪些可以被 Meetu 低成本接住。

## 0. 核心结论先行

### 结论 1：大学生不是缺一个“社交 App”，而是缺一批具体、低压力、可启动的社交理由

样本里真正高行动意图的表达不是“我要交朋友”，而是：

- “蹲一个不压力人的王者搭子”；
- “有没有女大学生也是自己一个人，互相搭个伴”；
- “求拉学生群 / 二手群 / 兼职群”；
- “找个聊天搭子，但不要消失”；
- “周末一个人不知道去哪”；
- “想认识同校/同城/同兴趣的人，但不想尬聊”。

这说明 Meetu 不应该先把自己定义成“帮你交朋友”，而应该先成为：**具体场景里的低压连接器**。

### 结论 2：评论区已经在承担临时产品功能

在 4404 条评论里，高频行动词包括：`求`132 次、`一起`131 次、`dd`75 次、`搭子`73 次、`群`71 次、`私`62 次、`蹲`61 次。  
这些不是抽象讨论，而是用户在直接发起交易/连接/资源请求。

XHS 现在被学生当成半个“需求发布器”使用，但它的问题也很明显：

- 需求会被淹没；
- 身份、地点、性别、边界、时间没有结构化；
- 安全感和真实性不足；
- 链接/群/私信受平台限制；
- 评论区无法沉淀成长期校园网络。

Meetu 的机会是：不要和 XHS 抢内容，而是在 XHS 暴露需求之后，提供更轻、更安全、更结构化的承接层。

### 结论 3：低成本高回报方向，不是“做卡片生成器”，而是“场景化接龙 + 轻匹配 + 本地活动门牌”

“卡片/截图/大字报”很有传播价值，但它本身不是产品终点。它是外壳。真正的产品价值在于：

1. 用户是否能通过它找到人；
2. 是否能降低社交启动成本；
3. 是否能在武汉/学校/具体兴趣里形成局部网络；
4. 是否能沉淀为 Meetu 的活动/社群/交易闭环。

因此当前推荐的 P0 探索不是泛社交，也不是泛测试，而是：

> **武汉校园“低压搭伴/周末小局”接龙系统**：从一个具体场景开始，让学生以低心理成本发起或加入小范围活动/搭子需求。

## 3. 关键洞察

### 3.1 “搭子”不是朋友，是低承诺的协作协议

典型样本：

- `想找个王者游戏搭子`：199 赞 / 8742 评论。评论不是讨论观点，而是直接报段位、平台、是否开麦、是否“不压力”。
- `请赐我一个分享欲强粘人的聊天搭子`：评论大量出现 “04女 / 05女大 / 蹲 / 不消失 / 可以加”。
- 旅游搭子、饭搭子、自习搭子、运动搭子、livehouse 搭子都具有相同结构：用户不一定要深交，只需要一个具体场景里的低风险同伴。

产品含义：

- 不要把“搭子”包装成“交朋友”；
- 更应该把它做成“我现在要做一件事，谁刚好也要”的低压连接；
- 必须显式表达边界：时间、地点、性别/安全偏好、是否聊天、是否开麦、预算、频率、是否可取消。

### 3.2 “没有朋友”背后常常不是社交能力问题，而是启动理由不足

样本 `上大学拥有0个朋友怎么调理`（4631 赞 / 1203 评论）和 `大学第一课：忍受孤独`（45000 赞 / 543 评论）显示：

- 很多人不是不想连接，而是不知道从哪里开始；
- 初高中自然形成的关系断裂后，大学需要主动进入组织/活动/兴趣圈；
- 但直接说“我想交朋友”很重，容易尴尬。

产品含义：

- Meetu 的文案不要说“帮你交朋友”，要说“给你一个不尴尬出现的理由”；
- 场景比人格更重要：一起吃饭、去展、打球、打游戏、自习、周末逛、组局，比“找朋友”更容易发起。

### 3.3 宿舍是大学生最强情绪场，但不是最适合 P0 产品化的方向

样本 `私密性的缺失是大学生活里最大的 bug`（约 17k 赞 / 1712 评论）和 `期末周宿舍微妙氛围`（高评论）说明：

- 宿舍是高痛点空间；
- 但它的需求很多是“想要逃离/想要安静/想要边界”，不一定是“想社交”；
- 宿舍矛盾极易引发攻击、吐槽、隐私暴露。

产品含义：

- 可以做“安静自习/低干扰活动/一个人也能去”的场景；
- 不建议 P0 做“宿舍关系调解”“室友匹配”“宿舍吐槽墙”。

### 3.4 校园群和信息差很强，但直接做“群入口”有风控和信任问题

样本 `找大学群的几种方法`、`大学必备9种信息渠道`、`大学生互助群` 等显示：

- 用户强烈需要群：新生群、二手群、兼职群、资料群、投票互助群、活动群；
- 评论里大量 `求拉`、`互换`、`私`、`主页`；
- 但这类需求也最容易引发平台引流、广告、诈骗、群污染。

产品含义：

- 可以做“可信群/活动/资源门牌”，但不要一开始就做公开群索引；
- 更安全的 P0 是“场景接龙 + 审核后的活动/群承接”，逐步积累信任。

### 3.5 周末/城市生活是 Meetu 的低风险切入口

样本 `在武汉，周末可以做的N件事`、`武汉最舒服的citywalk路线`、`和朋友出去玩除了吃饭还能做的一些事` 显示：

- 周末去哪、城市探索、活动汇总有强收藏；
- 评论中会自然出现“有没有人一起”“蹲个搭子”；
- 武汉本地有明确的校园-城市心理地图：街道口、光谷、江汉路、武大/华科/华师等。

产品含义：

- “武汉周末低压小局”是低成本高回报方向；
- 它比泛交友安全，比做资料库更有 Meetu 差异，比恋爱更低风险。

### 3.6 视觉不是装饰，是信任和传播机制

300 条深读样本中，视觉类型分布显示：

| 视觉类型 | 数量 |
|---|---:|
| 自介/扩列/卡片 | 43 |
| 聊天/群聊截图 | 43 |
| 备忘录/清单 | 38 |
| 评论截图/热评 | 35 |
| 实拍生活方式 | 32 |
| 活动/组织海报 | 30 |
| 梗图/表情包 | 29 |
| 大字报 | 14 |
| 校园墙/投稿 | 7 |

这说明大学生内容不是一种统一视觉风格，而是一套“外壳机制”：

- 截图类：可信、像真实发生；
- 大字报类：强钩子、适合冲突句；
- 卡片类：身份包装、便于转发；
- 清单/备忘录：低成本可信，适合收藏；
- 评论截图：用热评证明“不是我一个人这样”。

产品含义：

- Meetu 未来的传播物料不要只追求“好看”，要判断它承担什么功能：信任、传播、组织、身份、情绪；
- 设计语言必须按圈层和场景拆，而不是统一套皮。

## 4. 对 Meetu 的产品判断

### 4.1 最值得优先验证的方向

> **武汉校园低压小局 / 搭伴接龙系统**

一句话定义：

> 让大学生在一个具体场景里，低压力地发起或加入“我也想去/我也想做”的小范围连接。

为什么是它：

1. 数据上有行动意图：`dd/蹲/求/私/一起/群` 高频出现；
2. 场景清晰：周末、饭、游戏、自习、citywalk、livehouse、桌游、运动；
3. 可本地化：武汉校园和城市空间天然适合试点；
4. 实现成本低：H5/表单/接龙/人工审核/小群承接即可验证；
5. 品牌风险低于恋爱和匿名墙；
6. 能接入 Meetu 的长期活动、社群、信用和交易闭环。

### 4.2 P0 不要做什么

- 不要做泛交友 App：表达太重，启动成本高，竞争也重；
- 不要做恋爱/脱单主产品：流量大但安全、性别、骚扰、品牌风险高；
- 不要做公开群索引：容易引流、诈骗、广告、平台风控；
- 不要做匿名校园墙：情绪和传播强，但舆情/隐私/攻击风险高；
- 不要把卡片生成器当产品本体：卡片可以传播，但必须接回场景和行动。

### 4.3 推荐验证路径

**第 1 周：只验证需求承接，不重开发**

- 做 3 个武汉场景接龙：
  1. 周末逛/吃/拍照；
  2. 游戏/桌游/羽毛球；
  3. 自习/期末低压搭子。
- 每个场景用 XHS/群/公众号发“需求帖”；
- 用表单或 H5 收集：学校、区域、时间、想做什么、可接受人数、安全偏好；
- 人工把相近需求配到小群或活动局；
- 统计：填写率、有效匹配率、到场率、复用率、用户反馈。

**第 2 周：把高频场景产品化为轻 H5**

- 场景入口：`我想找一个低压搭子`；
- 选场景：吃饭/自习/游戏/周末/运动/展演；
- 填边界：时间、地点、人数、性别偏好、是否聊天、预算；
- 生成可分享卡/接龙页；
- 人工审核+群承接。

**第 3 周：只保留转化最高的 1-2 个场景**

- 如果周末小局强，往活动平台走；
- 如果游戏/自习搭子强，往低压搭子工具走；
- 如果校园信息群强，往可信门牌/资源入口走；
- 如果全弱，说明社交动物测试更适合作为内容流量工具，而不是产品入口。

## 5. 给团队的行动建议

### 给 Lucy

运营内容不要再写“我们做了一个产品”。更好的内容结构是：

1. 真实场景：今天周末/期末/室友都出去了/想找人打球；
2. 低压声明：不尬聊、不强社交、不压力；
3. 明确边界：时间地点预算人数；
4. 评论动作：dd / 蹲 / 报学校 / 报区域 / 报品种；
5. 私信承接：只给真正问的人链接或入口。

高价值评论词要进入 Lucy 的语言库：`蹲一个`、`dd`、`不压力`、`不消失`、`同校`、`一起`、`求拉`、`私`、`主页`、`救命`、`正常吗`。

### 给 Phoebe

视觉系统不要只追求统一好看，而要建立五类机制：

1. 信任型视觉：截图、评论、校园墙、实拍；
2. 传播型视觉：大字报、梗图、结果卡、锐评；
3. 组织型视觉：群公告、活动海报、地图、时间表；
4. 身份型视觉：自介卡、头像、圈层物件；
5. 情绪型视觉：备忘录、碎碎念、精神状态图。

每个物料先问：它是让用户停、信、笑、截图，还是行动？不要用一套“年轻化设计”解决所有场景。

### 给产品

产品下一步不要先做完整 App。先把 XHS 评论区里已经出现的动作拿出来结构化：

- 把“蹲/求/dd/私”变成可填表单；
- 把“同校/同城/时间/活动”变成筛选；
- 把“怕尴尬/不压力/不消失”变成边界选项；
- 把“发群/截图/报到”变成传播机制。

## 6. 仍需继续验证的问题
